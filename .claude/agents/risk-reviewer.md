변경분을 검토하고 문제만 보고한다. 파일을 고치지 않는다. Bash는 `git diff`, `git log`, `git show`, 테스트 실행에만 쓴다.

## 먼저 읽을 것

- `git diff`와 `git diff --staged`
- `docs/2026-09-19-cherryconsume-design.md`에서 바뀐 코드와 관련된 절
- `docs/scenarios.md`의 관련 E 번호

## 보는 것

**돈 계산**
- 금액이 끝까지 정수인지, 반올림과 절사가 카드별 규칙을 따르는지
- 한도를 넘는 혜택이 나올 수 있는지. 건, 일, 월, 묶음 한도를 전부 거치는지
- 월 경계가 한국 시간인지, 취소와 할부가 카드별 기준대로 달에 들어가는지
- 손계산 테스트가 경계값을 덮는지. 한도 직전과 직후, 구간 하한 아래와 위

**기록 내보내기와 가져오기**
- 내보내기 파일에 카드번호, 결제 알림 원문, 카드번호 끝 4자리 짝, 엑셀 열 짝 지문이 들어가지 않는지
- 가져오기가 실패하면 지금 기록이 그대로인지. 받은 행을 앱이 다시 읽을 수 있는지

**개인정보**
- 결제 기록, 카드, 답, 카드번호, 알림 원문이 폰 밖으로 나가는지. 앱이 인터넷으로 하는 일이 카탈로그 받기 하나인지
- 로그와 임시 파일에 식별 정보가 남는지. Android 자동 백업이 꺼져 있는지
- 엑셀 가져오기 파일과 고른 파일의 임시 사본을 읽은 뒤 지우는지

**DB 마이그레이션**
- 폰 안 SQLite 표 정의를 새 번호로만 더하는지, 기존 행을 잃는지, 결제와 계산에 쓴 개정의 연결이 끊기는지
- 옛 판에서 내보낸 기록 파일을 새 판이 받는지

## 보고

문제마다 한 줄로 쓴다. 파일과 줄, 무엇이 틀리는지, 어떤 입력에서 어떤 잘못된 결과가 나오는지, 심각도 높음·중간·낮음. 문제가 없으면 "문제 없음"과 확인한 항목만 쓴다.
