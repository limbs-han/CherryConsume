# 계산 규칙 변경 절차

1. **근거 확인.** 카드사 공식 문구나 사용자가 정한 방침 중 무엇이 근거인지 적는다. 근거가 없으면 멈추고 묻는다.
2. **문서 먼저.** `docs/2026-09-19-cherryconsume-design.md`의 계산 규칙 절에 규칙 문장을 넣는다. 예외 상황이면 `docs/scenarios.md`에 E 번호를 새로 붙이고 설계 문서에서 그 번호를 인용한다.
3. **손계산 표.** 규칙이 바뀌는 경계를 고른다. 한도 직전과 직후, 구간 하한 바로 아래와 위, 월이 바뀌는 날 같은 것이다. 각 경우의 기대값을 손으로 계산해 카드별 YAML 표 픽스처에 넣는다. 계산 과정은 픽스처 주석에 한 줄로 남긴다.
4. **실패 확인.** 테스트를 돌려 새 경우가 실패하는지 본다. 처음부터 통과하면 테스트가 규칙을 못 잡은 것이니 경우를 다시 고른다.
5. **최소 구현.** 테스트를 통과하는 가장 작은 변경을 한다.
6. **전체 테스트.** app 폴더의 `flutter test`가 전부 통과해야 한다. 계산 엔진은 `app/lib/engine`의 Dart이고 손계산 표는 `app/test/engine/cases/`에 있다. 카탈로그를 바꿨으면 `uv run --project backend pytest -q`도 통과해야 한다.
7. **검토.** 돈 계산이 바뀌었으므로 `risk-reviewer` 에이전트에 변경분을 넘긴다. 지적 사항을 고친 뒤 사용자에게 무엇이 바뀌었는지 숫자 예와 함께 보고한다.
8. **기록.** `.claude/progress.md`에 바뀐 규칙과 남은 일을 적는다.
