# 작업 단위

작업 단위는 커밋 몇 개에서 며칠 분량의 목적 하나다. 오타나 한 줄 수정처럼 한 문장으로 설명되는 변경은 작업 단위를 만들지 않는다.

폴더는 `docs/work/<번호>-<영문 소문자 슬러그>/`다. 번호는 가장 큰 번호에 1을 더한 세 자리다. 안에 세 파일을 둔다.
- `intent.md`: 왜, 성공 기준, 하지 않을 것
- `design.md`: 설계. 설계가 필요 없는 작은 작업이면 만들지 않는다
- `plan.md`: 단계 목록. 단계마다 "검증:"을 붙인다

다른 스킬이 설계나 계획 문서를 다른 경로에 쓰라고 해도 이 폴더의 `design.md`와 `plan.md`에 쓴다.

## 시작

1. `intent.md`를 먼저 쓴다. 사용자에게 한 번에 하나씩 물어 채운다. 성공 기준은 검사나 테스트로 참과 거짓을 가릴 수 있게 쓴다.
2. 사용자가 intent를 확인하면 설계로 넘어간다. 설계는 절마다 사용자 확인을 받고 `design.md`에 적는다.
3. `plan.md`를 쓴다.
4. `.claude/progress.md`의 지금 위치를 이 폴더로 바꾼다.

## 진행

- 단계를 끝낼 때마다 `plan.md`에 표시하고 `.claude/progress.md`를 고친다.
- 커밋 본문에 "작업 001"처럼 번호를 적는다.
- 설계가 바뀌면 코드보다 `design.md`를 먼저 고친다.

## 끝

1. `intent.md`의 성공 기준을 하나씩 검사로 확인하고 결과를 `plan.md` 끝에 적는다.
2. 결론을 전체 문서인 설계 문서, ERD, 시나리오에 합친다. 기준은 전체 문서이고 작업 폴더는 이력이다.
3. `.claude/progress.md`에서 이 작업을 끝난 것으로 옮긴다.
