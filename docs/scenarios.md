## 2. 예외 상황과 처리

### 2.1 실적 계산

| ID | 상황 | 처리 | 새로 정한 것 |
|---|---|---|---|
| E1 | 카드를 등록한 달에는 전월 결제 데이터가 없음 | 등록 시트의 전월 실적 추정값으로 구간 결정. 비워 두면 최저 구간에 `no_prev_month_data` 경고 | |
| E2 | 등록한 달에 지난달 결제를 뒤늦게 입력함 | 입력한 전월 결제가 1건 이상이면 그 합계를 쓰고, 없을 때만 추정값을 쓴다. 다음 달부터는 입력한 결제만 본다 | 결정. 입력값 우선 |
| E3 | 한 달 결제가 0건 | 인정 실적 0, 다음 달 최저 구간. 홈에 "이번 달 실적 없음" 표시 | |
| E4 | 할부 결제 | 카드사 처리를 따른다. 카드 규칙 `spend.installment`가 당월 전액이면 결제 달에 전액, 매달 할부금이면 할부 개월 동안 나눠 인정. 무이자할부 제외 카드면 무이자 건은 제외 | 결정. `spend_rules.installment_basis`, `transactions.installment_months` 추가 |
| E5 | 결제 취소·환불 | 기록을 지우지 않고 취소 금액과 시각을 적는다. 카드 규칙 `spend.cancellation`이 취소한 달이면 그 달 실적에서 빼고 이번 달 구간은 유지, 원 결제 달이면 그 달 실적을 다시 계산하고 전월이었으면 이번 달 구간도 다시 정한다. 구간이 바뀌면 이번 달에 저장한 혜택도 새 구간으로 다시 계산한다. 2026-09-29 작업 002 위험 검토에서 정했다. 전액 취소면 예상 혜택도 0으로 되돌려 한도 사용량에서 뺀다. 취소 시각은 결제마다 하나라 다른 달에 더 취소한 금액은 미지원이다. 0원 취소는 취소를 되돌린다. 2026-10-02 작업 005 위험 검토 | 결정. `spend_rules.cancellation_basis`, `transactions.cancelled_amount`, `cancelled_at` 추가 |
| E6 | 실적 기준이 전월 달력 월이 아닌 카드. 당월 실적, 3개월 평균, 연간 실적, 결제일 기준 | `spend.basis`가 `prev_calendar_month`가 아닌 카드는 실적 계산을 하지 않고 홈에 실적 계산 미지원 배지와 공식 안내 링크를 보여 준다. 결제일 기준 실적은 이용기간 표가 모델에 들어간 뒤에 계산한다 | 결정. `spend.basis` |
| E7 | 시간대 경계. 밤 12시 근처 결제, 해외 체류 | 모든 월 경계는 한국 시간 기준. `paid_at`은 시각과 시간대를 함께 저장하고 집계 때 한국 시간으로 변환 | 결정 |
| E8 | 연회비 청구 | 업종 `annual_fee`로 기록하면 실적 제외. 사용자가 직접 기록해야 함 | |
| E9 | 해외 결제 | 결제의 `region`이 `overseas`. 해외 혜택과 해외 실적 제외는 카드 규칙의 지역 조건을 따른다 | |

## 4. 이 문서에서 새로 정한 스키마 변경

- `cards.spend_basis` 추가. 값은 `prev_calendar_month` 또는 `unsupported`. 기본 `prev_calendar_month`
- `spend_rules.installment_basis` 추가. `full_at_purchase` 또는 `per_installment_month`
- `spend_rules.cancellation_basis` 추가. `cancel_month` 또는 `original_month`
- `transactions.installment_months`, `cancelled_amount`, `cancelled_at` 추가. 취소는 삭제가 아니라 기록으로 남김
- `benefits.conditions_not_modeled` 추가. bool, 기본 false
- `benefits.active` 추가. bool, 기본 true. 카탈로그 교체 때 사라진 혜택을 지우지 않고 비활성으로
- `card_requests` 테이블 추가. id, user_id, issuer_text, card_name_text, created_at
- `transactions.approval_no`, `transactions.import_batch_id` 추가. `import_batches` 테이블 추가
- `transactions.sync_state`는 앱 로컬에만 두고 서버 스키마에는 넣지 않음
- `transactions.source` 추가. manual, excel, notification 중 하나. 기본 manual
- 결제 알림 초안과 카드번호 끝 4자리 짝은 앱 로컬에만 두고 서버 스키마에는 넣지 않음
- 카탈로그 2판으로 카탈로그 영역을 `card_revisions` 중심으로 바꿨다. 작업 001 설계 3.4
