# 체리컨슘 사용자 시나리오와 예외 상황

작성일 2026-09-19. 화면 번호는 화면 시안 `design/체리컨슘-화면-시안.pdf`의 보드 번호, 계산 규칙은 설계 문서 6.5절을 따른다. 여기서 새로 정한 결정은 설계 문서와 ERD에도 반영했다.

## 1. 주요 시나리오

## 2. 예외 상황과 처리

### 2.1 실적 계산

| ID | 상황 | 처리 | 새로 정한 것 |
|---|---|---|---|
| E1 | 카드를 등록한 달에는 전월 결제 데이터가 없음 | 등록 시트의 전월 실적 추정값으로 구간 결정. 비워 두면 최저 구간에 `no_prev_month_data` 경고 | |
| E2 | 등록한 달에 지난달 결제를 뒤늦게 입력함 | 입력한 전월 결제가 1건 이상이면 그 합계를 쓰고, 없을 때만 추정값을 쓴다. 다음 달부터는 입력한 결제만 본다 | 결정. 입력값 우선 |
| E3 | 한 달 결제가 0건 | 인정 실적 0, 다음 달 최저 구간. 홈에 "이번 달 실적 없음" 표시 | |
| E4 | 할부 결제 | 카드사 처리를 따른다. 카드 규칙 `spend.installment`가 당월 전액이면 결제 달에 전액, 매달 할부금이면 할부 개월 동안 나눠 인정. 무이자할부 제외 카드면 무이자 건은 제외 | 결정. `spend_rules.installment_basis`, `transactions.installment_months` 추가 |
| E5 | 결제 취소·환불 | 기록을 지우지 않고 취소 금액과 시각을 적는다. 카드 규칙 `spend.cancellation`이 취소한 달이면 그 달 실적에서 빼고 이번 달 구간은 유지, 원 결제 달이면 그 달 실적을 다시 계산하고 전월이었으면 이번 달 구간도 다시 정한다. 구간이 바뀌면 이번 달에 저장한 혜택도 새 구간으로 다시 계산한다. 2026-09-29 작업 002 위험 검토에서 정했다. 전액 취소면 예상 혜택도 0으로 되돌려 한도 사용량에서 뺀다. 취소 시각은 결제마다 하나라 다른 달에 더 취소한 금액은 미지원이다. 0원 취소는 취소를 되돌린다. 2026-10-02 작업 005 위험 검토 | 결정. `spend_rules.cancellation_basis`, `transactions.cancelled_amount`, `cancelled_at` 추가 |
| E6 | 실적 기준이 전월 달력 월이 아닌 카드. 당월 실적, 3개월 평균, 연간 실적, 결제일 기준 | `spend.basis`가 `prev_calendar_month`가 아닌 카드는 실적 계산을 하지 않고 홈에 실적 계산 미지원 배지와 공식 안내 링크를 보여 준다. 결제일 기준 실적은 이용기간 표가 모델에 들어간 뒤에 계산한다 | 결정. `spend.basis` |
| E7 | 시간대 경계. 밤 12시 근처 결제, 해외 체류 | 모든 월 경계는 한국 시간 기준. `paid_at`은 시각과 시간대를 함께 저장하고 집계 때 한국 시간으로 변환 | 결정 |
| E8 | 연회비 청구 | 업종 `annual_fee`로 기록하면 실적 제외. 사용자가 직접 기록해야 함 | |
| E9 | 해외 결제 | 결제의 `region`이 `overseas`. 해외 혜택과 해외 실적 제외는 카드 규칙의 지역 조건을 따른다 | |

### 2.2 혜택과 추천

| ID | 상황 | 처리 | 새로 정한 것 |
|---|---|---|---|
| E10 | 이번 달 한도를 다 씀 | 그 혜택 기대 금액 0, `limit_exhausted` 경고. 다른 카드가 앞으로 옴. 5b에서는 "한도 소진"으로 회색 표시 | |
| E11 | 금액을 넣지 않고 추천을 봄 | 정률 혜택은 금액이 없으면 비교가 안 되므로 1만 원을 기준 금액으로 계산하고 화면에 "1만 원 기준"이라고 적는다 | 결정 |
| E12 | 주말·시간대·결제 횟수 순서 같은 조건이 붙은 혜택 | 조건은 `when`으로 계산한다. 결제 입력으로 판단할 수 없는 조건만 `unmodeled`에 문장으로 남기고, 그 혜택은 조건이 없는 것처럼 계산하되 확인 필요를 붙인다 | 결정. 작업 001 설계 2.4, 2.13 |
| E13 | 포인트·마일리지 적립과 할인을 비교 | `point_programs.yaml`의 1포인트 가치로 원으로 바꿔 정렬하고, 화면에 "적립"이라고 종류를 구분해 적는다 | |
| E14 | 한 카드에 같은 가게에 걸리는 혜택이 둘 | 같은 중복 묶음이면 큰 것 하나, 다른 묶음이면 더해서 받는다. 5b에서는 작은 쪽을 "중복 불가, 할인이 더 큼"으로 표시 | |
| E15 | 카드사 업종 분류와 카카오 분류가 다름. 백화점 안 카페, 편의점 안 택배, PG 이름으로 찍힌 온라인 결제 | 별칭표가 카카오 분류보다 우선. 없으면 사용자가 업종 칩을 바꿈. 화면 하단에 "카탈로그 기준 추정치" 문구 고정 | 알려진 한계 |
| E16 | 가게 검색 실패, 카카오 API 장애 | 업종 칩 수동 선택으로 진행. 가게 이름은 자유 입력 그대로 저장 | |
| E17 | 카드를 한 장도 등록하지 않고 추천 탭 진입 | 빈 상태 화면과 "카드 추가" 버튼 | |
| E18 | 카탈로그 갱신으로 혜택이 바뀜 | 이미 저장된 결제의 예상 혜택은 고정. 이후 결제부터 새 규칙. 카드 상세에 갱신일 표시 | 사용자 알림은 2차 |
| E19 | 카드가 단종됨 | `cards.active = false`. 보유 카드는 유지하고 계산도 계속. 카드 추가 검색에서는 숨김. 상세에 "신규 발급 중단" 표시 | |
| E37 | 구간이 모자라 지금 못 받는 혜택 | 카드 상세의 "구간이 모자라 아직 못 받는 혜택"에 보여 줌. 필요 금액은 그 구간 하한 − 이번 달 인정 실적. 받는 시점은 다음 달. 추천 결과에는 넣지 않는다. 결제 직전에는 지금 받는 혜택만 필요하다 | 결정. 설계 문서 6.5절 `LockedBenefit`. 2026-09-30 사용자가 추천 결과에서 뺐다 |
| E47 | 결제가 부모 업종까지만 알 때. 카카오 업종이 음식점까지만 알려 주거나 통신사처럼 휴대폰과 인터넷을 둘 다 파는 가맹점 | 실적 제외와 혜택 제외에는 걸린 것으로, 혜택 대상에는 안 맞는 것으로 보고 자식 업종을 한 번 묻는다. 추천에서는 조건부 혜택으로 보여 준다 | 결정. 작업 002 설계 2.1 |
| E48 | 순위 카드의 달 중간 혜택이 달 끝 순위와 다를 때 | 달 중간에는 그때까지의 순위로 계산하고 `ranked_provisional`을 붙인다. 달이 끝나면 그 카드의 그 달 결제를 최종 순위로 다시 계산한다. 다시 계산하는 범위는 그 카드의 그 달 결제 전체이고 지금 카탈로그로 계산한다. 저장한 혜택을 다시 계산하지 않는다는 원칙의 예외다. 예외는 E5, E51, E52, E53, E54, E56과 함께 일곱이다 | 결정. 작업 002 설계 3.5 |
| E50 | 결제를 고치거나 모르던 값을 답해 앞 결제의 혜택이 늘어남. 예: 9월 3일 결제가 카페 월 한도를 다 쓴 뒤 9월 2일 결제가 네이버페이였다고 답함 | 그 결제만 다시 계산하고 뒤 결제의 저장된 혜택은 그대로 둔다. 한 달 합계가 한도를 넘게 계산될 수 있다. 사용자가 뒤늦게 고친 것으로 본다 | 결정. 작업 002 설계 3.9 |
| E52 | 이미 저장한 결제보다 앞선 시각의 결제를 손으로 넣음. 예: 9월 15일 21시 GS25 4,300원을 저장해 430원을 받은 뒤 같은 날 10시 GS25 5,000원을 넣음. 편의점 할인은 하루 1회 | 그 달부터 마지막 결제가 든 달까지 결제 시각 순서로 다시 계산한다. 카드사처럼 앞 결제가 한도를 먼저 쓴다. 10시 결제가 500원, 21시 결제가 0원이 된다. 연 한도도 맞는다. IBK 나라사랑 철도 연 4회를 다 쓴 뒤 3월 결제를 넣으면 5월 결제가 0원이 된다. E50은 고치거나 답한 경우라 그 결제만 계산한다 | 결정. 2026-10-01 사용자가 정했다. 작업 005 |

## 4. 이 문서에서 새로 정한 스키마 변경

- `cards.spend_basis` 추가. 값은 `prev_calendar_month` 또는 `unsupported`. 기본 `prev_calendar_month`
- `spend_rules.installment_basis` 추가. `full_at_purchase` 또는 `per_installment_month`
- `spend_rules.cancellation_basis` 추가. `cancel_month` 또는 `original_month`
- `transactions.installment_months`, `cancelled_amount`, `cancelled_at` 추가. 취소는 삭제가 아니라 기록으로 남김
- `benefits.conditions_not_modeled` 추가. bool, 기본 false
- `benefits.active` 추가. bool, 기본 true. 카탈로그 교체 때 사라진 혜택을 지우지 않고 비활성으로
- `card_requests` 테이블 추가. id, user_id, issuer_text, card_name_text, created_at
- `transactions.approval_no`, `transactions.import_batch_id` 추가. `import_batches` 테이블 추가
- `transactions.sync_state`는 앱 로컬에만 두고 서버 스키마에는 넣지 않음
- `transactions.source` 추가. manual, excel, notification 중 하나. 기본 manual
- 결제 알림 초안과 카드번호 끝 4자리 짝은 앱 로컬에만 두고 서버 스키마에는 넣지 않음
- 카탈로그 2판으로 카탈로그 영역을 `card_revisions` 중심으로 바꿨다. 작업 001 설계 3.4
