## 과정

### 첫 결과

틀에 빠진 게 없게 카드 20장의 실제 규칙을 모두 다시 읽었다. "카드사 별로 든 카드 별로 든"은 두 가지로 읽혀서 둘 다 설계에 넣었다.
- 카드사 공통 규칙을 한 번 적고, 카드마다 필요한 부분만 덮어쓴다.
- 갱신을 카드사 단위로도, 카드 한 장 단위로도 돌릴 수 있게 한다.

세 방식을 비교했다.

| 방식 | 한 줄 설명 | 장점 | 단점 |
|---|---|---|---|
| A. 지금 틀에 칸 추가 | 혜택 한 줄에 필드를 계속 늘린다 | 바로 쓸 수 있음 | 구간마다 혜택을 복제하는 문제가 남고, 새 조건이 나올 때마다 DB 테이블을 고쳐야 함 |
| B. 개정 이력이 있는 규칙 문서 | 카드 한 장에 개정 목록을 두고, 조건과 한도와 중복 규칙은 종류가 정해진 블록으로 적는다 | 20장의 예외를 거의 다 담음. 새 조건 종류는 코드에 모델 하나만 더하고 DB는 그대로 둠. 갱신 전후 비교가 쉬움 | 모델 종류가 많아 검증 코드를 꼼꼼히 짜야 함 |
| C. 규칙 전용 식 언어 | "평일이고 카페면 10%" 같은 식을 직접 해석한다 | 표현력이 가장 큼 | 해석기를 따로 만들어야 하고 AI 추출과 사람 검수가 어려움 |

B를 추천했다. 개정은 카드사가 혜택을 바꿀 때마다 새로 추가하는 규칙 묶음이고 적용 시작일이 붙는다. 지난달 실적은 지난달 규칙으로 계산해야 하므로 옛 개정은 지우지 않는다.

이어서 1절 파일 구조와 갱신 흐름을 냈다.
- 파일은 업종, 가맹점, 포인트 종류와 1포인트 가치, 리터당 기름값 같은 기준값, 카드사 파일, 카드 파일로 나눈다.
- 카드사 파일에는 공통 규칙과 수집 설정을 적는다. 20장을 보니 신한, KB, 현대는 실적 제외 목록이나 취소 반영 달 같은 규칙이 카드마다 거의 같았다.
- 카드 파일 윗부분에는 카드사 내부 상품 코드, 발급 상태, 연회비, 출처, 원문과 마지막으로 대조한 날, 개정 목록, 확인 못 한 질문을 둔다.
- 본문 지문은 광고와 날짜를 걷어 낸 본문으로 만든 짧은 값이다. 한 글자만 바뀌어도 값이 달라져서 원문을 다시 읽을지 판단하는 데 쓴다.
- 심의필 번호는 카드사 광고가 여신금융협회 심의를 받았다는 번호다. 유효기간이 끝날 때 페이지도 바뀌는 경우가 많다.
- 1판 notes에 흩어진 "공식 문구 미확인"은 `open_questions`로 모아 검수할 때 한눈에 보게 한다.

## 최종 결과

- 방식은 개정 이력이 있는 규칙 문서다. 카드사가 혜택을 바꾸면 새 개정을 더하고 옛 개정은 남긴다.
- 파일 구조
  - `catalog/categories.yaml`: 업종. 2단 트리
  - `catalog/merchants.yaml`: 가맹점과 별칭
  - `catalog/point_programs.yaml`: 포인트 종류와 1포인트 가치
  - `catalog/reference.yaml`: 계산에 쓰는 기준값
  - `catalog/issuers/<카드사>.yaml`: 카드사 공통 규칙과 수집 설정
  - `catalog/cards/<카드사>/<카드 id>.yaml`: 카드 한 장
- 카드 파일에 없는 항목은 카드사 값을 쓰고, 적은 항목만 카드 값으로 덮어쓴다.
- 수집 방법은 api, browser, manual, blocked 중 하나다.
- 갱신 흐름
  1. 카드사 단위로 상품 목록을 받아 상품 코드로 기존 카드와 짝을 맞춘다. 처음 보는 카드는 초안으로 만들고, 목록에서 사라진 카드는 지우지 않고 발급 중단 후보로 둔다.
  2. 카드 단위로 원문의 본문 지문을 비교한다. 같으면 대조한 날만 고치고, 다르면 혜택을 다시 뽑아 검증하고 사람이 검수해 새 개정으로 발행한다.
  3. 부가서비스를 줄일 때 카드사가 미리 내는 공지에서 시행일을 읽어 미래 개정을 넣는다.
  4. 혜택 key는 갱신해도 유지한다. 결제 기록이 개정과 혜택 key를 가리킨다.
  5. 같은 갱신을 두 번 돌려도 파일이 바뀌지 않게 저장 형식을 고정한다.
  6. 주기는 카드사마다 14일이나 30일이다. 행사 종료 2주 전, 심의필 유효기간 만료, 미해결 질문이 남은 카드는 주기와 상관없이 다시 본다.
- 남은 절은 2절 혜택 규칙, 3절 결제와 보유 카드 입력과 DB 변경, 4절 검증과 20장 옮기기다.
