## 과정

### 첫 결과
손계산 표와 시안 카탈로그를 앱 시험 폴더로 옮기고, 지우기 직전 시험 이름 대조가 빠짐 0인 것을 본 뒤 서버, Python 엔진, 로그인을 지웠다. 출시 서명과 실제 폰 안내는 단계 8에 필요해 새 안내서로 옮겼다. CI에서 서버 시험을 뺐다. 사용자 명세서 폴더는 지우지 않고 사용자가 옮기게 했다.

옮기는 사이 DataBricks 세션의 종료 훅이 백엔드 시험에서 걸려 알려 왔다. 지우기를 바로 이어 시험을 다시 통과시키고 그 세션에 알렸다.

### 사용자 확인
지침, 규칙, README를 고칠 안을 보였다. 사용자가 "안대로 고치기 (추천)"를 골랐다. 시나리오 E28 CSV 내보내기는 "JSON 내보내기가 대신 (추천)"을 골랐다.

### 위험 검토
높음 0, 중간 4, 낮음 15건이 나왔다. 옛 명세서 자리를 무시 목록에 계속 두고, 절차의 시험 명령에 `flutter test`를 넣고, 남은 서버 문장을 고쳤다. 종료 훅과 검토 에이전트 지침을 바꿀지 물었고 사용자가 "둘 다 바꾸기 (추천)"를 골랐다.

### 수정 요청 1
푸시하면 운영 배포가 한 번 돈다고 알리고 물었다. 사용자가 "커밋하고 푸시"를 골랐다.

반영: 여섯 커밋으로 나눠 넣었다. 진행 상황 파일은 다른 세션의 줄을 빼고 내 줄만 올렸다.
