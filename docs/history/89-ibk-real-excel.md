## 요청

> 설문 만들기와 앱 만들기는 일단 미뤄두고 그럼 이제 해야할게 뭐야

할 일 여섯을 순서대로 내자 사용자가 실제 폰 새 판 깔기와 실제 IBK 엑셀 가져오기를 하기로 했다. 엑셀은 IBK카드 앱에 저장 안내가 없어 기업은행 홈페이지 "파일저장"의 "출력용"과 "거래용"을 받아 폰으로 옮겼다.

## 과정

### 실제 폰 새 판
옛 판 홈을 찍어 두고 작업 014가 든 출시 판을 기록을 지우지 않고 덮어 깔았다. 옛 한 벌 카탈로그가 든 DB였는데 새 판 홈이 똑같았다. 다시 켜면 첫 화면까지 0.2초로 옛 판 0.3초보다 빨랐다. 1,500장 첫 실행은 앱 화면이 뜨기 전 일이라 폰의 실행 시간에 잡히지 않고, 시험용 판을 이 폰에 깔면 기록이 지워질 수 있어 11월 실제 1,500장 판으로 미뤘다.

### 두 파일
앞머리 바이트로 보니 출력용은 확장자만 xls인 html 표이고, 거래용은 진짜 옛 xls라 지금 앱이 읽지 못한다.

### 수정 요청 1
> 승인 일시에 결제일과 시각이 같이 있는경우 두개 다 승인 일시로 하니깐 읽기가 안되네
> 나머진 잘 돼
> 그리고 나라사랑카드의 경우 체크카드가 그런지는 모르겠는데 통신요금할인, 쇼핑할인, ~할인이 이용가맹점명에 있네

파일을 저장소에 올라가지 않는 `app/test/local/`로 가져와 머리 줄과 할인 줄 모양만 봤다.
- 가맹점 열 이름 "이용가맹점명"을 앱이 몰라 자동 짝짓기가 안 됐다. 그래서 손으로 짝짓다 결제일과 시각을 같은 승인일시 열로 고르면 "한 열은 한 칸에만" 검사에 막혔다
- 할인 줄은 승인구분 "취소또는할인"이고 가맹점명이 할인으로 끝난다. 시험으로 보니 "카카오T 자동결제 할인" 1,000원 줄이 이름이 겹치는 카카오T 결제를 1,000원 취소한 것으로 붙었다
- IBK는 취소된 결제를 원래 승인 줄 없이 취소 줄로만 적는다

반영: 열 이름 사전에 "이용가맹점명"을 더하고, 결제일 칸에 시각이 함께 있으면 시각도 그 열을 고를 수 있게 했다. 취소 표시가 있고 이름이 할인으로 끝나는 줄은 카드가 준 할인으로 따로 보이고 넣지 않는다. 진짜 옛 xls 안내에 기업은행 출력용을 적었다. 시나리오 E59를 새로 적었다.

### 위험 검토
높음 1, 중간 4, 낮음 3이었다.
- 높음. 시험 값에 실제 파일의 가게 이름, 시각, 금액, 승인번호를 옮겨 썼다. 지어낸 값으로 바꿨다
- 중간 1. 화면 검사가 같은 열 짝을 여전히 막았다
- 중간 2. 이름이 할인으로 끝나는 가게의 진짜 취소를 할인으로 뺄 수 있었다. 승인번호가 같은 결제가 있으면 취소로 본다
- 중간 3. 승인번호가 서로 다른 취소를 이름과 금액으로 다른 결제에 붙였다. 둘 다 승인번호가 있고 다르면 붙이지 않는다. 실제 파일에서 승인 줄 없는 다른 표의 취소가 같은 가게의 다른 결제를 부분 취소한 것으로 붙어 있던 것이 이 규칙으로 풀렸다. 잘못 붙으면 보이지 않게 틀리고 못 붙이면 미리보기에 보여 붙이지 않는 쪽을 골랐다
- 중간 4. 부분 취소를 승인금액으로 읽어 전액 취소로 넣을 수 있었다. 취소금액 열이 있으면 그것을 쓴다
- 낮음. 같은 열 시각이 날짜만 든 칸을 0시로 읽던 것, 할인 줄 설명이 두 번 나오던 것

다시 검토에서 중간 1, 낮음 4가 나와 고쳤다. 결제 줄에 취소금액이 찍히면 일부 취소된 결제라 넣지 않고 보인다. 그대로 넣으면 취소된 만큼 실적이 부풀려진다. 할인 줄의 승인번호 대조를 고른 카드 안으로 좁혔다. 날짜만 든 xlsx 칸 시험을 바로 만들었고, 화면 짝짓기 칸에 취소금액을 더했다. 다른 카드사가 취소 줄에 새 승인번호를 주는지는 그 카드사 실제 파일이 와야 안다

## 최종 결과

- 실제 IBK 출력용 파일이 자동으로 짝지어진다. 결제 42건이 들어가고, 원 결제가 없는 취소 4건과 카드 할인 8건은 넣지 않는다
- 이 PC에서만 도는 실제 파일 대조 시험을 `app/test/local/`에 두었다
- 앱 시험 818개가 통과한다
- 남은 것: 거래용 같은 진짜 옛 xls 읽기는 쓰는 사람이 생기면 정한다. 다른 카드사 실제 파일과 해외 결제 줄은 받으면 본다
