## 과정

### 첫 결과
파일이 아니라 터미널에서 돌리는 서버 켜기 명령이라고 답하고, DB를 먼저 켜고 backend 폴더에서 돌리는 순서를 안내서 3-2에 적었다.

### 수정 요청 1
> powershell 말고 git bash 여야만 해?

반영: PowerShell도 된다고 답하고 `$env:` 꼴의 명령을 알렸다. 배포 안내서는 Git Bash 문법이 많다고 알렸다.

### 수정 요청 2
> 디버깅 키고 usb pc 에 꽃은다음 뭐해

반영: USB 디버깅 허용, `adb devices`, `adb reverse`, `flutter run` 순서를 안내했다.

### 수정 요청 3
> 카카오 앱 ID 가 저거 맞아?

반영: 화면의 숫자가 앱 ID이고 네이티브 앱 키와 다르다고 답했다.

### 수정 요청 4
> 했는데 앱 관리자 설정오류 KOE101 떴어

반영: 빌드 옵션에 네이티브 앱 키가 아닌 값이 들어갔다고 보고 다시 빌드하는 법을 알렸다. 안내서 자주 나는 것에 KOE101을 더했다.

### 수정 요청 5
> 로그인 둘다 성공했어

반영: 작업 005 슬라이스 7 4단계와 5단계를 끝으로 표시했다. 탈퇴도 폰에서 해 보기를 권했다.

### 수정 요청 6
> 탈퇴했고, 성공했어

반영: 실제 폰의 탈퇴 확인 E27을 계획에 적었다. 슬라이스 7이 끝났다.

### 수정 요청 7
> supabase 가입 github 로 했는데 커넥트 깃허브 할까?

반영: 마이그레이션은 우리 서버가 돌리니 연결하지 말라고 답했다.

### 수정 요청 8
> 프로젝트 만들때 사진의 설정은 어떻게 할까

반영: Security의 세 칸을 모두 끄라고 답하고 배포 안내서 1의 3을 지금 화면에 맞췄다.

### 수정 요청 9
> 커넥트 눌렀는데 여기서 뭐해

반영: Direct Connection string에서 Session pooler를 고르라고 답하고 안내서 1의 5를 고쳤다.

### 수정 요청 10
> deploy 1.7 의 터미널이 어디 터미널 말한거야

반영: 새로 연 창 하나로 2의 11까지 한다고 답하고 안내서 1의 7에 적었다.

### 수정 요청 11
> 명령어를 항상 powershell 위주로 말해

반영: 기억 파일에 적고 두 안내서의 명령을 PowerShell로 바꿨다. 카카오 키 해시 변환과 백업 명령은 이 PC에서 돌려 확인했다.

### 수정 요청 12
> 이제와서 드는 생각인데 우리서비스에 이런 클라우드가 필요할까?
> 그냥 우리가 초기에 앱에 데이터를 다 담아두면 사용자 입장에서 데이터를 키지않고도 카드 등록, 카드 실적 관리 등등을 하는게 더 좋을 것 같아

반영: 서버를 둔 까닭과 폰 안에서 할 때 좋아지는 것, 잃는 것, 옮기는 데 드는 것을 표로 내고 폰 안 구조를 권했다.
- 선택: 서비스 구조 → 폰 안에서 다 하기
- 선택: 카탈로그 새로 하기 → 켜질 때 내려받기
- 선택: Python 엔진 → Dart 하나만 남기기
- 선택: 서버와 로그인 → 옮긴 뒤 지우기
- 선택: 폰을 바꿀 때 → 파일 내보내기 기능만

작업 005 슬라이스 8 배포를 멈추고, 설계 문서의 확정된 결정 구조 줄에 결정을 적고, 작업 006 의도를 썼다.

### 수정 요청 13
> 내보내기 가져오기 맞아

반영: 폰을 바꿀 때를 파일 내보내기와 가져오기로 확정했다. 엔진 시험이 387개이고 카드별 YAML 표가 20개라 성공 기준 2를 바로잡았다. 설계 1절 앱 안의 층을 썼다.

### 수정 요청 14
> 좋다

반영: 설계 1절을 확정하고 2절 카탈로그 파일과 내려받기를 썼다. 검수 승인 커밋의 `export.yml`에 JSON 다시 만들기 단계를 누가 더할지 물었다.

### 수정 요청 15
> 여기까지 내용을 주 개발 세션으로 승계해줘

반영: 진행 상황을 고치고 주 개발 세션에 인계했다.
