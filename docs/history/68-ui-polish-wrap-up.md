## 과정

### 성공 기준 확인과 빠진 시안 보드
의도 성공 기준 10개를 하나씩 확인했다. 엔진 코드와 엔진 시험은 작업 내내 바뀌지 않았다. 기준 1을 보다 차이 목록이 시안 보드 14개 가운데 셋을 빠뜨린 것을 찾았다. 0 시작, 3 카메라 인식, 10 상태 모음이다. 시작은 로그인 화면이라 작업 006에서 로그인을 뺀 대로, 카메라는 기능을 뺀 대로 두었다. 상태 모음에서 앱과 다른 넷을 물었다.
- 선택: 카드 상세의 카드별 답 → 설정처럼 줄과 바닥 시트 (추천)
- 선택: 추천에서 가게를 못 찾을 때 → 바닥 시트로 고르기 (추천)
- 선택: 결제 뒤 세부 업종 질문 → 칩만 알약으로 (추천)
- 선택: 추천의 조건 확인 → 추천에 붙이기 (추천)

### 짧은 이름이 들어온 뒤
그 사이 사용자가 `export`를 손으로 돌려 짧은 이름이 봇 커밋 `90ff4b3`으로 들어왔다. 긴 카드 이름을 기대하던 앱 시험 18개가 깨져 기대값을 짧은 이름으로 고쳤다. 저장소 시험도 카드 이름 표시를 보는 세 줄을 고쳤다. 짧은 이름을 정하는 곳이 저장소 함수 `named`이기 때문이다. Databricks 세션에는 시험을 따로 고치지 말고, 앞으로 이름을 바꾸는 승인은 먼저 알려 달라고 했다.

### 상태 모음 고치기
설계 2절에 M1, C1, T1~T5로 적고 시험부터 고쳤다.
- T2 결제 뒤 세부 업종 질문의 칩을 알약으로 바꿨다. 묻는 때와 자리는 그대로다
- T3 카드 상세의 사실과 옵션 답을 설정처럼 줄마다 답이나 배지와 화살표로 두고 바닥 시트에서 고른다. 줄 부품은 공용으로 옮기고 설정과 카드 상세가 같은 답하기 줄을 쓴다
- T4 가게를 못 찾으면 업종 칩 수십 개 대신 "업종 고르기"를 눌러 바닥 시트에서 고른다
- T5 추천 결과의 카드 줄에 문장으로만 남은 조건이 있으면 "조건 확인" 배지와 그 문장을 붙인다. 엔진이 이미 주던 경고를 응답에 담았고 계산은 그대로다. 시나리오 E12

에뮬레이터는 앞 요청에서 사용자가 끄라고 해 다시 찍지 않았다. 네 화면은 실제 폰 확인에서 함께 본다.
