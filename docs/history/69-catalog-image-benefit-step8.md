## 과정

### 첫 결과
받아 둔 상품 페이지 약 190장과 브라우저 카드사 페이지 56장, 카드사마다 찍은 화면 열 장을 봤다. 혜택 표를 이미지로 넣은 실제 사례는 없었다. 페이지 전체 글로 재면 메뉴와 바닥글만으로 수천 자라 하나도 걸리지 않았다. 이 결과를 알리고 만들지 물었다.
- 선택: 8단계를 어떻게 할지 → 설계대로 만들기

기준을 머리말, 바닥글, 메뉴를 뺀 본문으로 재게 했다. 수집기는 기준에 걸린 상품 페이지를 끝까지 스크롤한 뒤 찍어 HTML 옆에 `.png`로 두고, 글 뽑기는 그 사진을 `ai_parse_document`로 해석해 `method` `screenshot`으로 쓴다. `documents`에 `image_count` 칸을 더했다. 개발용에서 KB 상품 페이지를 기준과 상관없이 찍어 넣으니 페이지 아래쪽까지 3,519자가 읽혔다.

위험 검토에서 높음 하나, 중간 여섯, 낮음 다섯이 나왔다. 높음은 브라우저 HTML이 받을 때마다 바이트가 달라 같은 페이지도 매번 다시 해석되고 바뀐 원문으로 잡힌다는 것이었다. 같은 원문의 앞 사진 문서와 페이지 글이 같으면 그 글을 다시 쓰게 했다. 본문 영역 이름을 낱말 단위로 보기, `noscript` 안 이미지 빼기, 스크롤 뒤 다시 재기, 찍기 실패에도 HTML 남기기, 해석 실패면 HTML 글 쓰기도 고쳤다. 받아 둔 187장을 새 기준으로 재니 10장이 걸렸고 모두 로고와 배지였다. 농협과 삼성이라 브라우저로 받지 않아 찍지 않는다.

### 수정 요청 1
> 결과 나오면 알려줘

반영: 개발용에서 같은 KB 페이지를 글은 같고 바이트만 다르게 한 번 더 넣었다. 사진 해석 0개, 앞 사진 글 다시 쓰기 1개였고 두 행의 지문이 같아 바뀐 원문 0개였다.

## 최종 결과

- 수집기는 브라우저로 연 상품 페이지가 본문 이미지 3장 이상이고 본문 글 2천 자 미만이면 스크롤 뒤 다시 재서 찍는다.
- 글 뽑기는 사진이 있으면 해석한 글을 쓰고, 페이지 글이 앞과 같으면 앞 사진 글을 다시 써 추출 요금이 다시 나지 않는다.
- 지금 브라우저 카드사 상품 페이지 중 기준에 걸리는 것은 없다. 실제 사례가 나오면 기준을 고친다.
