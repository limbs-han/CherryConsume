## 과정

### 첫 결과
어시스턴트가 평소 따르는 커밋 규칙을 정리해 보여줬다.

- 커밋과 푸시는 사용자가 시킬 때만 한다
- 기본 브랜치에 있으면 커밋 전에 브랜치를 만든다. 첫 커밋은 이 규칙을 지키지 않고 master에 바로 넣었다고 밝혔다
- 기존 커밋을 고쳐 쓰지 않고 새 커밋을 만든다
- 훅을 건너뛰지 않는다. 훅은 커밋할 때 자동으로 도는 검사다
- 강제 푸시나 하드 리셋처럼 되돌리기 어려운 명령은 다른 길이 없을 때만 쓴다
- 공동 작성자 표기는 붙이지 않는다

프로젝트 전용 규칙을 적어 두면 이후 세션에서도 따르겠다고 제안했다.

### 수정 요청 1
> 커밋 규칙이야 똑똑히 기억해놔
>
>
> ```
> # Git Commit & Merge Request Convention
>
> 모든 커밋과 MR은 아래 규칙을 따른다.
>
> ## 1. 기본 형식
>
> <type>: <작업 내용>
> ```

뒤로 Type 목록, 작업 내용 작성 규칙, 커밋 분리 기준, 에이전트 실행 규칙, Git 사용자 정보와 민감 정보 보호가 이어진다. 전문은 `.claude/skills/commit/SKILL.md`에 있다. type은 feat, fix, docs처럼 커밋 종류를 알리는 머리말이다.

반영: 규칙을 프로젝트 CLAUDE.md에 넣고 기억 파일에도 요점을 남겼다. CLAUDE.md는 프로젝트를 열 때마다 AI 작업 도구가 자동으로 읽는 지침 파일이다. 이어서 두 가지를 짚었다.

- 앞서 만든 커밋 `d4ff752`가 새 규칙에 어긋난다. type 머리말이 없고 문서와 디자인 파일을 한 커밋에 묶었다. 원격 저장소가 없으니 풀어서 다시 나눌 수 있다
- 지금 브랜치가 master다. 컨벤션에 브랜치 규칙은 없지만 기본 브랜치에 바로 커밋하지 않는 것이 평소 동작이라고 알렸다

아이콘 교체와 CLAUDE.md처럼 아직 커밋하지 않은 변경은 규칙대로 셋으로 나누자고 제안했고, Git 사용자 정보와 민감 파일도 확인했다.

### 수정 요청 2
> d4ff752 풀어서 규칙대로 다시 나눠줘

반영: 풀기 전에 파일 9개의 체크섬을 적어 두었다. 체크섬은 파일 내용이 바뀌지 않았는지 대조하는 지문 같은 값이다. 커밋 7개로 다시 나눴다.

|---|---|---|---|
| a2071cb | chore: 프로젝트 초기 설정과 gitignore 추가 | .gitignore | 4ab31d6 |
| 934d9ec | docs: 커밋 컨벤션 문서 추가 | CLAUDE.md | 없음. 06에서 뺐다 |

지금 해시는 이후 히스토리를 다시 쓴 뒤의 값이고 메시지로 짝을 맞췄다.

- 검증. 작업 트리에 남은 변경이 없고 체크섬 9개가 모두 일치했다. 코드가 아직 없어 빌드와 테스트는 건너뛰었다
- 버린 아이콘 후보 두 개는 처음부터 커밋되지 않은 상태가 됐다
- 옛 커밋 `d4ff752`는 참조만 끊겨 기본 90일 동안은 되살릴 수 있다고 알렸다
- 커밋은 시간 순서가 아니라 산출물 단위로 나눴다. 그래서 시나리오에서 나온 필드를 담은 ERD가 시나리오 문서보다 먼저 커밋됐다

### 수정 요청 3
> 혼자 개발하는건데 브랜치를 따로 파야해?

답: 지금은 필요 없다고 했다. 브랜치를 권한 것은 어시스턴트의 기본 습관이었고 사용자가 준 컨벤션에는 없는 규칙이라고 바로잡았다. 혼자 쓰는 저장소에서 브랜치는 품만 늘고, 커밋을 작게 자주 나누는 편이 되돌릴 지점을 촘촘하게 만든다.

브랜치가 필요해지는 때로 셋을 들었다.
- 스토어에 올린 뒤. 사용자가 쓰는 버전이 생기면 master를 늘 동작하는 상태로 둬야 한다
- 버릴지도 모르는 작업. 카메라 인식처럼 될지 모르는 것을 파 볼 때다
- CI를 붙인 뒤. CI는 코드를 올릴 때마다 빌드와 테스트를 자동으로 돌리는 장치다

출시 뒤에는 릴리스마다 태그를 붙이는 것이 브랜치보다 먼저라고 덧붙였다. 태그는 특정 커밋에 버전 이름표를 붙이는 기능이다. 이 판단을 CLAUDE.md에 한 줄로 남길지 제안했고, 사용자는 다음 질문으로 넘어갔다.

## 최종 결과

- 커밋 형식은 `<type>: 한국어 작업 내용`이다. 한 커밋에 논리적 작업 하나만 담고, 요청받을 때만 커밋한다
- 규칙 전문은 처음에 CLAUDE.md에 넣었다. CLAUDE.md는 푸시 전에 저장소에서 빼고 내 컴퓨터에만 두었다. [06](06-github-readme.md) 참고
- `d4ff752`는 규칙대로 커밋 7개로 나뉘었다. 이후 컨벤션 커밋이 빠지고 README 커밋이 더해져 푸시된 커밋도 7개다
- 브랜치는 지금 필요 없다는 답을 받았고 이후 커밋도 master에 바로 했다
