## 요청

> databricks 하나로 DB 역할까지 할 수 있어?

Databricks는 이 프로젝트에서 카드 수집 파이프라인과 분석에 쓰는 데이터 플랫폼이다.

## 과정

### 첫 결과
Databricks의 어느 부분을 쓰느냐에 따라 답이 갈린다고 했다.

보통 말하는 Databricks인 Delta 테이블과 SQL 웨어하우스로는 안 된다. Delta 테이블은 Databricks의 분석용 테이블이고, SQL 웨어하우스는 그 위에서 SQL을 돌리는 계산 서버다. 큰 데이터를 한 번에 훑는 데 맞춰져 있어, 앱처럼 결제 한 건을 넣고 바로 읽는 일에는 맞지 않는다.
- 결제 한 건 저장에 수백 밀리초에서 수 초가 걸린다. 파일을 다시 쓰는 방식이라서다
- 여럿이 동시에 쓰면 쓰기 충돌이 난다. 앱 DB에서 기본으로 기대하는 행 단위 잠금이 없다
- 사용자 id로 한 행을 찍어 읽는 조회에 인덱스가 없어 매번 훑는다
- 웨어하우스는 켜 둔 시간만큼 돈을 낸다. 가장 작은 서버리스를 상시 켜 두면 월 수백만 원 단위이고, 꺼 두면 첫 요청이 수십 초 걸린다

대신 Databricks 안의 Lakebase를 쓰면 된다고 했다. 2025년에 나온 기능으로, Databricks가 인수한 Neon 기술로 만든 관리형 Postgres다. Postgres는 널리 쓰는 오픈소스 DB이고, 관리형은 서버 운영을 서비스 회사가 대신 맡는 방식이다. ERD가 Postgres 기준이라 스키마를 바꾸지 않고 올라가고, 우리 서버인 FastAPI도 Postgres 드라이버로 붙는다. 앱 DB는 Lakebase, 수집과 분석은 Delta로 두고 둘 사이를 테이블 동기화로 이으면 설계 문서 4.1절의 밤마다 Parquet 내보내기가 사라진다. Parquet는 분석용 파일 형식이다.

| 항목 | Lakebase | Neon, Supabase 같은 별도 Postgres |
|---|---|---|
| 비용 | 첫날부터 유료. 안 쓰면 0으로 줄지만 무료 구간 없음 | 무료 구간이 있어 사용자 몇백 명까지 0원 |
| Free Edition | 상업 이용 금지라 어차피 못 씀 | 해당 없음 |
| 성숙도 | 나온 지 1년 남짓 | 수년 |
| 분석 연동 | 붙어 있음 | 내보내기 코드를 직접 짬 |

Free Edition은 Databricks의 무료판이다. 둘 다 Postgres라 덤프 후 복원으로 오갈 수 있다. 덤프는 DB 내용을 파일로 통째로 뽑는 일이다.

권고는 설계를 그대로 두고, 무료 구간이 있는 Postgres로 시작하되 Postgres 표준 기능만 써서 Lakebase로 옮길 수 있게 하는 것이었다. 수익이 없는 단계에서 첫날부터 나가는 돈을 만들 이유가 없고, 분석 데이터가 쌓일 때 옮기면 연동 이점을 그때 챙길 수 있다. Lakebase의 정확한 요금과 서울 리전 제공 여부는 기억이 확실하지 않아 나중에 확인하겠다고 했다. 서울 리전은 서울에 있는 데이터센터다.

### 수정 요청 1
> 오케이 그렇게 할게 문서에 작성해줘

반영: 설계 문서와 README를 고쳤다.
- 2절 결정 표. "앱 DB" 행을 새로 넣었다. Postgres, 처음엔 무료 구간이 있는 관리형 서비스로 시작, 분석 데이터가 쌓이면 Lakebase 이전 검토, 표준 기능만 사용이다
- 4.2절 신설 "앱 DB 운영 방식". Delta 테이블과 SQL 웨어하우스를 앱 DB로 쓰지 않는다는 것과 이유 세 가지를 적고, FastAPI가 요청마다 웨어하우스를 부르는 구조를 만들지 않는다고 명시했다. 1단계는 출시부터 무료 관리형 Postgres, 2단계는 4.1절 동기화가 실제로 필요해질 때 Lakebase다. 2단계로 갈 때 요금 구조, 서울 리전, 안 쓸 때 과금 수준을 옮기기로 정하는 시점에 확인해 적는다. 옮기는 절차는 덤프와 복원 후 접속 문자열 교체이고, 표준 기능만 썼다면 코드는 바뀌지 않는다
- 4.1절 끝. Lakebase로 옮기면 밤마다 Parquet 내보내기가 테이블 동기화로 바뀌고, 가명처리는 위치만 Delta 쪽으로 옮겨질 뿐 원칙은 같다고 덧붙였다. 가명처리는 누구인지 알아볼 수 없게 개인 식별 정보를 바꾸는 처리다
- 7절 위험. 무료 구간 조건이 바뀔 수 있다는 항목을 더했다. 상한에 가까워지면 유료 전환과 Lakebase 이전 중 하나를 미리 정한다
- README. 기술 스택의 서버 줄에 같은 내용을 한 줄로 넣었다

## 최종 결과
- 앱 DB는 Postgres다. 처음엔 무료 구간이 있는 관리형 Postgres로 시작한다
- Delta 테이블과 SQL 웨어하우스는 앱 DB로 쓰지 않는다
- Postgres 표준 기능만 써서, 4.1절 동기화가 실제로 필요해지면 Lakebase로 옮길 수 있게 둔다
- Lakebase 요금, 서울 리전, 안 쓸 때 과금은 옮기기로 정할 때 확인한다
- 무료 구간 조건이 바뀔 위험은 설계 문서 7절에 올렸다
