# 09 이용 내역 엑셀 가져오기

- 날짜: 2026-09-19
- 결과물: `docs/2026-09-19-cherryconsume-design.md`, `docs/erd.md`, `docs/erd.html`, `docs/scenarios.md`, `design/wireframes.html`, `README.md`
- 커밋: `4855a94` docs: 이용 내역 엑셀 가져오기를 MVP 범위에 추가

## 요청

> 엑셀 가져오기 설계 문서에 넣어줘

08 문서에서 마이데이터 대신 제안한 중간 길이다. 카드사 웹 등에서 받은 이용 내역 엑셀 파일을 앱에 올려 결제를 한꺼번에 넣는 기능이다.

## 과정

### 첫 결과
설계 문서 두 곳을 바꿨다.
- 2절 확정 결정 표. 결제 입력 행을 "1차는 수동 입력만. 출시 뒤 이용 내역 엑셀 가져오기 추가"로 고쳤다. 마이데이터를 안 쓰는 이유에 데이터 사용료를 더했다
- 8절 신설. 제목은 "1차 출시 뒤 붙일 기능: 이용 내역 엑셀 가져오기"이고 여섯 항목이다

8절 여섯 항목은 다음과 같다.
- 왜 필요한가. 수동 입력의 이탈 위험과 마이데이터의 허가·비용 사이에 있는 길이다
- 어디서 받은 파일인가. 카드사 PC 웹 내려받기, 토스·뱅크샐러드 내보내기다. 형식이 제각각이라 카드사별 매핑 표를 둔다. 매핑 표는 파일의 어느 열이 날짜이고 어느 열이 금액인지 짝지어 둔 표다. 표에 없는 형식은 사용자가 열을 직접 짝짓는다
- 어떻게 처리하나. 카드 지정, 열 매핑, 업종 판정, 중복 제거, 취소 행을 원 결제에 붙이기, 미리보기 확인 뒤 저장 순서다. 중복은 승인번호로 가리고, 없으면 카드·일시·금액·가맹점명으로 가린다. 수동 입력 건과 겹치면 파일 쪽을 버린다
- 어디서 처리하나. 서버다. 매핑 표를 앱 재배포 없이 고치기 위해서다. 올린 파일은 파싱 직후 지우고 개인정보처리방침에 적는다. 파싱은 파일 내용을 읽어 항목별로 나누는 일이다
- 하지 않는 것. 카드사 사이트에 로그인해 대신 내려받는 자동화다. 스크래핑 금지와 약관 위반이라 파일은 늘 사용자가 직접 올린다
- 언제 하나. 앱 MVP로 수동 입력의 귀찮음을 실제로 확인한 뒤, 출시 준비와 같은 시기나 직후다

취소 처리는 앞서 정한 카드별 규칙 `cancelled_amount`, `cancelled_at`을 그대로 쓴다. 커밋은 하지 않았다.

### 수정 요청 1
> 1차 출시말고 처음부터 MVP에 넣자

반영: MVP는 처음 출시할 때 꼭 들어가는 최소 기능 묶음이다. 엑셀 가져오기를 MVP 범위로 옮기고 파일 6개를 고쳤다. 커밋은 하지 않았다.
- 설계 문서 1절 핵심 기능. 결제 기록에 "이용 내역 엑셀을 올려 한 달치를 한 번에"를 더했다
- 2절 결정 표. 결제 입력을 "직접 입력 + 엑셀 가져오기. 둘 다 MVP에 포함"으로 바꿨다
- 5절 하위 프로젝트 2. 범위에 엑셀 가져오기를 넣고 완료 기준에 "카드사 웹에서 받은 엑셀 한 달치가 중복 없이 들어감"을 더했다
- 6.3절 결제 모델. 승인번호 `approval_no`, 가져오기 배치 `import_batch_id` 필드를 더했다. 배치는 가져오기 한 번에 들어간 결제 묶음이다
- 8절. 제목에서 "1차 출시 뒤"를 떼고 시점을 하위 프로젝트 2로 바꿨다. 매핑 표는 초기 카드 20장의 카드사부터 채우고, 가져오기 한 번을 배치 한 행으로 남겨 되돌릴 수 있게 하는 항목을 더했다
- ERD. ERD는 테이블과 그 관계를 그린 DB 설계도다. `import_batches` 테이블을 더해 19개가 됐다. 출처, 파일 이름, 행 수, 저장 건수, 중복 건수를 남긴다. 중복 판정 인덱스 메모도 넣었다. 승인번호가 있는 행에는 카드와 승인번호 조합이 겹치지 않게 막고, 없으면 카드·일시·금액·가맹점명 일치로 본다. 렌더 페이지 `docs/erd.html`도 다시 만들었다
- 시나리오. 새 절 2.2b에 주요 시나리오 S11 "한 달치 결제를 엑셀로 한 번에 넣기"와 예외 6개를 넣었다. 모르는 형식은 사용자가 열을 짝짓고 그 결과를 재사용, 이미 넣은 결제와 겹치면 파일 쪽을 버림, 원 결제 없는 취소 행은 저장에서 제외, 여러 카드가 섞인 파일은 카드 이름 열로 나눔, 배치 단위로 되돌리기, 파일은 파싱 즉시 삭제다
- 와이어프레임. 화면 흐름 목록에 기록 탭에서 시작하는 가져오기 경로를 한 줄 더했다. 파일 선택, 열 짝짓기, 미리보기 화면은 그리지 않았다. 화면이 2~3개 늘어나는 일이라 따로 지시하면 하겠다고 했다
- README. 기능 표와 본문의 결제 입력 설명, ERD 테이블 수를 맞췄다

## 최종 결과
- 이용 내역 엑셀 가져오기를 MVP에 넣는다. 결제 입력은 직접 입력과 엑셀 가져오기 두 가지다
- 처리는 서버에서 하고, 올린 파일은 파싱 직후 지운다
- 중복은 승인번호로, 없으면 카드·일시·금액·가맹점명으로 가린다. 수동 입력 건과 겹치면 파일 쪽을 버린다
- 가져오기 한 번은 `import_batches` 한 행으로 남겨 배치 단위로 되돌릴 수 있다
- 카드사 사이트 로그인 자동화는 하지 않는다
- 가져오기 화면 2~3개는 아직 그리지 않았다
- 작업 당시에는 커밋하지 않았고, 이후 `4855a94`로 들어갔다
