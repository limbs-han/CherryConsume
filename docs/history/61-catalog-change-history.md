## 요청

> 카탈로그쪽을 databricks 작업 세션으로 보내줘

주 개발 세션에서 한 말이고, 주 개발 세션이 이 세션에 넘겼다. 사용자가 "우리 cdc 적재는 계획에 없어?"라고 묻자 주 개발 세션이 사용자 로그 쪽과 카탈로그 쪽 두 갈래를 보였고 사용자가 카탈로그 쪽을 골랐다.

## 과정

### 첫 결과
작업 010을 만들고 의도를 썼다. 골드 `card_revisions`는 승인할 때 고친 개정을 지우고 새로 넣어 고치기 전 규칙이 표에서 사라진다는 것을 확인해 적었다. 정할 것 셋을 물었다.
- 선택: 변경 이력의 원천 → card_revisions (추천)
- 선택: 이력 방식 → 2형, 옛 행을 남김 (추천)
- 선택: 이력 표를 볼 곳 → 운영 대시보드 (추천), SQL로만

### 수정 요청 1
> 확인, 010 먼저 해

반영: 의도를 확정하고 작업 008 4단계보다 먼저 하기로 했다. 설계를 썼다. 원천은 변경 데이터 피드, Lakeflow AUTO CDC로 2형 이력 표, 순서 값은 판 번호와 판 안의 차례와 시각을 묶은 것, 표 바뀜 트리거로 돈다.

### 수정 요청 2
> 확인

반영: 설계를 확정하고 1~4단계를 개발용에서 했다. 피드를 켜고 파이프라인 `cherry_history`를 돌려 23행이 모두 열린 행으로 찼다. 승인과 같은 MERGE로 규칙을 바꾸자 같은 판 안에서 옛 행이 닫히고 새 행이 열렸고, 개정을 빼자 열린 행이 닫혔다. 대시보드가 골드 스키마를 가리킬 수 없어 이력 표를 실버로 옮겼다. 대시보드에 "카탈로그 변경" 묶음을, 안내서에 SQL 예시 셋을 넣었다.

### 수정 요청 3
> 대시보드 보여, 지워도 돼

반영: 개발용 대시보드 확인을 마쳤고, 골드에 처음 만들었던 시험 이력 표를 지웠다. 위험 검토를 받아 중간 셋, 낮음 넷을 고쳤다. 피드와 보존 60일은 승인과 골드 첫 적재가 서비스 주체로 켜고, 운영 이력 표는 전체 다시 쌓기를 막는다.

### 수정 요청 4
> 커밋하고 푸시하고 운영 지금 켜

반영: 커밋 넷을 푸시했고 `test`와 `deploy`가 성공했다. 이 푸시에 주 개발 세션의 커밋 둘이 함께 올라갔다. 사용자가 그쪽 창에서 푸시를 요청한 것이라 문제없다고 주 개발 세션이 답했다. `064b76e`가 진행 상황 파일에서 주 개발 세션의 작업 006 두 줄을 옛 판으로 되돌려 `bf60864`로 되살렸다. 운영 `cherry_seed_gold`를 처음 해시 그대로 다시 돌려 운영 개정 표에 피드와 보존 설정을 넣었다.

### 수정 요청 5
> 결과 나오면 알려줘

반영: 트리거가 이력 작업을 켜기를 기다렸다.

### 수정 요청 6
> 언제 되는거야

반영: 24분 동안 트리거가 돌지 않았다. 표 바뀜 트리거는 데이터 변경만 보고 설정 변경은 보지 않는다는 것을 공식 문서로 확인했다. 운영 이력 작업을 손으로 한 번 돌려 62초 만에 성공했다. 운영 이력 표가 22행, 모두 열린 행으로 운영 개정 22개와 같았다.

### 수정 요청 7
> 커밋하고 푸시해

반영: 운영 켜기 결과와 트리거 한계를 설계 2절과 계획 6단계에 적어 `6c4b787`로 푸시했다.

### 수정 요청 8
> 끝 단계 진행해

반영: 성공 기준 열을 확인해 계획 끝에 적었다. 통과 여덟, 일부 둘이다. 운영 대시보드 데이터셋을 운영에서 돌려 "첫 적재" 22행이 표를 직접 센 값과 같았다. 테스트 312개가 통과했다. 전체 설계 문서 5절과 안내서에 결과를 합쳤다.

## 최종 결과

- 골드 `card_revisions`의 변경 데이터 피드를 Lakeflow AUTO CDC 파이프라인 `cherry_history`가 받아 실버 `card_revision_history`에 2형으로 쌓는다. 개발용과 운영 모두 돈다.
- 운영 이력 표는 2026-10-04 22행으로 시작했다. 어느 날 어떤 규칙이 맞았는지 안내서의 SQL로 묻고, 운영 대시보드 "카탈로그 변경" 묶음에서 본다.
- 개정 표에 데이터가 바뀌면 표 바뀜 트리거로 돈다. 설정 변경으로는 돌지 않는다.
- 남은 것: 다음 운영 승인 뒤 트리거로 이력이 갱신되는지, 청구 기록으로 본 한 번의 비용. 비용은 2026-10-13 비용 검토 때 함께 본다.
