## 과정

### 첫 결과

| 해시 | 메시지 | 한 줄 설명 |
|---|---|---|
| 4855a94 | docs: 이용 내역 엑셀 가져오기를 MVP 범위에 추가 | 설계 문서, 시나리오, ERD, README, 와이어프레임 |

설계 문서, README, 와이어프레임은 한 파일 안에 주제가 섞여 있었다. 그래서 다른 주제의 변경을 되돌린 중간 판을 만들어 순서대로 커밋했고, 끝난 뒤 최종본과 한 글자도 다르지 않은지 확인했다. 색과 홈 구조를 고르며 만든 비교 페이지 `design/accent-candidates.html`, `design/home-depth.html`은 커밋하지 않고 어떻게 할지 물었다. 푸시는 하지 않았다.

### 수정 요청 1
> 푸시해줘

반영: 커밋 3개를 GitHub 원격 저장소에 올렸다. 로컬과 원격이 같아졌다. 비교 페이지 둘은 여전히 커밋 밖에 있었다.

### 수정 요청 2
> html 말고 화면 시안은 github 에 못 올려?

반영: 캔버스 자체는 GitHub에 들어가지 않지만 화면마다 PNG로 찍어 넣으면 README에서 바로 보인다고 답했다. 헤드리스 브라우저로 찍으려고 Edge와 Chrome이 있는 것까지 확인했다. 헤드리스 브라우저는 창을 띄우지 않고 돌리는 브라우저다. PNG를 만들기 전에 작업이 멈췄다.

### 수정 요청 3
> png 말고 figma 형식처럼

반영: Figma 파일인 .fig는 Figma 안에서만 만들어져 밖에서 생성할 수 없다고 답했다. 대신 Figma가 고칠 수 있는 레이어로 열어 주는 SVG를 쓰는 두 방법을 냈다. SVG는 도형과 글자를 좌표로 적어 두는 그림 형식이고 GitHub에서도 이미지처럼 보인다.

- A. 화면 13개를 SVG로 변환해 저장소에 넣는다. 그림자와 그라데이션은 근사라 똑같지는 않다. 1시간쯤 걸린다. 추천한 안이다.
- B. HTML 소스를 두고 html.to.design 같은 Figma 플러그인으로 가져간다. 10분이면 되지만 변환은 사용자가 Figma에서 직접 한다.

### 수정 요청 4
> 그냥 지금이랑 똑같이 담고 싶은데 SVG로 비슷하게 말고

반영: 똑같이 담는 방법은 캔버스가 실제로 저장하는 파일 자체를 넣는 것이라고 답했다. 화면마다 하나인 `.dc.html` 13개와 배치 파일 `canvas.json`을 `design/canvas/project/`에, 생성 스크립트 `design/canvas/gen.py`를 넣어 `950c9f0` docs: 화면 시안 원본 파일과 생성 스크립트 추가로 커밋했다. 푸시는 하지 않았다.

이때 이미 푸시한 `7f1270c`의 와이어프레임 페이지에 캔버스 도구 이름과 주소를 적어 둔 것을 알렸다. 저장소에 남기지 않기로 한 문자열이었다. 처리 방법 둘을 냈다.

1. 새 커밋으로 문장만 바꾼다. 원격에 올라간 이전 커밋에는 그 문자열이 남는다.
2. 그 커밋을 고쳐 쓰고 강제 푸시한다. 강제 푸시는 원격 저장소의 기록을 로컬 기록으로 덮어쓰는 것이다. 히스토리에서도 사라지고, 혼자 쓰는 저장소라 위험은 없다.

### 수정 요청 5
> 2번으로 하고 디자인은 그냥 pdf 로 내보내기 했으니깐 저걸로 하자 나머지는 html은 그냥 지우고

반영: 사용자가 캔버스에서 내보낸 `design/체리컨슘 화면 시안.pdf`를 찾아 13페이지, 2.3MB이고 그 문자열이 없는 것을 확인했다. 히스토리 고쳐 쓰기와 HTML 삭제를 하기 전에 작업이 멈췄다.

### 수정 요청 6
> 그냥 화면 pdf까지 포함해서 커밋해서 푸시해줘

반영: 커밋 2개를 만들어 푸시했다.

- `45dfb21` docs: 와이어프레임 안내를 화면 시안 PDF로 연결. 와이어프레임 상단 문장을 PDF 안내로 바꾸고 캔버스 이름과 주소를 지웠다.
- `f53321b` docs: 고해상도 화면 시안 PDF 추가. PDF 이름의 공백은 README 링크가 깨지지 않게 하이픈으로 바꿔 `design/체리컨슘-화면-시안.pdf`로 넣고, README 문서 표에 한 줄 더했다.
- 푸시 전이던 원본 파일 커밋 `950c9f0`은 내려놓고 파일도 지웠다. 비교 페이지 둘도 지웠다. design 폴더에는 아이콘, 저해상도 와이어프레임, PDF만 남았다.
- "그냥 커밋해서 푸시"라고 해서 히스토리 고쳐 쓰기는 하지 않았다고 알렸다. 캔버스 원본과 생성 스크립트는 저장소 밖 작업 폴더에만 남아 세션이 끝나면 사라지고, 캔버스는 그대로 살아 있다고 짚었다.

### 수정 요청: 히스토리 정리
> 히스토리에서도 지우고 강제 푸시해줘

반영: 히스토리를 고쳐 쓰고 강제 푸시했다.

- `7f1270c`와 `45dfb21`을 하나로 합쳐 처음부터 PDF 안내 문장이 들어간 `73482bd` docs: 홈 요약 띠와 화면 시안 위치 반영으로 다시 만들었다. PDF 커밋은 그 위에 다시 얹어 `c4d63f7`이 됐다.
- 고쳐 쓴 뒤 최종 파일 상태가 이전과 같은지 비교했고 차이가 없었다. 원격 히스토리 전체에 그 문자열이 없는 것도 확인했다.
- 강제 푸시는 원격이 알던 상태일 때만 덮어쓰는 방식으로 했다.
- 앞으로 커밋 전에 저장소 전체에서 그 문자열을 검색하기로 했다.

### 추가 질문: Figma로 옮기는 방법
> 그럼 화면 시안 아티팩트는 어떻게 내보내기 할 수 있어? 별개의 요소가 아닌 저대로 내보내기 하고싶은데 피그마로든

사용자가 캔버스에서 "All artboards" PDF를 내보낸 뒤에 한 질문이다.

캔버스가 통째로 내보내는 형식은 PDF뿐이고 그 밖에는 아트보드별 이미지 정도다. 아트보드는 캔버스에 놓인 화면 한 장이다. Figma가 그대로 여는 것은 .fig, Sketch 파일, 이미지, SVG뿐이라 한 번에 Figma로 가는 내보내기는 없다고 답하고 셋을 냈다.

| 방법 | Figma에서 편집 | 한 줄 설명 |
|---|---|---|
| A. HTML을 Figma 플러그인으로 | 글자, 상자, 아이콘이 레이어로 들어옴 | 원본 충실도가 가장 높다. 추천한 안 |
| B. PDF를 Figma 플러그인으로 | 글자가 윤곽선이 되어 수정 불가 | 지금 PDF로 바로 시도할 수 있다 |
| C. SVG로 변환 | 글자와 도형이 레이어로 들어옴 | 그림자와 그라데이션은 근사. 작업 1시간 |

저장소에 편집 가능한 파일을 두는 것이 목적이면 PDF로 충분하고 Figma를 거치지 않아도 된다고 짚었다.

### 수정 요청 7
> 그럼 아티팩트로 나에게 보이는 화면 그대로를 html로 내보내기 할 수 있어? 하나의 html 로

반영: 화면 13개가 캔버스 배치 그대로 놓인 HTML 한 파일 `design/체리컨슘-화면-시안.html`을 만들었다. 92KB이고 외부 의존은 글꼴 링크 하나다.

- 윗줄 6개, 아랫줄 7개로 줄마다 제목, 화면마다 이름 띠를 달았다.
- 화면 안 버튼과 탭을 누르면 연결된 화면으로 이동하고 그 화면에 파란 테두리가 켜진다.
- 50%, 75%, 100%로 확대와 축소를 할 수 있고 처음엔 75%다.
- 색 변수는 코발트 값으로 채우고 캔버스 전용 껍데기는 벗겼다. 캔버스처럼 편집은 안 된다.

HTML은 저장소에서 빼기로 했던 터라 커밋하지 않고 넣을지 물었다.

### 수정 요청 8
> 넣어줘 커밋하고 푸시까지

반영: `5257482` docs: 화면 시안 HTML 추가로 커밋하고 푸시했다. 커밋 전에 도구 이름과 컴퓨터 경로가 없는지 검사했다. README 문서 표의 PDF 아래에 HTML 안내 한 줄을 더했다.

## 최종 결과

- 화면 시안은 저장소에 PDF와 HTML 두 파일로 둔다. 캔버스 원본 파일과 생성 스크립트는 넣지 않는다.
- PDF는 훑어보는 용도다. HTML은 내려받아 열면 화면 사이를 눌러 이동하고 확대와 축소를 할 수 있다. GitHub에서는 소스로만 보인다.
- design 폴더에는 아이콘, 저해상도 와이어프레임, 시안 PDF, 시안 HTML 넷이 있다.
- 캔버스 도구 이름과 주소가 담긴 커밋은 히스토리에서 지우고 강제 푸시했다.
- 이번 작업의 원격 커밋은 `4855a94`, `be61bd5`, `73482bd`, `c4d63f7`, `5257482`다.
