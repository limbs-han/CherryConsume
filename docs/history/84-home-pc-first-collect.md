## 요청

> PC에서 collect 돌렸는데 일단 다 실패뜨긴 했어

사용자가 집 PC에 GitHub 러너를 등록하고 `collect`를 30으로 처음 돌린 결과다.

## 과정

### 첫 결과
러너에서 `bash`가 Git Bash가 아니라 Windows의 WSL로 잡혀 bash 단계가 모두 바로 실패했다. 첫 단계에서 Git Bash 폴더를 PATH 앞에 넣게 고쳤다.

### 수정 요청 1
> 커밋하고 푸시해

> 푸시해

반영: `f0bd70a`를 푸시했다.

### 수정 요청 2
> collect 돌렸는데 이번에도 다 실패인데

반영: PATH를 넣는 단계가 PowerShell이었는데, Windows PC는 PowerShell 스크립트 실행이 기본으로 막혀 있었다. 그 단계를 cmd로 바꿨다.

### 수정 요청 3
> collect를 PC에서 돌릴땐 powershell 말고 git bash 로 하는게 좋아? 그럼 이것만은 git bash 로만 할게

> 커밋하고 푸시해

반영: 러너는 Git Bash에서 켜기로 하고 안내서를 고쳤다. `4ee498b`를 푸시했다.

### 수정 요청 4
> collect 돌렸는데 현대, 롯데, 우리 실패했어

반영: 여덟 카드사는 올라갔다. 현대는 상품 페이지 하나가 시간 초과였고 나머지 595줄은 올라갔다. 롯데는 Docling이 깨진 PDF를 읽다 수집기 프로세스가 죽어 41개에서 멈췄다. 그래서 롯데만 Docling을 껐다. 우리는 올리기에서 `ls`를 `grep -q`에 이은 곳이 파이프 쓰기 오류로 멈췄다. 올리기를 고치고, 한 카드사만 다시 받는 칸을 더했다. 현대 PDF 53개가 빈 쪽 기준에 걸려 기준을 낮췄다.

### 수정 요청 5
> 커밋하고 푸시

반영: `300c51d`를 푸시했다.

### 수정 요청 6
> 우리는 됐고 롯데는 돌리는 중이야

반영: 우리를 다시 돌린 결과 운영 `cherry_refresh`가 10분 걸려 새 원문 981개를 글로 바꿨다. 색인은 우리 934장, 판매 중 321장이다. 판매 중인데 종류를 모르는 카드는 10장이다.

### 수정 요청 7
> 롯데 collect 실패했어

반영: 롯데는 색인 카드 575개 가운데 554개를 받았고 수집기 중단은 없어졌다. 실패 40개는 모두 상품설명서 PDF 주소의 파일 이름에 든 한글과 공백 때문이었다. 모든 받기가 거치는 `_get`이 요청 직전에 주소를 퍼센트 인코딩하게 고쳐 `91dc3f6`을 푸시했다.

## 최종 결과

- 집 PC 러너는 Git Bash에서 켜고, 카드사를 하나씩 다시 받을 수 있다.
- 우리와 롯데 원문이 운영에 들어온다. 롯데 PDF 40개는 다음 실행에서 받는다.
- 삼성과 IBK의 카탈로그 카드 원문은 7단계 봇 커밋 전 실행이라 아직 없다. 사용자가 다시 실행을 예약했다.
