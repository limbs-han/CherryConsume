## 과정

### 첫 결과
사용자를 기다리지 않아도 되는 일 셋을 골랐다. 단계 3의 2 기록 내보내기 날짜, 단계 2의 5 시험자 안내 초안, 그리고 뒤에 Databricks 세션이 넘긴 카드 요청 링크다.

기록 내보내기 날짜는 표 정의 3번 `app_state`에 저장 창에서 저장했을 때만 적고, 설정의 내보내기 줄 아래에 마지막으로 내보낸 날을 보인다. 시험을 먼저 써 실패를 봤다. 처음 판은 날짜는 저장되는데 "내보내지 못했어요"가 떴다. `setState` 안에서 화살표로 Future를 돌려줘 디버그 검사에 걸린 것이고 기존 시험이 잡았다.

### 수정 요청
사용자가 고르기로 세 가지를 정했다. 기록 내보내기 날짜는 커밋하고 푸시한다. 카드 요청 링크는 이번 출시 준비에 넣는다. 설문 연락처는 카드를 넣고 알린 뒤 바로 지운다.

### 위험 검토
기록 내보내기 날짜는 높음 0, 중간 1, 낮음 7이었다. 중간 1은 표 번호가 3이 되자 지금 앱이 내보낸 2번 파일의 빠진 표와 칸 검사가 꺼진 것이다. 혜택 표가 빠진 파일을 받으면 혜택이 0원으로 굳는다. 기록 표가 마지막으로 바뀐 번호 `recordSchema = 2`를 두어 고쳤다.

카드 요청 링크와 방침은 높음 0, 중간 2, 낮음 7이었다. 시트에서 행만 지우면 설문 응답, 시트 버전 기록, 보낸 알림 메일에 메일 주소가 남아 방침의 "바로 지운다"와 달랐다. 설문을 시트에 잇지 않고 응답째 지우며 보낸 메일도 지우기로 했다. 넣을지 정하지 않은 요청은 지우는 때가 없어 받은 날부터 1년으로 묶었다. Databricks 세션의 설문 안내서도 같이 고쳤다. 다시 검토에서 Gmail이 메일을 보낸 주소를 기타 연락처에 저절로 남긴다는 지적을 받아 그 설정을 끄는 단계를 안내서에 더했다.

## 최종 결과

- 설정이 마지막으로 기록을 내보낸 날을 보인다. 판 번호 올리기는 단계 2가 끝난 뒤다.
- 시험자 그룹 첫 글과 7일쯤 둘째 글 초안이 있다. 링크 두 곳은 시험 트랙을 만든 뒤 채운다.
- 카드 추가 화면에 카드 요청하기가 있다. 설문 주소가 비어 있어 지금은 숨는다. 사용자가 설문을 만들면 주소를 적는다.
