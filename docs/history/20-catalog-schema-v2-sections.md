## 과정

### 첫 결과: 2절 혜택 규칙

20장 초안에서 1판이 담지 못한 규칙을 전부 담는 것을 기준으로 2절을 design.md에 썼다.
- 숫자 칸마다 구간 하한을 키로 한 구간표를 쓸 수 있게 했다. 1판처럼 구간마다 혜택을 복제하지 않는다. 신한 Mr.Life 주말 할인은 혜택 6개가 2개와 공유 한도 하나로 줄었다.
- 한도는 건, 일, 월, 분기, 연, 행사 기간으로 세고, 혜택 금액, 횟수, 계산에 넣는 결제액 세 종류를 둔다. 여러 혜택이 같이 쓰는 한도에는 이름을 붙인다.
- 중복 묶음을 두었다. 같은 묶음에서는 하나만 받고 다른 묶음끼리는 더한다. 한도를 넘은 금액을 다음 혜택으로 넘기는 방식도 적을 수 있다.
- 사용자가 고르는 옵션, 이번 달 이용액 순위로 고르는 자동 선택, 등록 때 묻는 사실을 두었다.
- 조건은 금액 범위, 요일과 공휴일, 시각, 지역, 채널, 할부, 결제수단, 청구 방식이다.
- 보상은 정률, 정액, 2만원당 1천P 같은 단위 계산, 리터당 할인, 한 달 합산 조건이다.
- 해외는 업종에서 빼고 결제의 지역으로 옮겼다. 업종은 두 단계 트리로 바꿨다.
- 행사성 혜택은 기간만 적고, 값이 바뀌는 날은 바뀐 곳만 적는 새 개정으로 둔다.
- 계산 예로 현대카드M 100만 구간 음식점 30만원을 들었다. 1판은 1만 포인트로 계산했지만 2판은 5% 한도를 넘은 10만원을 1.5%로 넘겨 11,500포인트가 된다.

### 수정 요청 1: 2절 확정, 3절 진행
> 이대로 확정하고 3절 진행해줘

반영: 2절을 확정으로 표시하고 3절 입력과 DB를 썼다.
- 원칙은 세 가지다. 입력 칸을 늘리지 않는다. 모르는 값을 아는 척 계산하지 않는다. 사용자가 넣은 값이 자동값보다 우선한다.
- 결제에 결제수단, 국내·해외, 청구 방식을 더하되, 결제 기록 화면에 이미 있는 "자동으로 채웠어요" 줄에만 보이게 했다.
- 보유 카드에 사용 시작일, 옵션 선택 이력, 사실 답을 더했다.
- 모르는 값은 저장한 결제에서는 조건을 채우지 않은 것으로 계산하고 한 번 묻는다. 추천에서는 "네이버페이로 결제하면 +1,000원" 같은 조건부 혜택으로 보여 준다.
- DB는 혜택을 행으로 쪼개던 테이블 5개를 없애고 개정 하나를 JSON 문서 하나로 두는 `card_revisions`로 바꿨다. 테이블은 19개에서 22개가 된다.

### 수정 요청 2: 3절 확정, 4절 진행
> 이대로 확정하고 4절 진행해줘

반영: 3절을 확정으로 표시하고 4절 검증과 20장 옮기기를 썼다.
- 검증기는 계산 엔진과 같은 패키지 `backend/cherry_core/catalog/`에 두고 1판 스크립트는 지운다.
- 모르는 필드는 실패로 처리하고, 구간, 대상, 조건, 보상, 한도, 묶음, 옵션, 날짜, 근거, key를 교차 검사한다. 저장 형식이 고정 형식과 다르면 실패로 처리한다.
- 20장은 기계 변환, 공통 파일, 카드사 파일, 카드별 판단, 따로 대조, IBK 확인, 보고 순서로 옮긴다. 시간은 하루 반쯤으로 잡았다.

### 수정 요청 3: 4절 확정, 전체 검토
> 이대로 확정하고 설계 전체 검토 진행해줘

반영: 설계 전체를 처음부터 다시 읽고 11군데를 고쳤다.
- 카드사 공통 규칙에도 적용 시작일을 붙였다.
- 같은 뜻의 두 이름을 `exclude_applied` 하나로 합쳤다. 업종 이름도 트리 이름으로 맞췄다.
- 자동 선택 그룹을 두 번 적지 않게 했다.
- 사실 정의에 범위를 넣었고, 조건 목록에 빠진 값과 조건 문법을 명시했다.
- 구간표 앞부분이 비는 경우를 막았다.
- 신규 발급 기준일은 등록할 때 묻는 문구를 그 카드의 기준에 맞추기로 했다.
- 엑셀에서 구분할 수 없는 삼성페이는 실물카드로 보기로 했다.
