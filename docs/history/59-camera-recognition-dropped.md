## 과정

### 의도
작업 009를 만들고 의도를 한 가지씩 물었다.
- 선택: 기준 그림 → 카드사 상품 페이지 이미지 (추천)

- 선택: 가진 카드 → 1장

### 수정 요청 1
> 그대로 확인, 설계 가자

반영: 설계를 절마다 물어 적었다.
- 선택: 1절 기준 그림 받기 → 처음은 저장소의 Python 도구 (추천)
- 선택: 2절 모델 → ML Kit 도 포함, 그다음 둘 다 재 보기
- 선택: 3절 벡터를 앱에 넣는 길 → catalog.json에 합치기 (추천)
- 선택: 4절 찍기 → 버튼으로 찍기 (추천)
- 선택: 5절 화면 → 제안대로 (추천)
- 선택: 6절 시험 → 제안대로 (추천)

계획을 다섯 단계로 쓰고, 막힌 카드사 다섯 장의 그림 저장과 사진 20장을 부탁했다.

### 수정 요청 2
> 단계 1 가자

반영: `camera`와 `tflite_flutter`를 넣어 에뮬레이터에서 앱이 뜨는 것을 봤다. 카메라 패키지가 붙이는 마이크, 저장소, 전화 상태, 네트워크 상태 권한을 뺐다. PC 도구로 그림 손질, 넓이 평균 줄이기, 정수 벡터, 순위, 색 기준선, 합성 사진을 만들고 시험 14개를 통과시켰다. 후보 모델 넷을 만들었다. 카드 그림 주소는 에이전트가 찾던 중이었다.

### 수정 요청 3
> 그냥 카메라 기능 빼자 너무 투머치같아
> 문서에도 다 반영하고 커밋해줘

반영: 에이전트를 멈췄다. 단계 1에서 넣은 패키지, 권한 설정, Gradle 설정, PC 도구와 시험, 의존성을 모두 커밋 전 상태로 되돌렸다. 앱에 남아 있던 "카메라로 인식" 버튼 둘과 그 버튼만 쓰던 준비 중 안내를 지웠다. 설계 문서, 시나리오 S2, E20, E23, ERD, README, 지침, 위험 검토 기준을 고쳤다. 작업 009 문서에는 중단을 적어 기록으로 남겼다. 받은 카드 그림과 후보 모델이 든 `plates/` 폴더는 지우는 명령이 안전 장치에 막혀 사용자에게 지워 달라고 했다.

## 최종 결과

카메라 카드 인식을 제품에서 뺐다. 카드는 카드사와 이름으로 검색해 등록한다. 화면 시안의 카메라 화면은 고치지 않고 만들지 않는다고만 적었다. 작업 008의 색인 표 `image_url` 칸은 카메라 인식용이라 이제 필요 없다. 앱 시험 629개가 통과한다.
