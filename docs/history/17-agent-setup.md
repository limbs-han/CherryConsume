## 과정

### 첫 결과

설정에 쓸 Claude Code 기능이 실제로 있는지 먼저 확인하고 제안을 냈다. 핵심은 규칙을 글로 부탁하지 않고 자동 검사로 강제하는 것이다. 글로 적은 규칙은 세션마다 지켜지는 정도가 다르지만 검사는 어느 PC에서든 똑같이 돈다.

| 넣을 것 | 한 줄 설명 |
|---|---|
| `CLAUDE.md` | 프로젝트 소개, 작업 순서, 금액은 정수 원 같은 필수 규칙, 이 PC 전역 설정에만 있던 말투 규칙 |
| `rules/` | `catalog/`나 `backend/`를 고칠 때만 읽히는 규칙 |
| `skills/` | 반복 작업 절차서. `/commit`, `/card`, `/rule-change` |
| `agents/` | 역할과 도구를 제한한 보조 작업자. 카드 조사, 카드 대조, 위험 변경 검토 |
| `hooks/` | 파일 수정 뒤, 커밋 전, 마치기 전, 세션 시작 때 자동으로 도는 검사 스크립트 |
| `progress.md` | 진행 상황과 다음 할 일. 다른 PC에서 어디까지 했는지 바로 보게 함 |
| `settings.json` | 모델 고정, 안전한 명령 자동 허용, `.env` 읽기와 강제 푸시 차단, 훅 연결 |
| `.gitattributes` | 줄바꿈 통일 |

훅은 Claude가 파일을 고치거나 작업을 끝낼 때 자동으로 도는 스크립트다. 검사가 실패하면 오류가 Claude에게 돌아가 다시 고치게 된다. 조사하는 에이전트와 검증하는 에이전트를 나눠야 실수가 잡힌다는 점도 적었다.

정할 것 하나를 물었다. `.claude` 폴더를 저장소에 올리면 전에 정한 "저장소에 claude 흔적을 남기지 않는다"는 규칙과 부딪힌다. 어느 PC에서든 같은 설정을 쓰려면 폴더가 git으로 따라다녀야 한다.

선택: `.claude` 폴더를 어떻게 관리할지 → 공개 유지, 그대로 올리기

### 만들기

공식 문서에서 권한 규칙과 설정 키 형식을 확인한 뒤 규칙, 스킬, 에이전트, 훅 파일을 만들었다. 작업 중 `rm -rf`가 든 명령이 방금 만든 차단 규칙에 막혀, 삭제 명령을 빼고 다시 돌렸다.

### 추가 질문 1

> intent.md 그런건 안 써?
>
> 지금 구조를 한 근거가 뭐야? 공식 문서대로 만든건가?
> 이게 ai native sdlc 구조야?

작업 도중 보낸 질문이다. 설정을 마무리하면서 세 가지에 답했다.

반영
- 근거는 공식 문서다. `.claude/CLAUDE.md` 위치와 200줄 이하 권장, `rules/`의 `paths:`, 훅 설정 형식과 스크립트가 종료 코드 2를 내면 오류를 Claude에게 돌려주는 방식, 권한 규칙 문법과 작성자 표시를 끄는 설정을 문서와 대조했다.
- 기억 폴더를 옮기려던 계획은 문서를 보고 바꿨다. 그 설정은 절대 경로만 받아 PC마다 달라지므로, 오래 둘 기억은 규칙 파일에 직접 넣었다.
- 무엇을 넣을지는 공식 권장 사항에서 골랐다. 반드시 지킬 규칙은 CLAUDE.md가 아니라 훅으로, 마치기 전에는 테스트를, 검토는 새로 시작한 검토자에게, 가끔 쓰는 절차는 스킬로 둔다는 내용이다. `progress.md`와 사람이 직접 커밋할 때도 도는 `.githooks`는 문서에 없고 어시스턴트가 더한 것이라고 밝혔다.
- AI native SDLC라고 하기에는 절반이라고 답했다. 정해진 폴더 구조가 있는 표준이 아니라 개발 흐름에 대한 방식이다. 만든 것은 규칙, 자동 검사, 역할 분리라는 도구 쪽 뼈대다. 작업마다 왜 하는지, 무엇이 되면 끝인지, 어떤 순서로 하는지를 잇는 기록이 빠졌다. AWS의 AI-DLC와 GitHub Spec Kit이 이 부분을 파일로 채운다고 예를 들었다. GitHub 서버에서 도는 자동 검사인 CI도 아직 없고, 계산 코드가 생기는 하위 프로젝트 1에서 넣는다.
- intent.md는 작업 단위마다 폴더를 두는 방식으로 제안했다. `docs/work/<번호>-<이름>/`에 intent.md, design.md, plan.md를 둔다. intent.md는 왜 하는지, 성공 기준, 하지 않을 것을 설계 전에 적는 10줄 정도의 문서다. 끝나면 결론을 설계 문서와 ERD에 합치고, 새 작업은 `/work` 스킬로 시작한다.

훅 검사 결과도 함께 보고했다.
- 커밋 메시지: type이 없는 "수정", "fix: 수정", 제목 끝 마침표, claude가 든 메시지, Co-authored-by를 붙인 경우가 모두 막혔다. 51자 제목은 알림만 띄웠다.
