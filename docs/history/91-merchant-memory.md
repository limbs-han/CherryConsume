## 요청

> 근데 이렇게 엑셀 업로드하니 업종 매치가 안되는게 너무 많은데 CU 같은 대중적인 프랜차이즈도 업종 매치가 안되더라고 이걸 해결할 방법이 뭐가있어

실제 파일 셋의 가게 이름을 가게 이름 없이 종류별 건수로만 셌다. 원인은 둘이었다. 브랜드인데 "씨유(CU) 지점명"처럼 적힌 모양이 달라 못 맞춘 것과, 카탈로그 145곳에 없는 동네 가게다. 동네 가게가 가게 이름 수의 2/3였다. CU는 별칭에 "CU" 자체가 없었다. 방법 넷을 한 줄 설명과 걸리는 시간으로 냈다. 고친 업종 기억, 이름 정리 뒤 맞추기, 뱅크샐러드 분류 쓰기, 카탈로그 늘리기다. 카카오맵이나 사업자번호 조회는 가게 이름을 폰 밖으로 보내야 해서 뺐다.

> 2와 1을 함꼐

## 과정

### 의도와 설계
정할 것 셋을 물었다. 사용자가 붙여 쓴 "지점명점"은 편의점과 카페만 맞추기, 이미 들어간 같은 이름 결제는 물어보고 바꾸기, 기억은 기록 내보내기에 담기를 골랐다. 의도 성공 기준 9개와 설계 7절을 사용자가 확정했다.

### 구현
1. 가게 이름 열쇠와 카탈로그 맞추기
2. 표 정의 5번 `merchant_categories`와 업종 순서. 결제에 고른 업종, 기억한 업종, 카탈로그 업종 차례다
3. "같은 가게 결제 N건도 바꿀까요?"와 한꺼번에 바꾸기. 카드마다 가장 이른 달부터 다시 계산한다
4. 기록 내보내기에 기억 담기

### 위험 검토
- 단계 1: 높음 1, 중간 3, 낮음 5
  - 높음: 공식 이름을 별칭처럼 쓰자 "KT 대리점"이 통신요금 혜택에 맞았다. 편의점과 카페만 공식 이름을 쓴다
  - 중간: 붙여 쓴 이름을 여러 낱말에 걸쳐 맞췄고, "커피빈스강남점"처럼 흔한 말과 같은 별칭이 동네 카페에 맞았다. 첫 낱말만, 한글 세 글자 이상의 "점"으로 끝날 때만 맞추고 "커피빈"은 붙여 쓴 이름에서 뺐다
  - 낮음: 괄호를 모두 빼자 "네이버페이(스타벅스)"가 네이버페이에 맞았다. 영문 괄호와 "(주)"만 뺀다
- 단계 2~4: 높음 없음, 중간 4, 낮음 11
  - "네이버페이(CGV)"와 "네이버페이(KFC)"가 한 가게로 묶이고, 기록 고치기가 가져오기와 다른 가맹점을 찾았다. 가맹점 찾기와 기억 열쇠를 모두 간편결제 이름을 뗀 가게 이름으로 맞췄다
  - 부모 업종을 고르면 자식 업종 결제를 덮어 혜택이 빠졌다. 덮지 않는다
  - 한꺼번에 바꾸기 시험이 좁았다. 카드 두 장, 두 달, 취소, 실적에서 빠지는 상품권으로 "처음부터 그 업종으로 넣은 것과 결과가 같다"를 시험한다
  - 기록 내보내기의 기준 번호 하나를 5로 올리면 옛 파일에서 혜택 표가 빠져도 받아 버렸다. 표마다 있어야 하는 번호를 둔다
- 카탈로그 별칭 빈틈인 CU의 "CU"와 할리스의 "할리스커피"는 Databricks 세션에 넘겼다. 그쪽이 운영 승인을 사용자에게 묻는다

## 최종 결과

- 이 PC의 실제 파일에서 업종이 맞는 가게 이름이 뱅크샐러드 25에서 35, 신한카드 1에서 2가 됐다. 예전에 맞던 가맹점이 바뀐 것은 없다
- 한 번 고친 동네 가게는 다음 결제와 엑셀 가져오기에 그 업종으로 들어간다
- 앱 시험 866개 통과. 성공 기준 9개 가운데 5는 편의점과 카페로 좁혀서 맞고 나머지 여덟이 맞다
- 남은 것: 출시 판을 폰에 깔아 사용자가 확인한다. 폰이 연결되지 않아 깔지 못했다
