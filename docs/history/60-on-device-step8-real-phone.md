## 과정

### 첫 결과
출시 키가 없고 폰이 연결되지 않아, 사용자가 할 출시 키 만들기와 USB 디버깅 켜기를 안내했다.

### 수정 요청 1
> release-setup 1-1 의 비밀번호 내가 임의로 설정해?

반영: 사용자가 직접 정한다고 답했다. 6자 이상, 한글과 역슬래시를 빼고, 세 곳에 같은 값을 쓴다고 알렸다.

### 수정 요청 2
> 2-1 하다가 아래 오류 났어

반영: 출시 빌드에서만 도는 lint가 백업 규칙의 `database`와 `sharedpref` 칸 `path="./"`를 하위 폴더로 보고 막았다. 27곳을 같은 뜻인 `.`으로 바꾸고 시험 기대값도 바꿨다. 출시 APK가 출시 키로 서명되는 것을 봤다.

### 수정 요청 3
> adb uninstall com.cherryconsume.app
> adb.exe: no devices/emulators found

반영: PC가 폰을 USB 장치로도 알아보지 못하는 것을 Windows 장치 목록으로 확인하고, 잠금 풀기, 케이블, 포트, 허용 누르기를 안내했다.

### 수정 요청 4
> 다시하니 설치까지 성공했어

반영: 폰에서 SQLite 3.53.4로 PC와 같은 것을 시험으로 보고, 출시 앱을 다시 깔아 자동 백업이 막힌 것을 봤다. 시험용 엑셀을 폰 다운로드 폴더에 넣고 비행기 모드에서 눌러 볼 순서를 줬다.

### 수정 요청 5
> 8번까지 다 됐어

반영: 성공 기준 6을 실제 폰에서 확인하려 기록 파일을 다시 내보내 달라고 했다.

### 수정 요청 6
> 8번하면서 만든 파일이야

반영: 그 파일 A를 PC에 복사해 두고 앱을 지웠다 다시 깔았다.

### 수정 요청 7
> 다 정상적으로 작동했고
> B 저장했어

반영: A와 B를 PC에서 같음과 다름만 출력하게 비교했다. 표 8개가 모두 같고 내보낸 시각만 달랐다. 사본은 지웠다. 의도 성공 기준 8개를 확인해 계획 끝에 적었다.

### 수정 요청 8
> 커밋하고 푸시해

반영: 위 두 커밋과 이 기록을 커밋하고 푸시했다. 진행 문서는 다른 세션의 줄을 빼고 이 세션의 줄만 올렸다.

## 최종 결과

작업 006이 끝났다. 갤럭시 S24+ Android 17에서 비행기 모드로 여덟 기능, 기록 옮기기, 백업 막힘을 확인했고 의도 성공 기준 8개가 모두 맞다. 남은 것은 실제 카드사 엑셀 두 번 올리기와 사용자가 할 7.6이다.
