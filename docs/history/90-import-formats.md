# 90 작업 015 엑셀 가져오기를 카드사별 파일 형식 표로 읽기

- 날짜: 2026-10-05
- 결과물: [작업 015](../work/015-import-formats/), [설계 문서 8절](../2026-09-19-cherryconsume-design.md), [시나리오 E30, E33, E59, E60, E61](../scenarios.md), [형식 표](../../app/lib/store/formats.dart)
- 커밋: `077a099` 의도와 설계와 계획, `7c9a9e9` 기업은행 출력용, `2467310` 신한카드와 뱅크샐러드, `e5d9d59` 실제 금액을 적지 않는 규칙. 문서 커밋은 `ad498ef`, `6448f0c`와 이 기록

## 요청

> 미리보기가 결제 42건, 원 결제 없는 취소 4건, 카드 할인 8건
> 이라는 문구 자체가 안 보이는데

폰 화면을 찍어 보니 저장 예정 건수와 합계는 맞고, 취소와 할인 12건이 읽지 못한 행이었다. 폰에 취소 여부를 "없음"으로 고른 짝이 기억돼 있었다. 이 PC의 실제 파일에 같은 짝을 넣어 폰과 같은 숫자를 다시 만들었다.

> 근데 이러면 카드사별로 너무 결과가 다를 것 같은데

같은 IBK 파일이 기억한 짝에 따라 세 가지 결과로 나온 것을 표로 보이고, 카드사 파일 모양마다 읽는 법을 정해 두는 형식 표를 제안했다. 설계 문서 8절에 처음부터 "카드사별 매핑 표"로 적혀 있었지만 만들지 않은 것이었다.

> 그럼 내가 카드사 별로 실제 파일이 있어야 해결가능한거네?

결제 내용 없이 머리 줄과 취소 줄 모양만 있으면 된다고 답했다. 시험자와 가계부 앱 내보내기라는 두 길과, 파일 없이 지금 할 안전장치 셋을 제안했다.

> 그렇게 하고
> 사람들이 자주쓰는 토스나 우리가 갤럭시에 우선 출시하니 삼성 월렛에서 데이터를 가져올 방법이 없을까

찾아보니 토스는 토스뱅크카드 한 장의 이용내역확인서만 엑셀로 받고, 삼성 월렛은 내역을 보기만 하고 내보내지 않는다. 다른 앱이 읽어 가는 공개 통로도 찾지 못했다. 대신 뱅크샐러드 가계부의 "파일로 받기"가 여러 카드를 한 파일에 담는다는 것을 찾았다.

> 그럼 다른 카드사의 엑셀 양식을 알 방법이 없나

카드사는 양식을 공개하지 않는다. 공개 저장소 둘에서 신한카드와 우리카드 파일 모양의 단서를 찾았지만, 다른 사람이 어느 때 받은 파일이라 열 이름 후보로만 쓰기로 했다.

> 일단 우리카드나 신한카드는 나도 있긴 해

> 우리카드는 이메일 오는데 1시간 정도 걸려서 일단 뱅크샐러드로 엑셀 1년치 다운받았고, 신한카드 받았어

두 파일을 폰에서 저장소에 올라가지 않는 `app/test/local/`로 가져왔다. 값은 보지 않고 머리 줄, 값 종류, 건수만 봤다. 뱅크샐러드는 카드 다섯 장의 1년치를 담고 결제를 음수로 적는다. 지금 코드는 음수를 취소로 읽어 결제가 모두 취소가 될 뻔했다. IBK 결제는 모두 뱅크샐러드에서 같은 날, 같은 금액, 같은 이름으로 찾아져 겹침 규칙이 통한다는 것도 봤다.

## 과정

### 의도와 설계
의도 성공 기준 10개와 설계 6절을 사용자가 확정했다.
- 형식 표는 카탈로그가 아니라 앱 코드에 둔다
- 열은 번호가 아니라 이름으로 짝짓는다
- 실제 파일에서 본 값만 적고, 본 적 없는 값이 든 줄은 넣지 않는다
- 아는 형식은 기억한 짝을 쓰지 않는다. 3절을 쓰다 형식 규칙과 손으로 고른 짝이 엇갈리는 것을 보고, 짝짓기 단추를 없애는 안으로 바꿔 사용자가 골랐다
- 뱅크샐러드에는 할부 열이 없다. 사용자가 신용카드 결제를 빼는 안 대신 일시불로 넣고 알리는 안을 골랐다

### 구현
1. 형식 표와 기업은행 출력용. 이 PC의 실제 파일이 세 칸만 기억된 짝이 있어도 결제 42건, 원 결제 없는 취소 4건, 카드 할인 8건으로 나온다
2. 미리보기에 읽은 형식, 모르는 형식 안내, 자동으로 찾은 짝과 다른 칸 알림을 붙였다
3. 신한카드 이용내역. 맨 아래 "총 25건" 합계 줄을 건너뛰게 했다. 취소가 든 파일을 아직 보지 못해 취소상태에 값이 든 줄은 넣지 않는다
4. 뱅크샐러드. 부호를 반대로 읽고 결제수단 칸의 카드 이름으로 줄을 나눈다
5. 실제 IBK 파일과 뱅크샐러드 파일을 두 순서로 넣어도 결과가 같았다

### 위험 검토
- 단계 1, 2: 높음과 중간 없음, 낮음 7. 괄호 붙은 비슷한 열 이름, 화면이 보낸 짝, 늘 0이던 칸을 고쳤다
- 단계 3~5: 중간 2, 낮음 9
  - 중간 1: 뱅크샐러드 카드 이름을 이름 일부로 맞춰 다른 카드사의 나라사랑카드가 IBK로 들어갈 수 있었다. 공식 이름이 같은 카드에만 붙인다
  - 중간 2: 카드 여러 장의 줄이 섞인 카드사 파일이 모두 고른 카드로 들어갈 수 있었다. 카드 칸 값이 둘 이상이면 넣지 않는다
  - 낮음 10: 작업 문서에 실제 결제 금액이 적혀 있었다. 문서에서 지웠다

### 수정 요청
> 폰 연결했어 커밋메세지는 그대로 두는데 다음엔 적지않도록 조심해

앞서 올린 커밋 메시지 하나에 실제 합계의 차액이 적혀 있었다. 사용자가 그대로 두기로 했다. 실제 파일에서 본 금액, 합계, 차액을 저장소에 적지 않는 규칙을 프로젝트 지침에 더했다. 출시 판을 폰에 기록을 지우지 않고 깔았다.

## 최종 결과

> 다 잘 됐어

- 폰에서 기업은행 출력용과 뱅크샐러드 파일이 형식 이름과 함께 맞게 읽혔다
- 앱 시험 852개 통과. 성공 기준 10개 가운데 우리카드가 남은 2와 우리카드로 확정할 8을 뺀 여덟이 맞다. 결과는 계획 끝의 성공 기준 확인이다
- 남은 것: 우리카드 형식은 메일로 오는 파일을 받으면 넣는다. 확인 필요로 남긴 것은 신한카드 취소상태 값, 뱅크샐러드의 짝 없는 양수 줄과 해외 결제, 두 파일의 부분 취소 날짜가 다를 때다. IBK 신용카드, 해외, 할부 줄은 막히니 시험자에게 알린다
