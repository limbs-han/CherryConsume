# 008 카탈로그 전체로 넓히기

작업 003과 007의 뒤를 잇는다. 2026-10-03 사용자가 "지금 파는 카드 전부를, 막힌 카드사를 포함해서" 담기로 했다. 2026-10-03 사용자가 의도를 확인했다.

## 왜

- 카탈로그에 카드 20장뿐이다. 수집기도 그 20장의 주소와 카드사 목록만 받는다. 앱에 없는 카드는 등록할 수 없다. 시나리오 E22.
- 설계 문서는 "스키마가 계산에 맞는지 20장으로 먼저 증명하고 그다음 넓힌다"고 적었고, 작업 002와 003으로 증명은 끝났다. 넓히는 방법은 아직 정하지 않았다.
- 2026-10-03 확인 결과, 모든 카드를 한곳에서 주는 공식 출처는 없다. 여신금융협회 카드다모아는 카드사마다 추천 카드 3장씩만 보여 주고, 비교공시는 수수료율과 금리뿐이다. 그래서 카드사마다 있는 상품공시실에서 전체 색인을 만들어야 한다.
- 카드사마다 막힌 까닭이 다르다. 삼성과 IBK는 robots.txt가 자동 수집을 막는다. 롯데는 봇 이름, 브라우저 이름, 브라우저 TLS 지문을 흉내 내도 연결이 끊긴다. 신한은 데이터센터 주소만 끊고 PC에서는 열린다.

## 성공 기준

- 카드사 상품공시실에서 지금 파는 카드와 최근 3년 안에 단종된 카드의 이름, 상태, 단종일, 상품 페이지 주소, 상품설명서 PDF 주소를 모은 색인 표가 Databricks에 있고, 수집이 그 색인을 따라 돈다.
- 수집이 집 PC의 GitHub 자체 호스팅 러너에서 돌아 신한 원문이 사람 손 없이 들어온다.
- 카드다모아의 카드사별 추천 카드 46장과 Google 설문으로 들어온 요청 카드가 먼저 검수되고, 나머지는 초안으로 쌓인다. 앱은 승인된 카드만 보인다.
- 삼성, 롯데, IBK의 지금 파는 카드가 들어온다. 삼성과 IBK는 자기 이름을 밝힌 수집기로, 롯데는 집 PC 러너의 Playwright 브라우저로 받고, 그것도 끊기면 사람이 저장해 도우미로 넣는다.
- 카탈로그에 없는 카드의 상품설명서에서 새 카드 파일 초안을 만들고 검수 앱에서 승인할 수 있다.
- 혜택을 이미지로 넣은 페이지에서도 혜택이 추출된다. 이미지만 있는 페이지의 정답 예시에서 혜택 key가 하나 이상 나온다.
- 파이프라인 테스트가 모두 통과하고, 운영 배포 뒤 첫 `cherry_refresh`가 성공한다.
- 새 카드 추출의 모델 비용이 카드당 몇 센트 안쪽이다. 사람이 검수하는 시간이 가장 큰 비용임을 계획에 적는다.

## 하지 않을 것

- 봇 표시를 숨기는 도구, 접속 주소를 바꾸는 유료 프록시, 다른 봇 이름으로 속이기를 쓰지 않는다. robots.txt가 막은 삼성과 IBK도 자기 이름을 밝힌 수집기로 천천히 받는다. 2026-10-03 사용자가 정했다.
- 카드 비교 사이트의 비공개 API와 데이터를 색인이나 값의 근거로 쓰지 않는다. 프로젝트 규칙이다.
- 추출 정확도 올리기 자체는 이 작업이 아니다. 다만 새 카드 초안 모드의 점수는 잰다.
- 앱 화면의 카드 요청 버튼은 이 작업이 아니다. 요청은 Google 설문으로 받고, 버튼은 주 개발 세션의 앱 작업에서 단다.
- 3년 넘게 전에 단종된 카드와, 단종일이 없는 카드사의 이미 단종된 카드는 넣지 않는다. 사용자 요청이 오면 그때 넣는다. 뒤쪽은 2026-10-05 바뀌었다. 정한 것 마지막 줄.

## 정한 것

- 2026-10-03 사용자가 지금 파는 카드 전부를 막힌 카드사까지 담기로 했다.
- 2026-10-03 사용자가 여신금융협회 포털 확인을 먼저 하기로 했고, 확인 결과 전체 목록 출처가 아니었다.
- 2026-10-03 사용자가 robots.txt로 막은 삼성과 IBK를 자동으로 받기로 했다. Claude는 약관 위반과 접속 차단, 출시 뒤 분쟁 소지를 알렸고 권하지 않았다. 수집기는 지금처럼 `cherryconsume-collector` 이름을 밝히고 주소마다 2초 쉬며, 429나 403 같은 차단 신호가 오면 그 카드사를 그 실행에서 멈춘다. 봇 표시를 숨기는 도구는 쓰지 않는다. 카드사가 요청하면 즉시 중단한다.
- 2026-10-03 사용자가 넷을 정했다. 단종 카드는 최근 3년 안에 단종된 것만 넣는다. 공시실에 단종일이 있어야 한다. 수집은 집 PC에 GitHub 자체 호스팅 러너를 두고 지금 워크플로를 그대로 돌린다. 수집 날 새벽에 PC가 켜져 있어야 한다. 카드 요청은 Google 설문으로 받고 답은 스프레드시트에 쌓인다. 검수는 카드다모아의 카드사별 추천 46장과 요청 카드를 먼저 하고 나머지는 초안으로 쌓아 둔다.
- 2026-10-03 사용자가 롯데 상품 페이지가 브라우저에서 열리는 것을 확인했다. 봇 이름, 브라우저 이름, 브라우저 TLS 지문 흉내는 모두 연결이 끊겼으므로 진짜 브라우저가 아닌 접속을 막는 것이다. 집 PC 러너의 Playwright로 먼저 시험하고, 끊기면 사람이 저장하는 길로 한다.
- 2026-10-03 1단계 조사 뒤 사용자가 둘을 정했다. 카카오뱅크도 삼성, IBK와 같이 robots.txt를 무시하고 이름을 밝혀 받는다. 단종일이 없는 카드사 일곱 곳은 지금 파는 카드만 넣고, 수집을 시작한 뒤 사라진 카드부터 그 날을 추정 단종일로 삼아 3년을 다룬다. 이미 단종된 카드는 사용자 요청이 오면 넣는다. 단종일이 있는 KB, 현대, 우리는 최근 3년 단종을 그대로 넣는다.
- 2026-10-05 사용자가 공시실에 단종일 없이 단종으로 나오는 카드도 일단 수집하기로 했다. 수집 코드가 처음부터 그렇게 받고 있었고, 작업 013에서 이 문서와 다른 것이 드러났다. 운영 색인에 롯데 244장, IBK 13장이다. 새 카드 초안 고르기도 같은 기준이라 이 카드들의 초안도 만든다.
