# 카드 수 확대 작업 이어받기

다음은 일반 초안 중 조건이 단순한 개인 카드를 추가로 조사해 승인 후보를 늘리는 일이다. 현재 승인 후보 30장은 보존한다. 사용자는 2026-10-10 더 많은 카드를 준비하도록 작업을 넘기고 문서 갱신과 커밋을 요청했다. 운영 반영은 승인하지 않았다.

## 지금 완료한 것

| 대상 | 수 | 한 줄 설명 |
|---|---:|---|
| 앱 원본 카드 | 21 | 저장소와 운영에 이미 있는 카드다 |
| 최신 열린 초안 | 2,421 | 일반 2,162장과 사람 판단 필요 259장이다 |
| 일반 초안 구조 검사 | 2,162 | 전부 확인했지만 공식 조건의 정확함을 보장하지 않는다 |
| 오류 없이 계산 혜택이 있는 일반 초안 | 1,034 | 원문 대조 전 후보 수다. 즉시 승인 가능한 수가 아니다 |
| 이번 승인 후보 | 30 | 첫 9장에 하나 8장, 추천 혼합 4장, 추천 기타 9장을 추가했다 |
| 추가 조사한 카드 | 35 | 21장은 후보에 추가했고 14장은 후속으로 남겼다 |
| 최종 계산 사례 | 700 | 새 카드 391개, 기존 카드 281개, 교육비 제외 28개다. 모두 통과했다 |

운영 반영 뒤 총 51장이다. 승인 파일 47개는 새 카드 30개와 공통 및 기존 분류 연결 17개다. 카탈로그 오류와 경고 0개, 실제 승인 함수와 중복 상품 검사 통과다. 마지막 파일 47개의 지문도 일치했다. 운영 쓰기, 원본 `catalog/`와 앱 카탈로그 수정, 직접 푸시는 하지 않았다.

최종 통합 결과의 상태는 원문 대조 전 2,135장, 승인 후보 30장, 추가 조사 또는 계산 기능 보완 236장, 개인 카드 대상 제외 제안 20장이다. `blocked`는 사용자가 직접 판단할 카드라는 뜻이 아니다. AI가 원문을 확보하거나 계산 기능을 보완할 대상이다.

## 카드 수를 늘릴 순서

1. 현재 모델로 정확히 표현할 수 있는 일반 초안부터 고른다. 로컬 `tmp/release-card-expansion/triage-results.json`과 `simple-candidates.json`에 구조 검사와 후보가 있다. 한 혜택 카드도 핵심 혜택 누락, 회사 직원 전용, 기존 상품 중복이 있으므로 원문 대조 없이 승인하지 않는다.
2. 일반 초안 2,162장 가운데 카드사와 상품이 다른 개인 신용·체크 카드를 나눠 조사한다. 연회비, 판매 상태, 실적 제외, 신규 특례, 최소 금액, 대상 결제수단, 한도와 횟수를 공식 페이지와 설명서로 확인한다.
3. 임시 카탈로그 사본에 카드와 손계산을 작성한다. 작성자와 다른 검토자가 공식 원문을 다시 확인한다. 실제 Dart 엔진으로 각 혜택의 양수 계산과 실적 경계 및 제외 사례를 검증한다.
4. 승인 후보에 합친 뒤 기존 계산과 공통 분류 영향을 다시 확인한다. 최종 승인 파일 목록과 지문, 초안 번호, 중복 검사를 갱신한다.
5. 새 기능을 추가할 때는 `rule-change`를 적용한다. 설계와 손계산부터 정하고 현재 후보가 깨지지 않게 한다. 운영 반영은 사용자에게 최종 목록을 보여 승인받은 뒤 한다.

## 지켜야 할 계산 결정

- `Fact.scope`는 `user`와 `card`만 있다. `txn`은 없다. 카드 답은 날짜 이전의 최신 값을 쓰며 자동 만료하지 않는다. 월마다 변하는 상태를 영구 답으로 대신하지 않는다.
- 결제 입력으로 구별할 수 있는 필수 조건을 현재 모델이 표현하지 못하면 보류한다. 안내 문장만 붙여 승인하지 않는다. 매출표 접수 순서나 입점 여부처럼 입력으로 알 수 없는 조건은 원문 근거와 안내를 보존한다.
- 하나 현대렌탈서비스와 대명아임레디는 최초 등록 다음달까지 최소 구간 한도만 적용한다. 높은 실적과 신규 특례의 최댓값을 선택하면 틀린다. 토스뱅크 Wide도 첫달 규칙을 별도 혜택으로 처리했다.
- 생애 최초 발급과 탈회 후 재발급의 차이는 정적 카드 답과 등록월 조건으로 처리한다. 삼성 국민행복 체크 V2와 우리 일부 카드 사례를 참고한다.
- `education.school_fee`는 유치원과 초중고를 포함한다. 새 `education.primary_secondary_fee`와 `education.kindergarten`을 기존 12카드와 현대 공통 제외에 연결했다. 연결을 빼면 기존 카드가 새 분류에서 잘못 적립한다. 기존 14카드의 두 업종 28개 시험을 유지한다.
- JADE Classic의 거래별 하나머니 적립과 현대 X의 거래별 1% 할인은 계산한다. 바우처·라운지와 현대 X의 연간 추가 캐시백은 자동 계산하지 않는 범위를 승인 목록에 공개했다.
- 미미 09:00 정각은 원문이 불명확해 09:00 미만으로 계산한다. zgm 일부 페이 제외 이름도 확인 안내로 남겼다.

## 로컬 자료와 다른 PC에서 복원

현재 PC의 `tmp/release-card-expansion/`에 일반 초안 조회 응답 두 조각, 전체 검사 결과, 색인, 추천 카드 공식 원문, 작성 사본과 도구가 있다. `tmp/card-ready-review/`는 첫 9장, `tmp/card-human-review/`는 첫 259장 검토 자료다. 인증 정보와 전체 공식 원문은 커밋하지 않는다. 같은 PC에서는 이 자료를 다시 가져올 필요 없다.

공개 저장소에는 최종 승인 사본, 보류 14장의 수정 사본과 사례, 결과, 공식 URL·원문 경로·문서 지문을 보존했다. 다른 PC에서는 Databricks 로그인 뒤 결과의 초안 번호와 원문 경로로 최신 자료를 읽기 조회한다. 조회는 `cherry.silver.drafts`의 최신 `new_card` 초안과 열린 `cherry.silver.queue`를 연결한다. 일반 초안 응답은 1,226행과 936행 두 조각이었다. 잘림 없이 전체 조각을 받아야 한다. 토큰이나 로그인 설정을 문서에 넣지 않는다.

`prepare.py`와 카드 작성용 초기 스크립트를 다시 실행하지 않는다. 후속 독립 검토 수정이 덮어써진다. `assemble.py`, `package.py`, `triage.py` 사본은 `release-2026-10-10/tools`에 보존했다. 원래 `tmp/release-card-expansion` 경로를 기준으로 만들어진 도구이므로 그대로 문서 폴더에서 실행하지 않는다. 기존 로컬 사본을 사용할 때도 준비 입력 파일을 확인한다.

최종 승인 사본을 검증할 때는 저장소 루트에서 아래처럼 복원한다. 운영에는 쓰지 않는다.

```powershell
uv run --project backend python docs/work/008-catalog-all-cards/release-2026-10-10/tools/verify_snapshot.py
Copy-Item docs/work/008-catalog-all-cards/release-2026-10-10/tools/check_engine.dart tmp/release-card-expansion/check_engine.dart
dart --packages=app/.dart_tool/package_config.json tmp/release-card-expansion/check_engine.dart tmp/release-card-expansion/handoff/catalog.json docs/work/008-catalog-all-cards/release-2026-10-10/cases
dart --packages=app/.dart_tool/package_config.json tmp/release-card-expansion/check_engine.dart tmp/release-card-expansion/handoff/catalog.json app/test/engine/cases
dart --packages=app/.dart_tool/package_config.json tmp/release-card-expansion/check_engine.dart tmp/release-card-expansion/handoff/catalog.json docs/work/008-catalog-all-cards/release-2026-10-10/school-cases skip-benefit-coverage
```

승인 전 현재 골드 값과 초안 번호, 끊긴 승인, 신규 상품 중복을 다시 확인한다. 실제 승인 작업은 `cherry_approve`, 작업 번호는 승인 파일 목록에 있다. 공통 및 기존 분류 연결 17개를 먼저 반영하고 봇 내보내기를 확인한 뒤 새 카드별 초안 번호로 승인한다. 첫 9장을 포함해 모두 아직 운영에 들어가지 않았다. 사용자의 이번 커밋 요청은 운영 승인이나 푸시 승인으로 해석하지 않는다.
