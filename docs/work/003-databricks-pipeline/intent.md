# 003 Databricks 파이프라인

작업 002는 계산 엔진으로 예약되어 있어 이 작업은 003이다. 설계 문서 5절의 하위 프로젝트 3이다. 방식은 2026-09-29 사용자가 정했다. 설계는 `design.md`에서 절마다 확인받는다.

## 왜

- 카탈로그는 한 번 모으고 끝나지 않는다. 카드사마다 14일이나 30일마다 원문을 다시 봐야 한다. 지금은 사람이 에이전트를 띄워 카드를 하나씩 조사하는데, 카드가 늘면 무엇이 바뀌었는지 찾는 일과 바뀐 혜택을 읽는 일을 자동으로 해야 한다.
- 사용자 로그로 추천을 실제로 따르는지, 실적 경고 뒤 결제가 느는지 본다. 설계 4.1절이다.
- 개발자가 Databricks를 배운다. 고른 이유는 `docs/databricks.md`에 있다.

## 정한 방식

**현업식 A.** 원문 적재부터 카탈로그까지 모든 층을 Databricks 안에 둔다. 레이크하우스의 취지에 가장 맞는 방식이다.
- LLM이 혜택 초안을 만들고, 코드가 검사하고, 사람이 승인한다. 처음에는 모든 초안을 사람이 승인한다.
- 작업 001에서 사람이 확인한 카드 20장을 정답 예시로 삼아 추출 정확도를 잰다. 기록이 쌓이고 카드가 늘면 자동 승인할 칸을 다시 정한다.
- 원문에서 카탈로그 한 줄까지의 계보를 Unity Catalog로 남긴다. 계보는 결과가 어느 원문의 어느 문장에서 나왔는지 따라갈 수 있는 기록이다.

검토한 다른 방식은 다음과 같다.

| 방식 | 한 줄 설명 | 고르지 않은 이유 |
|---|---|---|
| B | 변경 감지만 Databricks, 혜택 읽기는 지금처럼 에이전트와 사람 | 가장 중요한 변환이 Databricks 밖에서 일어나 계보가 끊긴다 |
| B+ | B에 숫자만 바뀐 경우를 일반 코드로 초안 만들기를 더한 것 | 같은 이유. 숫자 초안은 A 안의 한 단계로 쓸 수 있다 |
| C | Databricks는 사용 기록 분석에만 | 레이크하우스를 분석 창고로만 쓴다 |

## 확인된 제약

- 처음부터 유료 계정으로 한다. 무료판은 상업 이용이 금지이고 유료로 바꿀 수 없어 쓰지 않는다. design.md 4절 9번.
- 결제해도 Databricks 서버리스에는 브라우저를 설치할 수 없다. 원문은 바깥에서 받아 Databricks에 올린다.
- 삼성, BC, IBK는 robots.txt로 자동 수집을 막는다. 이 카드사들은 사람이 공식 페이지를 보고 올리는 수동 방식이다. NH는 보안 프로그램 설치 화면이 뜨고, 롯데, 하나, 우리, 현대는 브라우저로만 혜택 상세가 열린다. 작업 001 과제 12 에이전트 보고.
- 한 달 비용은 30달러에서 멈추게 한다. design.md 4절 8번.
- 계정, 작업 공간, CLI, 토큰, 결제 설정은 사용자가 직접 한다. `docs/databricks.md`.
- 로그 분석은 서버가 생긴 뒤에야 로그가 있다. 하위 프로젝트 2 다음이다.

## 성공 기준

설계 문서 5절의 완료 기준을 구체적으로 바꾼 것이다. 설계에서 수치를 다듬는다.

- 카드 20장의 원문이 주기마다 브론즈에 쌓이고, 바뀐 문서만 추출 단계로 넘어간다.
- 원문이 같은 주기에는 카탈로그 차이가 0이다.
- 카드사 3곳 이상에서 새로 나온 카드와 목록에서 사라진 카드가 검수 대기에 뜬다.
- LLM 추출 결과를 정답 예시 20장으로 채점한 필드별 정확도가 MLflow에 남는다. 프롬프트나 모델을 바꿀 때마다 다시 잰다.
- 검사에 걸린 초안도 걸린 이유와 함께 검수 대기에 오르고, `cherry_core` 검증을 통과해야 승인된다. 사람 승인 없이 골드로 가는 초안은 없다.
- 골드의 카드 개정 한 줄에서 원문 파일까지 Unity Catalog 계보로 따라갈 수 있다.
- 하루치 사용자 로그가 다음 날 실버 테이블에서 조회된다. 하위 프로젝트 2 뒤에 확인한다.
- 사용자가 직접 하는 설정 단계마다, 무엇이 보이면 성공인지 안내 문서에 적혀 있다.

## 하지 않을 것

- 카드사 사이트에 로그인해 가져오는 자동화, robots.txt가 막은 사이트의 자동 수집
- 사람 승인 없이 초안을 골드에 올리기. 자동 승인은 정확도 기록이 쌓인 뒤 다시 정한다
- 앱 DB를 Lakebase로 옮기기. 설계 4.2절의 2단계 조건이 되면 따로 한다
