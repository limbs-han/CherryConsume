# 004 화면 시안 검토 반영

2026-09-30 화면 시안을 UI 결함과 UX 법칙 다섯 가지로 검토했다. 힉스의 법칙, 피츠의 법칙, 제이콥의 법칙, 근접성의 법칙, 폰 레스토프 효과다. 사용자가 작업 003보다 먼저 시안을 고치기로 했다.

## 왜

- 작업 002 엔진은 모르는 값을 사용자에게 묻고, 조건부 혜택과 횟수 한도와 순위 잠정값을 돌려준다. 시안에는 이것을 보여 주거나 답하는 화면이 없다. 이대로 하위 프로젝트 2에서 앱을 만들면 엔진이 준 값을 버리게 된다.
- 상태 모음 화면의 문구 두 곳이 지금 엔진과 다르다. 시안을 보고 앱을 만들면 틀린 경고를 띄운다.
- 색 하나가 여러 뜻을 맡고, 누를 곳이 작고, 익숙하지 않은 동작이 숨어 있다. 체리피커는 계산대 앞에서 몇 초 안에 카드를 골라야 한다.

## 성공 기준

1. 엔진이 묻는 값을 답하는 곳이 있다. 결제수단, 카드별 사실과 옵션, 쓰기 시작한 날, 자식 업종이다. 시나리오의 화면 번호로 어느 화면인지 적는다
2. 추천 결과에 조건부 혜택이 보인다. 예: 네이버페이로 결제하면 +1,000원
3. 횟수 한도와 순위 잠정값이 보인다. 횟수 한도는 카드 상세에 보이고, 추천 결과에서는 한도 때문에 혜택이 줄었을 때만 이유로 보인다. 2026-09-30 사용자가 추천 결과를 핵심만으로 줄이며 바꿨다
4. 상태 모음에 1판 문구가 없다. 주말·시간대를 계산하지 않는다는 문장이 없고, 실적 계산 미지원 예시는 카탈로그에서 실제로 미지원인 경우다
5. 2026-09-30 검토의 법칙별 "어긴 곳"과 "그 밖에 거슬리는 곳"이 모두 고쳐졌거나, 고치지 않은 까닭이 plan.md에 있다
6. 모든 글자의 바탕 대비가 4.5:1 이상이다. 큰 글자는 3:1 이상이다. 시안 HTML의 글자색과 바탕색 짝을 스크립트로 계산해 확인한다
7. 누르는 것은 모두 높이 44px 이상이다. 시안 HTML의 크기로 확인한다
8. 혜택 금액 색이 한 가지다. 빨강은 되돌릴 수 없는 동작에만 쓴다
9. 모든 화면을 390×844로 찍어 넘치거나 잘린 곳이 없다
10. 화면 시안 숫자 테스트 `backend/tests/engine/test_mockup.py`가 그대로 통과한다. 시안에 새로 넣은 숫자는 시안 카드 규칙으로 계산해 맞는다
11. 시안 PDF는 한 쪽에 화면 하나다. 설계 문서, 시나리오, README의 화면 번호와 이름이 시안과 같다
12. 캔버스, 저장소 HTML, PDF가 같은 화면을 담는다. 캔버스를 먼저 고치고 저장소 파일은 캔버스에서 다시 만든다
13. 둥근 모서리와 안쪽 여백은 설계에서 정한 몇 가지 값만 쓴다. 지금은 모서리 값이 19가지이고 카드만 16, 18, 20, 24px이 섞여 있다. 시안 HTML에서 값을 모아 확인한다
14. 두 줄 글자가 든 줄과 카드는 위아래 여백이 있다. 지금 결제 기록의 "자동으로 채웠어요"와 추천 첫 화면의 업종별 1순위 줄은 두 줄을 높이 52px에 넣어 답답하다. 2026-09-30 사용자가 짚었다

## 하지 않을 것

- 실제 카드 20장 값으로 시안을 다시 그리는 일. 2026-09-29 정한 대로 하위 프로젝트 2에서 한다
- 결제 알림 읽기 화면. 출시 뒤 부가 기능이다
- 앱 코드
