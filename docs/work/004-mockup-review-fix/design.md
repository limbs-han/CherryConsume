# 004 화면 시안 검토 반영 설계

의도는 `intent.md`다. 2026-09-30 사용자가 설계를 한 번에 보고 바로 고치기로 했다.

## 1절 원본과 만드는 순서

- 원본은 캔버스의 화면 파일 14개와 배치 파일이다. 화면마다 파일이 하나다
- 화면 파일은 작업 폴더의 생성 스크립트가 아래 2절의 값으로 만든다. 모서리와 여백이 한 곳에서 정해져 화면마다 달라지지 않게 하려는 것이다
- 캔버스에 올린 뒤 같은 화면 파일로 저장소의 `design/체리컨슘-화면-시안.html`과 PDF를 다시 만든다. PDF는 Chrome으로 화면마다 한 쪽씩 인쇄한다
- 생성 스크립트와 검사 스크립트는 작업 폴더 밖 임시 폴더에 둔다. 2026-09-28 화면 시안 원본과 생성 스크립트를 저장소에 두지 않기로 한 것을 따른다

## 2절 공통 값

### 2.1 색

| 이름 | 값 | 쓰는 곳 |
|---|---|---|
| 바탕 | #F2F4F7 | 화면 바탕 |
| 상자 | #FFFFFF | 카드, 목록, 입력칸 |
| 선 | #E1E5EC | 구분선, 보조 버튼 테두리 |
| 글자 | #191F28 | 본문 |
| 보조 글자 | #4E5968 | 설명, 절 이름. 바탕과 상자 어디서나 4.5:1을 넘는다 |
| 흐린 글자 | #6B7684 | 흰 상자 안에서만 쓴다. 회색 바탕 위에서는 4.19:1이라 쓰지 않는다 |
| 파랑 | #3457B2 | 주 버튼, 링크, 선택, 추천 1위 테두리, 사용자가 답할 것 |
| 초록 | #2F7A4F | 혜택 금액. 앱 전체에서 아낀 돈은 이 색 하나다. "1,000원 아낌"처럼 적고 빼기 표시를 쓰지 않는다 |
| 호박색 | #B45309, 바탕 #FFF4E5 | 기회에만 쓴다. 구간이 모자라 아직 못 받는 혜택, 결제수단을 바꾸면 더 받는 혜택 |
| 알림 회색 | 바탕 #EEF0F3, 글자 #4E5968 | 알려 주기만 하는 것. 실적 제외, 조건 확인, 달 끝에 확정, 실적 계산 미지원. 실적에 들어가는 결제는 당연해서 "실적 인정"을 적지 않고 빠지는 결제만 "실적 제외"로 적는다. 2026-09-30 사용자가 정했다 |
| 빨강 | #B23B3B | 되돌릴 수 없는 동작에만 쓴다. 탈퇴 |

사용자가 답할 것은 파랑 테두리 칩으로 묻는다. 업종 미정, 휴대폰 요금인지 같은 질문이다. 호박색은 기회, 회색은 알림, 파랑은 할 일로 뜻을 하나씩만 맡긴다.

### 2.2 모서리

| 값 | 쓰는 곳 |
|---|---|
| 20px | 카드, 목록 상자, 아래에서 올라오는 시트의 위쪽 모서리 |
| 16px | 버튼, 입력칸, 카드 안의 작은 상자 |
| 8px | 배지, 카드 그림 |
| 완전히 둥글게 | 칩, 원형 아이콘, 결제 기록 버튼, 진행 막대 |

이 네 가지 밖의 값은 쓰지 않는다. 휴대폰 틀처럼 화면 밖 장식은 세지 않는다.

## 3절 화면

화면 번호는 지금과 같다. 새 화면은 만들지 않고 모르는 값을 묻는 곳은 있던 화면 안에 넣는다.

| 번호 | 화면 | 바꾸는 것 |
|---|---|---|
| 0 | 시작 | 이용약관과 개인정보처리방침을 밑줄 링크로 |
| 1a | 홈 첫 시작 | 2절 값을 맞추고 "등록하면 이런 걸 알려 드립니다" 카드를 뺀다. 이 화면에서 할 일은 카드 등록 하나다 |
| 1 | 홈 | 오른쪽 아래 버튼에 "결제 기록" 글자를 붙인다. 현대 ZERO의 빈 원을 "상시" 표시로 바꾼다. 카드 줄에는 이름, 할 일, 구간만 둔다. 할인 잔여와 아낀 돈 아래 결제 건수·합계, "1장 더 채우면 돼요"를 뺀다. 한도는 카드 상세에, 건수와 합계는 기록에 있다 |
| 2 | 카드 추가 | 카드사 칩 한 줄만 두고 신용·체크 칩 줄을 뺀다. 등록 시트에 "최근 두 달 안에 새로 받은 카드인가요"를 넣는다. 쓰기 시작한 날이 없으면 신규 발급 특례를 주지 않기 때문이다 |
| 3 | 카메라 인식 | "없으면 이름으로 검색"을 링크 색 버튼으로 |
| 6 | 카드 상세 | 혜택을 통합 한도 아래로 묶는다. 혜택마다 건당, 하루 1회 같은 횟수 한도를 보여 준다. 구간이 모자란 혜택은 따로 묶어 "41.8만 더"처럼 적는다. "카드 정보"에 쓰기 시작한 달을 둔다. 카드 삭제는 점 세 개 메뉴로 옮기고 그 자리에 "이 카드 결제 보기"를 둔다 |
| 4 | 결제 기록 | "자동으로 채웠어요"에 결제수단을 넣고 두 줄로 편다. 가게 칸과 같은 테두리 입력칸 모양이고 값은 보통 굵기다. 무엇·언제 한 줄, 어떻게 한 줄로 나눈다. 예상 혜택은 왼쪽에 이름과 이유 두 줄, 오른쪽에 금액을 세로 가운데로 둔다. 금액에 입력칸 밑줄을 넣는다 |
| 5 | 추천 | 업종별 1순위 줄을 두 줄 높이로 펴고 오른쪽 화살표를 단다. 금액을 "1,000원 아낌"으로 |
| 5b | 추천 결과 | 카드마다 순위, 카드 이름, 아끼는 금액, 이유 한 줄만 둔다. 1위에는 "이 카드로 결제 기록"을 둔다. 3위 IBK에 "네이버페이로 내면 1,000원 아낌"을 한 줄로 넣는다. "조금 더 쓰면", 잔여 한도, 건당·하루 조건은 뺀다. 금액 입력칸을 입력칸 모양으로. 2026-09-30 사용자가 결제 직전에는 핵심만 보여 달라고 했다 |
| 7 | 기록 | 날짜마다 결제를 목록 상자 하나로 묶고 줄을 누르면 수정으로 간다. 길게 누르기 안내를 뺀다. 실적 제외는 회색 배지로. 요약을 "13건 · 74.2만 원"으로. 월 이동 화살표를 44px로 |
| 8 | 엑셀 가져오기 | 파일 형식으로 알아낸 카드를 미리 고른다. 파일을 고른 뒤에는 파일 고르기 칸을 접는다. "이렇게 처리합니다" 설명을 뺀다. 미리보기가 결과로 보여 준다 |
| 8b | 미리보기 | 업종 미정을 맨 위로 올리고 파랑 칩으로 바로 고르게 한다. 안내는 "저장하면 8월 혜택과 9월 구간을 다시 계산해요. 나중에 통째로 되돌릴 수 있어요" 한 문장으로 줄인다. E51 |
| 9 | 설정 | "혜택 계산에 쓰는 답"을 넣는다. 생일 달, 현역병 여부처럼 사람에 대한 사실이다 |
| 10 | 상태 모음 | 1판 문구와 틀린 예시를 빼고 아홉 가지로 다시 짠다. 실적 계산 미지원, 답할 것이 있을 때, 카드마다 다른 답, 가게를 못 찾을 때, 조건 확인, 순위 혜택, 한도 소진, 오프라인, 카드가 없을 때. 실행 중에 둘을 더했다 |

설정과 상태 모음은 스크롤하는 화면이라 세로로 늘린다. 설정 1040px, 상태 모음 2240px이다.

카드가 많아질 때의 방침이다. 시안 카드는 세 장이라 그리지 않고 하위 프로젝트 2에서 그린다.
- 결제 기록과 기록의 카드 칩은 그 가게 1순위 두 장과 "다른 카드"로 줄인다
- 카드 상세의 혜택 목록은 받는 중, 구간이 모자람, 조건 확인 필요로 묶고 접는다

### 3.1 모르는 값을 묻는 곳

| 모르는 값 | 묻는 곳 | 예 |
|---|---|---|
| 결제수단 | 4 결제 기록의 "자동으로 채웠어요". 마지막에 쓴 것이 기본값 | 실물카드 |
| 쓰기 시작한 날 | 2 등록 시트, 6 카드 정보 | 최근 두 달 안에 새로 받은 카드인가요 |
| 카드별 사실과 옵션 | 6 카드 정보. 없는 카드는 줄을 두지 않는다 | 급여이체 여부, 패키지 |
| 사람에 대한 사실 | 9 설정의 혜택 계산에 쓰는 답 | 생일 달, 현역병 여부 |
| 자식 업종 | 결제를 저장한 자리에서 한 번 묻는다. 10 상태 모음에 예를 둔다 | KT 5만 원이 휴대폰 요금인가요 |

### 3.2 시안 카드에 더하는 것

조건부 혜택을 보여 주려고 시안 IBK에 혜택 하나를 더한다. 실제 IBK 나라사랑의 Npay 포인트와 같은 모양이다.

- `npay-10`: 네이버페이로 결제하면 10% 포인트, 건당 1,000P, 20만 구간부터. 통합 한도를 쓰지 않는다
- 스타벅스 1만원을 실물카드로 내면 기본 0.2% 20원이고, 네이버페이로 내면 1,000P라 980원을 더 받는다
- 지금 시안 테스트의 결제에는 결제수단이 없어 기존 숫자는 그대로다. 980원은 새 테스트로 확인한다
