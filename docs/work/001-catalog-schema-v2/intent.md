# 001 카탈로그 틀 2판

## 왜

카드 20장 초안을 1판 틀에 옮겨 보니 혜택 206개 중 147개가 조건을 다 담지 못했다. 비율로 71%다. 문제는 네 가지였다.
- 구간마다 같은 혜택을 복제해야 했다.
- 여러 혜택이 같이 쓰는 한도를 적을 곳이 없었다.
- 기본 적립에 더해지는 혜택과 기본 적립을 대신하는 혜택을 구분할 수 없었다.
- 사용자가 고르는 패키지를 적을 수 없었다.

이대로 계산 엔진을 만들면 추천 금액이 틀린다.

카탈로그는 한 번 모으고 끝나지 않는다. 2주나 한 달마다 다시 모아야 하는데, 1판에는 원문이 바뀌었는지와 바뀐 규칙이 언제부터 적용되는지를 적을 곳이 없다.

## 성공 기준

- 20장이 2판 검증을 통과한다.
- 구조로 담을 수 있는데 문장으로만 남긴 조건이 없다. 문장으로 남는 조건은 결제 입력에 없는 정보가 필요한 것뿐이다. 입점 매장 제외나 지정 품목 같은 것이 해당하고, 카드마다 그 목록을 보고한다.
- 1판의 구간별 복제 혜택이 하나도 남지 않는다. 이름 끝에 `-t1`, `-t2`를 붙여 구간마다 만든 혜택을 말한다.
- 같은 원문으로 갱신을 두 번 돌려도 카탈로그 파일 차이가 없다.
- 카드사 공통 규칙 하나를 바꾸면 그 카드사 카드 전부의 해석 결과에 반영된다.
- 혜택 변경 시행일 전날과 당일의 결제가 서로 다른 개정으로 해석된다.
- IBK 나라사랑카드의 확인 필요 항목 네 가지를 사용자가 확인했거나 확인 필요로 명시했다.

## 하지 않을 것

- 실적과 추천 계산 엔진. 002에서 이 틀을 입력으로 받아 만든다.
- 카드사 페이지 자동 수집 코드. 하위 프로젝트 3에서 만든다. 여기서는 갱신이 가능한 틀까지만 만든다.
- 20장 밖의 카드 추가.
- 앱 화면 변경. 입력 항목을 더하는 결정은 3절에서 하고 화면은 하위 프로젝트 2에서 고친다.
