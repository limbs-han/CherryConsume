# 009 카메라 카드 인식

2026-10-03 중단. 사용자가 "그냥 카메라 기능 빼자 너무 투머치같아"라고 해 카메라 인식을 제품에서 뺐다. 계획 단계 1의 1~6까지 하던 중이었다. 넣었던 패키지, 권한 설정, PC 도구는 지웠고 코드는 커밋하지 않았다. 받은 카드 그림과 후보 모델은 저장소에 올리지 않는 `plates/` 폴더에만 있었다. 이 폴더는 다시 꺼낼 때를 위한 기록이다. 결론은 설계 문서 2절과 5절, 시나리오 S2, E20, E23에 있다

하위 프로젝트 4다. 카드 앞면을 찍으면 폰 안에서 카탈로그의 카드 상품을 찾아 등록 시트를 연다. 시나리오 S2, E20, E23. 2026-10-03 사용자가 시작했고 같은 날 이 의도를 그대로 확인했다.

## 왜

- 카드사와 상품 이름을 검색해 고르는 것보다 카드를 비추는 쪽이 빠르다. 같은 카드사에 이름이 비슷한 카드가 많아 검색으로는 자기 카드를 고르기 어렵다
- 처음 정한 방식 그대로 카드 이름 글자를 읽지 않고 카드 앞면 디자인을 그림으로 비교한다. 2026-09-19 사용자가 정했다

## 이미 정한 것

| 질문 | 답 | 한 줄 설명 |
|---|---|---|
| 알아보는 방식 | 카드 앞면 디자인을 그림 특징으로 비교 | 이름이나 번호 글자를 읽는 방식이 아니다. 2026-09-19 사용자가 정했다 |
| 처리 위치 | 폰 안에서만 | 카드번호가 찍히므로 사진은 폰 밖으로 보내지 않는다. 찍은 화면은 인식 직후 메모리에서 버리고 어디에도 쓰지 않는다. E23 |
| 앱에 넣는 것 | 그림이 아니라 인식용 벡터만 | 카드 그림은 카드사 저작물이다. 벡터는 그림의 특징을 숫자 묶음으로 바꾼 것이라 그림으로 되돌릴 수 없다. 카드사 허락 전까지 앱 화면에 카드 그림을 띄우지 않는다. 설계 문서 3절 |
| 확정 | 늘 사용자가 확정 | 1순위와 후보 둘을 보이고 사용자가 고른다. 1순위가 기준값보다 덜 비슷하면 "확실하지 않음"과 이름 검색을 앞에 둔다. 기준값은 이 작업에서 실측으로 정한다. S2, E20 |
| 기준 그림 | 카드사 상품 페이지의 카드 그림 | 카탈로그 카드의 상품 페이지에서 받는다. 카탈로그가 늘면 함께 는다. 2026-10-03 사용자가 정했다 |
| 시험 사진 | 가진 카드 한 장을 여러 장면으로 | 카탈로그 20장 가운데 실물은 IBK 나라사랑 한 장이다. 2026-10-03 사용자가 정했다 |

## 성공 기준

1. 실물 시험. IBK 나라사랑 실물을 밝은 곳, 어두운 곳, 비스듬히, 손에 든 채, 다른 배경으로 찍은 사진 10장 가운데 9장 이상이 1순위로 맞고, 10장 모두 후보 셋 안에 든다
2. 없는 카드 시험. 카탈로그에 없는 카드나 멤버십 카드 사진 10장 가운데 9장 이상이 "확실하지 않음"으로 나온다. 1의 사진은 모두 기준값을 넘는다. 이 둘로 E20 기준값을 정한다
3. 카탈로그 전체 시험. 카탈로그 카드 그림 전부를 기울이고, 어둡게 하고, 흐리게 하고, 배경 위에 얹어 만든 사진에서 95% 이상이 1순위로 맞는다. PC에서 자동으로 돈다. 실물이 없는 19장이 서로 헷갈리지 않는지 본다
4. 실제 Android 폰에서 찍고 후보가 뜨기까지 1초 안이다
5. 찍은 사진이 파일이나 DB에 남지 않고 폰 밖으로 나가지 않는다. 앱이 인터넷으로 하는 일은 그대로 카탈로그 받기 하나다. 시험으로 확인한다
6. 기준 벡터는 카탈로그와 같은 길로 앱에 들어간다. 카탈로그에 카드를 더하면 그 카드의 벡터도 함께 들어온다
7. 앱 크기는 모델과 벡터로 15MB 안쪽 늘어난다

## 하지 않을 것

- 카드 이름이나 번호 글자 읽기
- 앱 화면에 카드 그림 띄우기
- 사진을 서버나 다른 곳으로 보내기, 찍은 사진 저장
- iOS
- 카드사 그림을 받을 수 없는 카드의 다른 출처 찾기. 수집이 막힌 삼성, IBK, 롯데의 그림은 작업 008의 수집 길을 따르고, 그 전에는 사용자가 상품 페이지에서 손으로 저장한 그림을 쓴다
