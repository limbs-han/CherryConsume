# 009 계획

2026-10-03 중단. 사용자가 "그냥 카메라 기능 빼자 너무 투머치같아"라고 해 카메라 인식을 제품에서 뺐다. 계획 단계 1의 1~6까지 하던 중이었다. 넣었던 패키지, 권한 설정, PC 도구는 지웠고 코드는 커밋하지 않았다. 받은 카드 그림과 후보 모델은 저장소에 올리지 않는 `plates/` 폴더에만 있었다. 이 폴더는 다시 꺼낼 때를 위한 기록이다. 결론은 설계 문서 2절과 5절, 시나리오 S2, E20, E23에 있다

설계는 `design.md`, 의도는 `intent.md`다.

- 단계마다 앱이 돌고 시험이 모두 통과한 채로 끝낸다
- 카메라는 개인정보라 단계 4가 끝나면 `risk-reviewer` 검토 뒤 사용자 확인을 받는다
- 커밋은 사용자가 요청할 때만 한다
- 실물과 없는 카드 사진은 카드번호가 찍힌다. Claude는 사진을 열어 보지 않고 도구가 낸 숫자만 본다. 카드사 그림은 열어 봐도 된다
- 사용자에게 주는 명령은 PowerShell이다
- 걸리는 시간은 단계 1이 2일, 2가 1일, 3이 1일, 4가 2일, 5가 반나절에서 하루다. 사용자가 그림을 저장하고 사진을 찍는 시간은 따로다

  - 결과: 2026-10-03 앱 시험 633개가 통과하고 에뮬레이터에서 앱이 뜬다. 기존 기록도 남았다
    - Dart 소스와 LiteRT 1.4.0의 Java 코드, 네이티브 라이브러리에 네트워크 호출이 없다. 네이티브는 소켓 함수를 부르지 않는다

    - camera 패키지가 마이크와 저장소 쓰기 권한을 넣고, 그 때문에 저장소 읽기가, LiteRT GPU 라이브러리 때문에 전화 상태 읽기가, 동영상 라이브러리 때문에 네트워크 상태 보기가 붙었다. 매니페스트에서 다섯을 빼고 카메라를 필수에서 뺐다. aapt로 보니 남은 권한은 INTERNET과 CAMERA다. 시험 `test/android_permissions_test.dart`

- [ ] 4. 후보 모델 파일
  - MediaPipe 이미지 임베더는 Google이 낸 `.tflite`를 받는다. MobileNetV3-Large와 EfficientNet-B0은 Keras에서 분류층을 빼고 `.tflite`로 바꾼다. 스크립트가 `plates/models/`에 만든다. 고른 모델 하나만 단계 3에서 저장소에 넣는다
  - TensorFlow가 Windows Python 3.13에 없으면 `uv run --python 3.12 --with tensorflow`로 바꾸기만 따로 돌린다
  - 검증: `ai-edge-litert`로 셋 다 열리고, 같은 그림을 두 번 돌리면 같은 벡터가 나온다. 파일 크기를 적는다
  - 결과: 2026-10-03 `backend/tools/plates_models.py`. TensorFlow 2.20을 Python 3.12에 따로 깔아 바꿨다. 넷 모두 열리고 같은 입력에 같은 벡터가 나온다
    - MediaPipe 임베더는 small과 large 둘이 있어 둘 다 잰다. 224×224 RGB를 0~1 값으로 받는다. 모델 파일 안의 설명에 적혀 있다. Keras 모델도 같은 입력을 받게 앞에 255배를 붙였다
    - 크기와 벡터 길이: MediaPipe small 3.9MB 1024, Keras MobileNetV3-Large 5.7MB 960, Keras EfficientNet-B0 7.7MB 1280, MediaPipe large 10.4MB 1280. Keras 둘은 무게를 float16으로 담았다
    - 아무 무늬 두 장의 코사인이 0.96~0.98로 높다. 특징이 모두 양수라 그렇다. 구별이 약하면 기준 벡터 평균을 빼고 비교하는 것을 재 본다
- [ ] 5. 벡터 만들기와 비교
  - 그림을 모델 입력 크기의 정사각형으로 늘려 넓이 평균으로 줄이고, 모델이 바라는 값 범위로 바꾼다. 앱도 똑같이 한다
  - 벡터를 길이 1로 맞춘 뒤 127을 곱해 반올림한 -127~127 정수로 담는다. 코사인 유사도는 길이와 무관해 배율을 따로 담지 않는다
  - 카드마다 벡터가 여럿이면 가장 비슷한 것을 그 카드의 값으로 보고 상위 셋을 고른다. 색 기준선도 같은 함수로 비교한다
  - 검증: 4×4를 2×2로 줄인 값, 정수로 담은 값, 코사인 값을 손계산한 시험
  - 결과: 2026-10-03 `shrink`, `model_input`, `quantize`, `cosine`, `rank`, `color_grid`와 시험 6개. 줄이기는 칸마다 중심이 그 칸에 드는 픽셀의 평균이고, 그런 픽셀이 없으면 칸 중심이 놓인 픽셀이다. PIL은 칸 사이에서 8비트로 반올림해 앱이 똑같이 옮기기 어려워 쓰지 않는다
- [ ] 6. 합성 사진 시험
  - 카드마다 50장을 만든다. 기울기 ±15도, 원근, 밝기 0.4~1.2배, 흐림, 만든 무늬 배경, JPEG 품질 40~90이다. 씨앗을 고정한다
  - 검증: 같은 씨앗이면 같은 사진이 나온다. 후보 넷의 1순위 비율과 후보 셋 안 비율을 표로 낸다
  - 2026-10-03 `photo`와 `synthetic` 명령, 시험 2개를 마쳤다. 바탕은 색 4×3칸을 부드럽게 늘리고 막대를 얹은 무늬다. 만든 무늬 카드로 여섯 장을 눈으로 봤다. 표는 그림이 모이면 낸다
- [ ] 7. 사용자 사진 20장

  - 도구는 앱 안내 틀과 같은 자리를 자른다. 틀은 미리보기 폭의 80%, 카드 비율, 가운데다
