# 009 카메라 카드 인식 설계

2026-10-03 중단. 사용자가 "그냥 카메라 기능 빼자 너무 투머치같아"라고 해 카메라 인식을 제품에서 뺐다. 계획 단계 1의 1~6까지 하던 중이었다. 넣었던 패키지, 권한 설정, PC 도구는 지웠고 코드는 커밋하지 않았다. 받은 카드 그림과 후보 모델은 저장소에 올리지 않는 `plates/` 폴더에만 있었다. 이 폴더는 다시 꺼낼 때를 위한 기록이다. 결론은 설계 문서 2절과 5절, 시나리오 S2, E20, E23에 있다

의도는 같은 폴더의 `intent.md`다. 절마다 사용자 확인을 받고 적는다.

## 1. 기준 그림 받기와 벡터 만들기

2026-10-03 사용자가 "처음은 저장소의 Python 도구 (추천)"를 골랐다.

- 처음 20장은 이 세션이 저장소의 Python 도구로 만든다. 도구는 카드 상품 페이지에서 카드 그림을 받고, 앱과 같은 모델 파일로 벡터를 만들어 벡터만 저장소에 둔다
- 카드 그림은 카드사 저작물이라 공개 저장소에 올리지 않는다. 저장소가 무시하는 폴더에 둔다
- 수집이 막힌 삼성, IBK, 롯데의 그림은 사용자가 상품 페이지에서 손으로 저장해 그 폴더에 넣는다. 작업 008의 수집 길이 생기면 그쪽을 따른다
- 카드가 늘면 작업 008의 수집이 그림을 받고 Databricks 파이프라인이 같은 도구를 불러 벡터를 만들게 옮긴다. 옮기는 일은 이 작업 밖이다. 도구는 그렇게 불릴 수 있게 함수 하나로 둔다
- 벡터는 앱 모델과 짝이다. 모델을 바꾸면 모든 벡터를 다시 만든다

## 2. 모델 고르기

2026-10-03 사용자가 제안한 후보에 ML Kit을 더해 "둘 다 재 보기"를 골랐다.

실행기
- 앱은 `tflite_flutter`다. TensorFlow 팀이 낸 패키지이고 Android GPU 가속과 별도 isolate 실행을 지원한다. 2026-10-03 0.12.1
- PC 도구는 `ai-edge-litert`다. 같은 `.tflite` 파일을 Windows의 Python 3.13에서 돌린다. 2026-10-03 2.2.0
- 앱과 도구가 같은 모델 파일과 같은 전처리를 써야 벡터를 비교할 수 있다. 그림 크기 바꾸기, 색 순서, 값 범위가 같은지 시험으로 본다

PC에서 재는 후보
| 후보 | 한 줄 설명 | 크기 |
|---|---|---|
| MediaPipe 이미지 임베더 | Google이 MobileNetV3를 그림 비교용으로 다듬은 모델 파일. SDK 없이 모델 파일만 쓴다 | 4MB 안팎 |
| MobileNetV3-Large | 사진 분류 모델의 마지막 분류층 앞 특징 | 3~6MB |
| EfficientNet-B0 | 조금 크고 특징이 촘촘한 사진 분류 모델 | 5~10MB |
| 색 기준선 | 모델 없이 카드를 칸으로 나눠 칸마다 색을 비교한다. 모델이 이것보다 나은지 보려는 비교용 | 0 |

- 세 모델은 Apache 2.0이라 상업적으로 쓸 수 있다. Keras나 공개 파일에서 한 번 변환해 모델 파일을 저장소에 둔다
- 성공 기준 1~3의 시험을 같은 사진으로 돌려 표로 비교한다. 1순위 비율, 후보 셋 안 비율, 카탈로그 카드와 없는 카드가 얼마나 갈라지는지, 크기, 속도다. 15MB 안에서 가장 나은 것을 고른다

에뮬레이터에서 재는 ML Kit
- ML Kit에는 그림을 벡터로 바꿔 기준 그림과 비교하는 기능이 없다. 그래서 두 쓰임으로 잰다
  - 자르기: ML Kit 사물 감지로 화면에서 카드만 잘라 PC 후보 중 가장 나은 임베더로 비교한다. 안내 틀로 자르는 것보다 나은지 본다
  - 분류: ML Kit 사물 감지에 카탈로그 20장의 분류 모델을 붙인다. 분류 모델은 카드사 그림을 비틀어 만든 사진으로 학습한다. 카드가 늘면 분류 모델을 다시 만들어야 해서 벡터만 더하는 방식보다 손이 많이 간다
- ML Kit은 진단과 사용 통계로 기기 정보, 앱 이름과 판, 설치 식별자, 처리 속도, 기능 사용 기록을 Google로 보낸다. 사진은 보내지 않는다. 끄는 방법은 문서에 없다. 2026-10-03 Google 문서 확인. 성공 기준 5와 부딪쳐 시험에서만 쓴다. ML Kit이 이기면 성공 기준 5를 바꿀지 사용자에게 다시 묻는다
- ML Kit 재기는 Android 시험 앱과 분류 모델 학습이 더해져 하루쯤 더 든다

기준을 못 넘으면
- 카드사 그림을 비틀어 만든 사진으로 고른 모델을 더 학습시키는 미세 조정을 그때 검토한다

## 3. 벡터를 앱에 넣는 길

2026-10-03 사용자가 "catalog.json에 합치기 (추천)"를 골랐다.

- 그림 출처 목록은 `plates/sources.yaml`이다. 카드 id마다 카드 그림 주소를 적는다. 카드 하나에 디자인이 여럿이면 주소도 여럿이다. 작업 008이 색인 표 `silver.card_index`에 `image_url` 칸을 두어 카드가 늘면 그 주소로 이 도구를 부른다. 2026-10-03 Databricks 세션이 알려 왔다
- 그림은 `plates/images/<카드 id>/`에 두고 저장소에 올리지 않는다. 수집이 막힌 카드사는 사용자가 손으로 저장해 넣는다
- 도구가 `plates/vectors.json`을 만들어 커밋한다. 모델 이름과 지문, 차원, 카드마다 벡터 목록이다. 지문은 모델 파일 내용의 sha256 앞부분이다. 벡터는 칸마다 -128~127 정수 하나로 줄여 담는다
- `python -m cherry_core.catalog json`이 벡터를 `catalog.json`의 `plates` 칸에 합친다. 받은 카탈로그에도 새 카드의 벡터가 함께 온다. 앱이 인터넷으로 하는 일은 그대로 카탈로그 받기 하나다
- 받은 카탈로그의 모델 지문이 앱 모델과 다르면 그 벡터는 쓰지 않고 앱에 담긴 카탈로그의 벡터를 쓴다. 파이프라인이 모델을 먼저 바꿔도 옛 앱이 엉뚱하게 비교하지 않는다
- 커밋 훅과 내보내기 워크플로가 `catalog.json`을 다시 만들어 맞춰 볼 때 `plates/vectors.json`도 읽는다
- ponytail: 카드 20장에 디자인 둘씩이면 수십 KB다. 카드가 수천 장이 되어 카탈로그 받기 상한 5MB에 가까워지면 차원을 줄이거나 따로 받는다

## 4. 폰에서 찍기

2026-10-03 사용자가 "버튼으로 찍기 (추천)"를 골랐다.

- 카메라는 `flutter.dev`가 낸 `camera`다. 2026-10-03 0.12.1, Android 7 이상. 사진 찍기 함수는 사진을 파일로 남겨 쓰지 않는다. 미리보기의 프레임 흐름에서 한 장을 메모리로 받는다. E23
- 화면 가운데에 실제 카드 비율 85.6×54mm인 안내 틀을 그린다. 카드를 틀에 맞추고 "찍기"를 누르면 그 순간의 프레임 하나에서 틀 안만 잘라 인식한다
- 처리 순서는 프레임 방향 맞추기, 틀 안 자르기, 모델 입력 크기로 줄이기, 별도 isolate에서 모델 돌리기, 카탈로그 벡터와 비교해 상위 셋 고르기다. 비교는 코사인 유사도다. 카드에 벡터가 여럿이면 가장 비슷한 것을 그 카드의 값으로 본다
- 인식이 끝나면 프레임을 버린다. 파일, DB, 로그에 쓰지 않는다. 카메라와 인식 코드가 파일 쓰기를 부르지 않는지 시험으로 본다
- 카메라 권한을 거절하면 이름 검색으로 안내한다
- 속도 기준 1초는 "찍기"를 누른 때부터 후보가 뜰 때까지다

## 5. 화면

2026-10-03 사용자가 "제안대로 (추천)"를 골랐다. 시안 보드 3을 따른다.

- 카드 추가 화면 아래 "카메라로 카드 인식"을 누르면 카메라 화면이다. 어두운 배경에 안내 틀, "사진은 폰 밖으로 나가지 않습니다", "찍기" 버튼이다
- 결과는 "이 카드가 맞나요?" 아래 1순위 카드와 확신 표시다
  - 거의 확실: 기준값을 넘고 2순위와 차이가 크다
  - 비슷함: 기준값은 넘지만 2순위와 가깝다
  - 확실하지 않음: 기준값 아래다. 이름 검색 버튼을 맨 앞에 둔다. E20
- 그 아래 "아니라면 비슷한 카드"로 2순위와 3순위를 보인다
- "이 카드로 등록"은 지금 쓰는 등록 시트를 연다. "다시 찍기", "없으면 이름으로 검색"이 있다. 이미 가진 카드면 등록 시트가 지금처럼 알린다. E21
- 시안과 다른 곳 둘. 후보마다 적은 "디자인 비슷함", "색이 비슷함" 같은 까닭은 벡터 비교로 알 수 없어 빼고 확신 단계만 보인다. 카드 그림은 저작물이라 띄우지 않고 카드사 색의 그라데이션 칸을 쓴다
- 기준값과 "차이가 크다"의 경계는 성공 기준 1과 2의 실측으로 정한다
