# 작업 015 엑셀 가져오기를 카드사별 파일 형식 표로 읽기

## 왜

- 2026-10-05 같은 실제 IBK 출력용 파일이 기억된 열 짝에 따라 세 가지 결과로 나왔다.
  1. 세 칸만 기억된 짝: 54건이 모두 결제로 들어가 합계가 101,147원 많았다
  2. 취소 여부를 "없음"으로 기억한 짝: 42건은 맞지만 취소와 할인 12건이 읽지 못한 행이 됐다
  3. 자동으로 찾은 짝: 결제 42건, 원 결제 없는 취소 4건, 카드 할인 8건. 맞는 결과다
- 지금은 모든 파일을 흔한 열 이름 사전과 손 짝짓기로 읽는다. 사용자가 짝을 하나 잘못 고르면 결과가 바뀌고, 틀린 결과가 그대로 저장될 수 있다.
- IBK 파일만 보고 만든 규칙이 모든 파일에 걸린다. "취소 줄인데 가맹점명이 할인으로 끝나면 카드가 준 할인"이라는 E59 규칙이 다른 카드사의 진짜 취소를 할인으로 뺄 수 있다.
- 같은 날 사용자가 "카드사별로 너무 결과가 다를 것 같은데"라고 했고, 카드사별 파일 형식 표와 안전장치 셋을 하기로 했다. 설계 문서 8절에 처음부터 "카드사별 매핑 표"로 적혀 있었으나 아직 만들지 않았다.

## 성공 기준

1. IBK 출력용 파일은 짝짓기 화면 없이 형식 표로 읽힌다. 앞서 기억된 짝이 세 칸만 있든, 취소 여부가 "없음"이든, 없든 결과가 같다. 시험: 지어낸 값의 IBK 모양 파일로 세 경우를 돌려 판정이 같다. 이 PC의 실제 파일 대조 시험은 결제 42건, 원 결제 없는 취소 4건, 카드 할인 8건이다
2. 신한카드, 우리카드, 뱅크샐러드 파일도 IBK처럼 형식 표로 읽힌다. 사용자가 받아 준 실제 파일마다 결제, 취소, 할인 건수와 합계를 파일에서 따로 센 값과 이 PC의 대조 시험이 같다. 지어낸 값의 같은 모양 파일로 저장소 시험을 둔다
3. 뱅크샐러드 파일은 결제수단 칸으로 줄마다 보유 카드를 찾고, 보유하지 않은 카드의 줄은 넣지 않는다. 시험: 지어낸 값의 두 카드 파일
4. 같은 결제를 카드사 파일과 뱅크샐러드 파일로 두 번 올려도 한 번만 들어간다. 시험: 이 PC의 IBK 출력용 파일을 넣은 뒤 같은 기간의 뱅크샐러드 파일을 올리면 IBK 줄이 모두 겹침으로 빠진다. 지어낸 값으로 같은 경우의 저장소 시험을 둔다
5. 미리보기가 어떤 형식으로 읽었는지 보인다. 아는 형식이면 "기업은행 출력용으로 읽었어요"처럼, 모르는 형식이면 짝을 확인해 달라는 말이 보인다. 시험: 위젯 시험 두 경우
6. E59 할인 줄 규칙은 그 규칙을 가진 형식에만 걸린다. 모르는 형식 파일의 이름이 할인으로 끝나는 취소 줄은 보통 취소로 다룬다. 시험: 두 경우
7. 자동으로 찾은 칸을 사용자가 비우거나 다른 열로 바꾸면, 자동으로 찾은 열 이름과 함께 결과가 달라질 수 있다는 알림이 보인다. 시험: 위젯 시험
8. 새 형식 하나를 더하는 일은 형식 표에 한 항목과 시험 하나를 더하는 것으로 끝난다. 읽는 코드는 바꾸지 않는다. 검사: IBK 형식이 표의 한 항목이다
9. 앞서 정한 가져오기 판정이 그대로다. 시험: `app/test/store/imports_test.dart`와 `app/test/import_test.dart`의 기존 시험이 기대값을 바꾸지 않고 통과한다. 이 작업 때문에 기대값을 바꾸는 시험은 plan.md에 까닭을 적는다
10. 저장소에 실제 결제 값을 넣지 않는다. 검사: 새 시험 파일의 가게 이름, 승인번호, 카드번호가 지어낸 값이다

## 하지 않을 것

- 실제 파일을 보지 못한 카드사 형식은 추측해 넣지 않는다. 시험자에게 머리 줄과 취소 줄 사진을 받을 때마다 하나씩 더한다.
- 진짜 옛 xls 읽기. 쓰는 사람이 생기면 정한다.
- 토스와 삼성 월렛 연동. 2026-10-05 찾아보니 둘 다 여러 카드 결제 내역을 파일로 내보내는 기능이 없다. 토스는 토스뱅크카드 한 장의 이용내역확인서만 엑셀로 메일로 받는다. 삼성 월렛은 페이 플래너에서 1년 내역을 보기만 하고, 다른 앱이 읽어 가는 공개 통로도 찾지 못했다.
- 결제 알림 읽기. 하위 프로젝트 6이고 출시 뒤에 한다.

## 정한 것

- 2026-10-05 사용자가 IBK 형식 표, 할인 줄 규칙을 IBK 형식에만 걸기, 자동으로 찾은 칸을 비우면 알리기, 모르는 형식 표시를 이 순서로 하기로 했다.
- 같은 날 사용자가 우리카드와 신한카드도 있다고 했다. 두 카드사 실제 파일을 받아 IBK와 함께 확정 형식으로 넣는다. 파일은 `app/test/local/`에만 둔다.
- 공개 저장소의 열 이름 단서는 흔한 열 이름 사전의 후보로만 쓰고, 카드사 전용 규칙은 걸지 않는다. MOA 가계부(MIT)가 신한카드 이용내역과 우리카드 이용대금명세서를 알아보고, card-recommend(라이선스 없음)가 여러 카드사의 열 이름과 취소 값을 모았다. 라이선스 없는 코드는 가져오지 않는다. 2026-10-05 사용자 답을 받기 전에 Claude가 정했다.
- 뱅크샐러드는 가계부의 "파일로 받기"로 최대 1년 내역을 엑셀로 받는다. 2026-10-05 사용자가 1년치를 받아 이 작업에 넣었다. 우리카드 파일은 메일로 오는 데 1시간쯤 걸려 뒤에 받는다.
- 2026-10-05 받은 두 파일의 모양. 값은 보지 않고 머리 줄, 값 종류, 건수만 봤다.
  - 신한카드 이용내역: 확장자는 xls지만 속은 xlsx다. 열은 거래일, 카드구분, 이용카드, 가맹점명, 업종, 승인번호, 금액, 매입구분, 이용구분, 거래통화, 최초결제일자, 해외이용금액, 취소상태다. 거래일에 날짜와 시각이 한 칸에 든다. 지금 앱이 결제일, 가맹점명, 금액, 할부, 승인번호, 카드를 자동으로 짝짓지만 취소상태는 모른다. 받은 25건에 취소가 없어 취소상태에 무엇이 적히는지는 확인 필요다
  - 뱅크샐러드: 시트 하나에 날짜, 시간, 타입, 대분류, 소분류, 내용, 금액, 화폐, 결제수단, 메모다. 시간은 시각만 든 칸이다. 결제는 음수 금액이고 취소는 양수 금액이다. 양수 18건 가운데 17건은 같은 카드, 같은 가게, 같은 금액의 결제와 짝이 맞는다. IBK 파일의 카드 할인 줄은 뱅크샐러드에 없다. 결제수단 칸에 카드 상품 이름이 들어 카드 다섯 장이 한 파일에 있다. 지금 앱은 이 파일의 머리 줄을 알아보지 못한다
