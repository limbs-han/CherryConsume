# 작업 015 계획

의도 `intent.md`, 설계 `design.md`. 2026-10-05 사용자가 의도와 설계 1~6절을 확정했다.

## 단계

1. [ ] 형식 표와 IBK 출력용
   - `app/lib/store/formats.dart`에 형식 표와 알아보기를 둔다. 설계 1절
   - `parseRows`가 형식의 `cancel`, `sign`, `discountRows`, `seen`을 따른다. 형식이 없으면 지금 규칙 그대로다
   - E59 할인 줄 규칙은 `discountRows`를 쓰는 형식에만 건다. 설계 4절 1
   - 미리보기가 아는 형식이면 기억한 짝과 사전을 쓰지 않는다. 설계 2절 1
   - 검증: 지어낸 값의 IBK 모양 파일로 기억한 짝 셋을 돌려 판정이 같다. 모르는 형식의 할인으로 끝나는 취소 줄은 보통 취소다. `seen`에 없는 값은 넣지 않는다. 이 PC의 실제 파일 대조가 결제 42건, 원 결제 없는 취소 4건, 카드 할인 8건이다. 기존 가져오기 시험이 그대로 통과한다
2. [ ] 미리보기와 화면
   - 미리보기 응답에 `format`과 `auto_mapping`을 더한다
   - 미리보기 위에 읽은 형식이나 모르는 형식 안내를 보인다. 설계 4절 3
   - 아는 형식에는 "열 다시 짝짓기"를 보이지 않고, 저장할 때 짝을 기억하지 않는다. 설계 2절 2
   - 모르는 형식에서 자동 짝과 다른 칸 아래에 알림을 보인다. 설계 4절 2
   - 검증: 위젯 시험 넷. 형식 이름, 모르는 형식 안내, 자동 짝과 다른 칸의 알림, 아는 형식에 단추 없음
3. [ ] 신한카드 이용내역
   - 형식 표에 `shinhan-usage`를 더한다. 설계 3절
   - 검증: 지어낸 값의 신한 모양 파일로 결제를 읽고, 취소상태에 값이 든 줄은 넣지 않는다. 이 PC의 실제 파일 25건과 합계가 형식 표를 쓰지 않고 따로 센 값과 같다
4. [ ] 뱅크샐러드
   - 형식 표에 `banksalad`를 더한다. 부호 반대와 `cardColumn`을 읽는 코드를 더한다. 설계 2절 4, 3절
   - 신용카드 줄 안내를 더한다
   - 검증: 지어낸 값의 두 카드 파일로 카드를 고르지 않으면 보유 카드 줄만, 고르면 그 카드 줄만 들어간다. 음수가 결제, 양수가 취소로 붙는다. 신용카드 안내가 보인다. 이 PC의 실제 파일 774건의 결제, 취소, 카드별 건수가 따로 센 값과 같다
5. [ ] 두 파일 겹침
   - 검증: 지어낸 값으로 IBK 먼저, 뱅크샐러드 먼저 두 순서의 결과가 같다. 이 PC에서 실제 IBK 출력용과 뱅크샐러드를 두 순서로 넣어 같은 기간 IBK 카드의 결제와 취소가 같다. 설계 5절
6. [ ] 우리카드
   - 메일로 오는 파일을 받으면 설계 3절에 적고 형식 표에 더한다
   - 검증: 3단계와 같은 방식
7. [ ] 검토와 문서
   - `risk-reviewer`로 검토하고 지적을 반영한다
   - 설계 문서 8절, 시나리오 E30과 E59에 결론을 합친다
   - 출시 판을 폰에 깔아 사용자가 IBK 출력용과 뱅크샐러드를 가져와 본다
   - 검증: 성공 기준 1~10을 하나씩 확인해 이 파일 끝에 적는다
