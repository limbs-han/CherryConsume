# 작업 015 계획

의도 `intent.md`, 설계 `design.md`. 2026-10-05 사용자가 의도와 설계 1~6절을 확정했다.

## 단계

1. [x] 형식 표와 IBK 출력용
   - `app/lib/store/formats.dart`에 형식 표와 알아보기를 둔다. 설계 1절
   - `parseRows`가 형식의 `cancel`, `sign`, `discountRows`, `seen`을 따른다. 형식이 없으면 지금 규칙 그대로다
   - E59 할인 줄 규칙은 `discountRows`를 쓰는 형식에만 건다. 설계 4절 1
   - 미리보기가 아는 형식이면 기억한 짝과 사전을 쓰지 않는다. 설계 2절 1
   - 검증: 지어낸 값의 IBK 모양 파일로 기억한 짝 셋을 돌려 판정이 같다. 모르는 형식의 할인으로 끝나는 취소 줄은 보통 취소다. `seen`에 없는 값은 넣지 않는다. 이 PC의 실제 파일 대조가 결제 42건, 원 결제 없는 취소 4건, 카드 할인 8건이다. 기존 가져오기 시험이 그대로 통과한다
2. [x] 미리보기와 화면
   - 미리보기 응답에 `format`과 `auto_mapping`을 더한다
   - 미리보기 위에 읽은 형식이나 모르는 형식 안내를 보인다. 설계 4절 3
   - 아는 형식에는 "열 다시 짝짓기"를 보이지 않고, 저장할 때 짝을 기억하지 않는다. 설계 2절 2
   - 모르는 형식에서 자동 짝과 다른 칸 아래에 알림을 보인다. 설계 4절 2
   - 검증: 위젯 시험 넷. 형식 이름, 모르는 형식 안내, 자동 짝과 다른 칸의 알림, 아는 형식에 단추 없음
   - 결과 2026-10-05: 앱 시험 837개 통과. 이 PC의 실제 IBK 파일은 세 칸만 기억된 짝이 있어도 결제 42건, 원 결제 없는 취소 4건, 카드 할인 8건이다. 기존 시험 가운데 기억한 짝 채우기 셋은 IBK 모양 파일이 아는 형식이 되어, 승인구분 열 이름을 거래구분으로 바꾼 모르는 형식 파일로 옮겼다. 그중 '기억한 짝에 없는 칸은 자동으로 찾은 열로 채운다'의 할인 줄 기대값은 모르는 형식에 E59를 걸지 않아 discount에서 orphan으로 바뀌었다. 성공 기준 6 그대로다. '없음으로 비운 칸' 위젯 시험은 새 안내 줄로 단추가 아래 고정 단추에 가려 누르기 전에 화면 안으로 끌어오게 했다. 짝짓기 화면 밖에서 기억한 짝이 자동 짝과 다르면 미리보기에 알리는 줄을 더해 설계 4절 2에 적었다
   - 위험 검토 2026-10-05: 높음과 중간 없음, 낮음 7. 고친 것: 늘 0이던 컵보증금과 할인금액을 본 값에 넣었다. 형식 알아보기에서 괄호 안을 남겨 승인금액(USD)를 승인금액으로 보지 않는다. 기억한 짝이 다른 머리 줄을 골라도 미리보기에 알린다. 저장소도 아는 형식이면 화면이 보낸 짝을 쓰지 않는다. 그래서 IBK 파일에 짝을 보내던 '결제일과 시각을 같은 승인일시 열로' 시험을 모르는 형식 파일로 옮겼다. 처음 보는 승인구분 시험, 화면이 보낸 짝을 쓰지 않는 시험, 괄호 열 이름 시험을 더했다. E59에 형식에만 건다고 적었다. 그대로 둔 것: 모르는 형식의 할인으로 끝나는 취소가 이름과 금액으로 원 결제에 붙는 것은 성공 기준 6이다. IBK 신용카드, 해외, 할부 줄은 단추 없이 막히는 것을 시험자에게 알린다
3. [x] 신한카드 이용내역
   - 형식 표에 `shinhan-usage`를 더한다. 설계 3절
   - 검증: 지어낸 값의 신한 모양 파일로 결제를 읽고, 취소상태에 값이 든 줄은 넣지 않는다. 이 PC의 실제 파일 25건과 합계가 형식 표를 쓰지 않고 따로 센 값과 같다
4. [x] 뱅크샐러드
   - 형식 표에 `banksalad`를 더한다. 부호 반대와 `cardRows`를 읽는 코드를 더한다. 설계 2절 4, 3절
   - 신용카드 줄 안내를 더한다
   - 검증: 지어낸 값의 두 카드 파일로 카드를 고르지 않으면 보유 카드 줄만, 고르면 그 카드 줄만 들어간다. 음수가 결제, 양수가 취소로 붙는다. 신용카드 안내가 보인다. 이 PC의 실제 파일 774건의 결제, 취소, 카드별 건수가 따로 센 값과 같다
5. [x] 두 파일 겹침
   - 검증: 지어낸 값으로 IBK 먼저, 뱅크샐러드 먼저 두 순서의 결과가 같다. 이 PC에서 실제 IBK 출력용과 뱅크샐러드를 두 순서로 넣어 같은 기간 IBK 카드의 결제와 취소가 같다. 설계 5절
   - 결과 2026-10-05, 단계 3~5: 앱 시험 850개 통과.
     - 신한카드: 실제 파일 25건이 모두 새 결제이고 합계가 따로 센 값과 같다. 맨 아래 "총 25건" 합계 줄이 읽지 못한 행으로 나와, 날짜 없이 "총 N건"인 줄을 건너뛰게 했다
     - 뱅크샐러드: 실제 파일 774건에서 카드를 고르지 않으면 IBK 줄만 들어가고 나머지 카드 줄은 보유 카드가 아니라 빠진다. 고르면 "고른 카드의 줄이 아니에요"로 빠진다. 결제 건수, 합계, 취소가 따로 센 값과 같다
     - 겹침: 실제 IBK 출력용과 뱅크샐러드를 두 순서로 넣어도 같은 기간 IBK 카드에 결제 46건과 결제 금액, 취소 금액이 같다. 결제 금액에서 취소 금액을 뺀 값은 IBK 파일만 넣었을 때의 합계와 같다
     - 바뀐 기대값: `imports_test.dart`의 요약 칸 전체 비교에 새 칸 `installment_assumed: 0`을 더했다
   - 위험 검토 2026-10-05: 높음 없음, 중간 2, 낮음 9.
     - 중간 1: 뱅크샐러드 카드 이름을 검색 이름이나 이름 일부로 맞춰 "KB국민 나라사랑카드" 줄이 IBK로 들어갈 수 있었다. 카드 이름으로 줄을 나누는 형식은 공식 이름이 같은 보유 카드 한 장에만 붙인다
     - 중간 2: 신한과 IBK 파일에 카드 여러 장의 줄이 섞여도 모두 고른 카드로 들어갔다. 이용카드와 카드번호 칸 값이 둘 이상이면 넣지 않는다. 값은 견주기만 하고 남기지 않는다
     - 고친 낮음: 뱅크샐러드 알아보는 열에서 읽지 않는 대분류, 소분류, 메모를 뺐다. 처음 보는 값 문구를 "카드 결제라면 기록에서 직접 적어 주세요"로 바꿨다. 고른 카드가 있으면 요약 줄을 "고른 카드가 아닌 행"으로 쓴다. 쉼표가 든 "총 1,025건" 합계 줄도 건너뛴다. 이 문서와 의도 문서, 작업 기록 89의 실제 결제 금액을 지웠다
     - 그대로 둔 낮음, 확인 필요: 카드사 파일과 뱅크샐러드에 같은 부분 취소의 날짜가 다르게 적히면 취소가 두 번 붙을 수 있다. 뱅크샐러드의 양수 줄이 캐시백 같은 취소가 아닌 줄이면 앞선 결제의 취소로 붙는다. 실제 파일의 짝 없는 양수 1건이 무엇인지 모른다. 뱅크샐러드가 해외 결제를 원화로 적는지 모른다. 실제 파일로 보면 정한다

   - `risk-reviewer`로 검토하고 지적을 반영한다
