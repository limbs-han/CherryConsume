2026-10-05 실제 파일 셋을 지금 코드로 읽어 본 결과다. 값은 보지 않고 머리 줄, 값 종류, 건수만 봤다.

|---|---|---|
| IBK 출력용 | 기억한 짝에 따라 결과가 셋으로 갈린다 | 사용자가 고른 짝이 사전보다 앞선다 |

| 뱅크샐러드 | 머리 줄을 못 찾는다. 짝지어도 결제 756건이 모두 취소로 읽힌다 | "날짜", "내용"이 사전에 없다. 결제를 음수로 적는데 지금 코드는 음수를 취소로 본다 |

뱅크샐러드 파일은 카드 다섯 장의 결제를 담는다. 지금 코드는 사용자가 카드 한 장을 고르면 카드 칸을 보지 않고 모든 줄을 그 카드로 넣는다.

## 1. 형식 표의 자리와 모양

형식 표는 `app/lib/store/formats.dart`의 상수 목록이다. 형식 하나가 카드사 파일 모양 하나다.

카탈로그에 두지 않는다. 카탈로그는 골드 표가 원본이라 검수 앱을 거쳐야 한다. 새 형식은 대개 금액 부호나 할인 줄 같은 새 읽기 규칙과 함께 와서 앱 코드와 시험이 같이 바뀐다. 카드사가 파일을 바꾸는 일은 드물어 앱 판 올림으로 충분하다.

| 칸 | 한 줄 설명 | IBK 출력용 예 |
|---|---|---|
| `id`, `name` | 형식 이름. 미리보기에 보인다 | `ibk-print`, 기업은행 출력용 |
| `marks` | 머리 줄에 모두 있어야 이 형식으로 아는 열 이름 | 승인구분, 승인일시, 이용가맹점명, 승인금액, 승인번호, 취소금액 |
| `columns` | 칸마다 읽을 열 이름. 열 번호가 아니라 이름이라 열 순서가 바뀌어도 맞는다 | 결제일과 시각은 승인일시, 가맹점명은 이용가맹점명 |
| `cancel` | 취소 줄을 알아보는 열과 값 | 승인구분이 "취소또는할인" |
| `sign` | 금액 부호. 보통은 음수가 취소이고, 반대면 음수가 결제다 | 보통 |
| `cardRows` | 카드 이름 열 `columns['card']`로 줄마다 보유 카드를 찾는지. 쓰면 카드 이름이 보유 카드와 맞는 줄만 넣는다 | 쓰지 않는다 |
| `discountRows` | E59 할인 줄 규칙을 쓰는지 | 쓴다 |
| `seen` | 열마다 실제 파일에서 본 값. 본 적 없는 값이 든 줄은 넣지 않고 "처음 보는 값이에요"로 보인다 | 승인구분은 원화, 취소또는할인 |

`seen`은 확인하지 못한 값을 추측하지 않으려는 칸이다. 예를 들어 신한카드 파일에서 취소상태는 빈 칸만 봤다. 취소된 결제가 오면 이 칸에 무엇이 적힐지 모르니, 빈 칸이 아닌 줄은 넣지 않고 보인다. 그 줄이 진짜 취소라면 결제로 넣어 실적을 부풀리지 않는다. 사용자가 그런 파일을 주면 값을 보고 `cancel`과 `seen`에 더한다.

알아보기: 위 20줄 가운데 띄어쓰기를 뺀 열 이름에 `marks`가 모두 든 줄이 머리 줄이다. 괄호 안은 남긴다. 열 이름 사전처럼 괄호 안을 빼면 "승인금액(USD)"를 "승인금액"으로 본다. 두 형식이 함께 맞으면 `marks`가 더 많은 형식이다. `marks`는 그 카드사 파일에만 있을 만한 열을 고른다. "금액"처럼 흔한 이름만으로는 알아보지 않는다.

## 2. 읽는 순서

1. 아는 형식이면 형식 표로 읽는다. 기억한 짝과 열 이름 사전은 쓰지 않는다. 미리보기에 "기업은행 출력용으로 읽었어요"가 보인다. 같은 형식의 파일은 누가 올려도, 앞서 무엇을 기억했든 결과가 같다. 성공 기준 1
2. 아는 형식에는 "열 다시 짝짓기"를 보이지 않는다. 형식 규칙이 열 이름에 묶여 있어 손으로 다른 열을 고르면 어느 규칙을 쓸지 정할 수 없다. 뱅크샐러드를 사전 규칙으로 읽으면 결제가 모두 취소로 읽힌다. 형식이 맞는다는 것은 형식이 읽는 열이 모두 이름 그대로 있다는 뜻이라, 카드사가 열 이름을 바꾼 파일은 모르는 형식으로 읽혀 손으로 짝지을 수 있다. 형식 표가 틀렸다면 형식 표를 고칠 일이다.
3. 모르는 형식이면 지금처럼 기억한 짝, 빠진 칸 채우기, 열 이름 사전 차례로 읽는다. 미리보기에 "처음 보는 형식이라 열 짝을 확인해 주세요"가 보인다. 4절의 안전장치가 붙는다.
4. 형식이 `cardRows`를 쓰면 줄마다 그 열의 카드 이름으로 보유 카드를 찾는다. 지금 `cardOf`를 그대로 쓴다.
   - 카드를 고르지 않았으면 보유 카드와 맞는 줄만 넣고, 나머지는 "보유 카드가 아니에요"로 보인다. 지금과 같다.
   - 카드를 골랐으면 그 카드와 맞는 줄만 넣고, 나머지는 "고른 카드의 줄이 아니에요"로 보인다. 지금은 모든 줄을 고른 카드로 넣는다. 뱅크샐러드 파일에서는 다섯 장의 결제가 한 카드로 들어간다.
   - 모르는 형식의 카드 칸은 지금처럼 둔다. 신한카드 "이용카드"처럼 카드번호 일부가 든 칸도 있어, 이름이 맞지 않는다고 줄을 빼면 멀쩡한 결제가 빠진다.

2026-10-05 사용자가 1, 2절을 확정했다. 처음 2번은 아는 형식에서 손으로 짝지으면 그 가져오기에만 쓰는 안이었다. 3절을 쓰다 형식 규칙과 고른 짝이 엇갈리는 것을 보고 단추를 없애는 안으로 바꿔 같은 날 사용자가 골랐다.

## 4. 안전장치

1. E59 할인 줄 규칙은 `discountRows`를 쓰는 형식에만 건다. 지금은 IBK 출력용 하나다. 모르는 형식 파일의 이름이 할인으로 끝나는 취소 줄은 보통 취소로 원 결제를 찾는다. 성공 기준 6
2. 모르는 형식을 짝지을 때, 자동으로 찾은 열과 다른 열을 고르거나 "없음"으로 비운 칸 아래에 알림을 보인다. 예: "자동으로 찾은 열은 '승인구분'이에요. 바꾸면 취소 줄이 결제로 읽힐 수 있어요." 칸마다 문구를 따로 두지 않고 "결과가 달라질 수 있어요. 미리보기 숫자를 확인해 주세요"를 함께 쓴다. 미리보기 응답에 자동으로 찾은 짝 `auto_mapping`을 더한다. 짝짓기 화면을 열지 않아도, 기억한 짝이나 고른 짝이 자동으로 찾은 짝과 다르면 미리보기에 "자동으로 찾은 열 짝과 다르게 읽었어요. 열 다시 짝짓기에서 확인해 주세요"를 보인다. 2026-10-05 실제 폰에서 기억한 짝이 짝짓기 화면 밖에서 조용히 결과를 바꿨다. 단계 2에서 더했다. 성공 기준 7
3. 미리보기 위에 읽은 형식을 보인다. 아는 형식이면 "기업은행 출력용 형식으로 읽었어요", 모르는 형식이면 "처음 보는 형식이라 열 짝을 확인해 주세요". 미리보기 응답에 `format`을 더한다. 성공 기준 5
4. `seen`에 없는 값이 든 줄은 "처음 보는 값이에요. 기록에서 직접 적어 주세요"로 보이고 넣지 않는다. 미리보기 요약의 읽지 못한 행에 든다

## 5. 두 파일의 겹침
