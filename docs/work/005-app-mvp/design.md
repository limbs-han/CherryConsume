# 005 설계

의도는 `intent.md`다. 2026-10-01 사용자가 알아서 진행하라고 해서 이 설계는 절마다 확인받지 않고 정했다. 바꿀 곳이 있으면 사용자가 짚은 절부터 고친다.

## 1. 구조

```
backend/
  pyproject.toml        # cherry-core 하나. 서버 의존성은 의존성 묶음 api에 둔다
  cherry_core/          # 카탈로그와 엔진. 그대로 둔다
  cherry_api/           # FastAPI 서버
    main.py             # 앱 만들기, 켜질 때 카탈로그 읽기와 DB 맞추기
    db.py               # 연결 풀, 마이그레이션 실행
    auth.py             # 세션 토큰, 개발용 로그인
    catalog_sync.py     # 카탈로그 파일을 카탈로그 표에 맞춘다
    routes/             # 슬라이스마다 파일 하나
    migrations/NNN_*.sql
  tests/api/            # 서버 테스트. Docker의 Postgres로 돈다
app/                    # Flutter 앱. Android만
compose.yaml            # 개발과 테스트용 Postgres
```

- 서버 의존성은 `[dependency-groups]`의 `api`에 둔다. 파이프라인이 쓰는 wheel에는 묶음이 들어가지 않아 Databricks에 FastAPI가 깔리지 않는다. `[tool.uv] default-groups`에 넣어 `uv run`은 그대로 쓴다.
- 서버는 엔진을 켜질 때 한 번 만든다. 작업 002 설계 대로다.
- DB는 psycopg 3로 SQL을 직접 쓴다. ORM은 쓰지 않는다. 표가 ERD와 한 줄씩 맞고, Postgres 표준 SQL만 쓰는지 눈으로 볼 수 있다.

## 2. DB

- 마이그레이션은 `cherry_api/migrations/`의 SQL 파일이다. 서버가 켜질 때 `schema_migrations` 표에 없는 파일을 번호 순서로 한 번씩 돌린다. 돌릴 파일 전부를 한 트랜잭션으로 돌려 하나라도 실패하면 모두 되돌린다. 서버 여러 대가 함께 켜져도 한 대만 돌리게 Postgres 잠금을 건다. 한 번 돌린 파일은 고치지 않고 새 번호를 더한다.
- 슬라이스마다 그 슬라이스가 쓰는 표만 만든다. 표 모양은 `docs/erd.md`를 따른다.
- 시각은 모두 `timestamptz`다. 달 경계는 한국 시간으로 서버 코드가 계산한다. E7
- ERD에 없던 표 하나를 더한다. `sessions`는 로그인 토큰이다. 3절

## 3. 인증

- 로그인하면 서버가 무작위 토큰을 만들어 앱에 준다. 서버는 토큰의 SHA-256만 `sessions`에 둔다. DB가 새도 토큰을 그대로 쓸 수 없다.
- 앱은 요청마다 `Authorization: Bearer <토큰>`을 보낸다. 서버는 해시로 세션을 찾고, 만료됐거나 탈퇴한 사용자면 401이다. 탈퇴는 즉시 막는다는 설계 문서 4.3절 5번 때문에 서명만 보는 토큰 대신 DB를 본다.
- 토큰은 1년 뒤 끝난다. 로그아웃하면 그 세션 행을 지운다.
- **개발용 로그인.** `CHERRY_DEV_LOGIN=1`이고 DB가 PC에 있는 서버에만 `POST /auth/dev`가 생긴다. DB 주소가 `127.0.0.1`, `localhost`, `::1`이 아니면 서버가 켜지지 않는다. 끈 서버는 켜질 때 개발용 사용자의 세션을 지운다. API 문서 화면도 이때만 연다. 2026-10-01 위험 검토. 이름 하나를 받아 `auth_identities`의 `provider = 'dev'` 사용자를 만들거나 찾고 진짜 로그인과 같은 토큰을 준다. 끈 서버에는 경로가 없어 404다. 카카오와 Google 로그인 슬라이스에서도 지우지 않고 개발과 테스트에 쓴다.

## 4. 카탈로그 동기화

- 서버가 켜질 때 `CHERRY_CATALOG_DIR`의 카탈로그를 읽어 엔진을 만들고, 같은 내용을 카탈로그 표에 맞춘다. ERD의 외래 키가 카탈로그 표를 가리키기 때문이다. 기본 경로는 저장소의 `catalog/`다.
- 카드사, 카드, 업종, 가맹점은 있으면 고치고 없으면 넣는다. 지우지 않는다. 카탈로그에서 사라진 카드도 보유 카드가 가리킬 수 있다.
- 개정 행은 쌓기만 한다. `(card_id, effective_from, rules_sha256)`이 없으면 넣는다. 같은 날의 개정이 고쳐지면 새 행이 생기고 옛 행은 그대로라, 결제가 가리키는 행은 그때 계산에 쓴 규칙이다. 2026-10-01 위험 검토에서 처음의 덮어쓰기를 바꿨다. E18
- 카탈로그에 오류가 있으면 엔진이 만들어지지 않아 서버가 켜지지 않는다. 작업 002 설계와 같다.

## 5. API. 슬라이스 1

모든 응답은 JSON이다. 금액은 원 단위 정수다.

| 경로 | 하는 일 |
|---|---|
| `POST /auth/dev` | 개발용 로그인. `{name}`을 받아 `{token}`을 준다 |
| `POST /auth/logout` | 지금 토큰의 세션을 지운다 |
| `GET /catalog/issuers` | 카드사 칩. `[{code, name}]` |
| `GET /catalog/cards?q=&issuer=` | 카드 검색. 단종 카드는 숨긴다. E19. 카드마다 이름, 카드사, 신용과 체크, 국내 연회비 최저값, 지금 개정의 구간 |
| `GET /catalog/cards/{id}/preview?prev=` | 등록 시트의 미리보기. 지난달 쓴 금액으로 이번 달 구간과 그 구간에서 받는 혜택 제목 |
| `POST /me/cards` | 카드 등록. `{card_id, assumed_prev_month_spend?, started_on?}`. 이미 가진 카드면 409. E21 |
| `GET /me/home` | 홈. 이번 달, 받은 혜택 합계, 카드마다 `spend_status` |

- 카드 등록과 홈은 지금 시각을 서버 시계에서 읽는다. 테스트는 시계를 바꿔 넣는다.
- 요청 모델은 `extra="forbid"`다. 모르는 칸을 보내면 422라서 카드번호 같은 칸이 몰래 들어오지 않는다. 의도 성공 기준 6
- 422 응답에는 보낸 값을 되돌리지 않는다. 카드번호를 잘못 보내도 응답에 남지 않는다
- 커밋은 응답을 보내기 전에 한다. FastAPI의 기본값은 응답 뒤라 `Depends(get_conn, scope="function")`으로 바꿨다

## 6. 앱

- Flutter, Android만. 패키지는 `http`와 `flutter_secure_storage` 두 개로 시작한다. 상태 관리 패키지와 라우터 패키지는 화면이 늘어 필요해질 때 넣는다.
- 서버 주소는 빌드할 때 `--dart-define=API_URL=`로 넣는다. 기본값은 에뮬레이터용 `http://10.0.2.2:8000`이다. 평문 HTTP는 디버그 빌드에서만 허용한다.
- 색과 모서리는 화면 시안을 따른다. 글자 `#191F28`, 보조 글자 `#4E5968`, 흐린 글자 `#6B7684`, 할 일 파랑 `#3457B2`, 연한 파랑 `#E8EEFB`, 바탕 `#F2F4F7`, 선 `#E1E5EC`, 혜택 초록 `#2F7A4F`, 연한 초록 `#E3F2E9`, 기회 호박색 `#B45309`. 모서리는 20, 16, 8px과 완전히 둥글게다. 작업 004
- 금액은 "7,669원", 큰 금액은 "11.8만"처럼 쓴다.
- 화면 시안의 숫자는 예시다. 앱은 실제 카탈로그 값을 보여 준다. 예를 들어 신한카드 Mr.Life의 구간은 시안의 30, 60, 90만이 아니라 카탈로그의 30, 50, 100만이다.

## 7. 테스트

- 서버 테스트는 `CHERRY_TEST_DATABASE_URL`이 있을 때만 돈다. 없으면 이유를 적고 건너뛴다. 사용자 명세서 대조 테스트처럼 다른 PC에서 전체 테스트가 깨지지 않게 하려는 것이다.
- 테스트 묶음이 시작할 때 빈 DB를 새로 만들고 마이그레이션을 돌린다. 테스트마다 사용자 영역 표를 비운다.
- 앱은 위젯 테스트로 화면을 확인한다. 서버는 `http` 패키지의 가짜 클라이언트로 바꿔 넣는다.
- 슬라이스가 끝나면 에뮬레이터에서 직접 눌러 보고 화면을 찍어 plan.md에 남긴다.
