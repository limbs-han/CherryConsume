# 005 서버와 앱 MVP

설계 문서 5절의 하위 프로젝트 2다. 2026-10-01 사용자가 Databricks 작업은 다른 세션에 맡기고 이 세션에서 서버와 앱을 수직 슬라이스로 먼저 만들기로 했다. 같은 날 "문제가 생기지 않는 한 알아서 진행해"라고 해서 아래 "정한 것"의 Claude 결정은 사용자 확인 전에 정했다.

## 왜

- 엔진과 카탈로그는 끝났지만 사람이 쓸 수 있는 것이 없다. 폰에서 카드를 등록하고 결제를 적고 추천을 봐야 제품이다.
- 층마다 따로 만들면 DB, API, 화면이 끝까지 맞물리는지 마지막에야 안다. 수직 슬라이스는 기능 하나를 DB부터 화면까지 한 번에 끝내고 다음 기능으로 간다. 슬라이스마다 에뮬레이터에서 눌러 볼 수 있다.

## 성공 기준

설계 문서 5절의 완료 기준을 검사할 수 있게 나눈 것이다.

1. 실제 Android 폰에서 로그인, 카드 등록, 결제 기록, 추천, 추천에서 결제 기록까지 한 흐름이 끊기지 않는다. 화면 시안 보드 0, 1a, 2, 등록 시트, 1, 4, 5, 5b 순서로 눌러 확인한다
2. 카드사 웹에서 받은 이용 내역 엑셀 한 달치를 두 번 올려도 결제가 한 번만 들어간다. 사용자 IBK 명세서로 확인한다. S11, E31
3. 홈의 구간 배지, 남은 금액, 이번 달 받은 혜택이 엔진의 `spend_status`, 저장한 혜택 합계와 같다. 서버 테스트가 손계산 값으로 확인한다
4. 결제를 저장하면 그 결제의 혜택이 `transaction_benefits`에 남고, 카탈로그가 바뀌어도 다시 계산하지 않는다. E18. 예외는 E5, E48, E51뿐이다
5. 추천을 따라 기록한 결제에 추천 요청 id가 붙는다. S4
6. 서버는 카드번호를 받는 칸이 없다. API 요청 모델에 카드번호처럼 보이는 칸이 없는지 테스트로 확인한다
7. 개발용 로그인은 환경변수를 켠 서버에서만 된다. 끈 서버에서 부르면 404다. 테스트로 확인한다
8. 서버 테스트와 앱 위젯 테스트가 모두 통과한다. 서버 테스트는 Docker의 Postgres로 돈다

## 하지 않을 것

- 카메라 카드 인식. 하위 프로젝트 4다. 시안의 "카메라로 인식" 버튼은 둔다. 누르면 아직 준비 중이라고 알린다
- 결제 알림 읽기. 하위 프로젝트 6이다
- 스토어 등록, 개인정보처리방침 본문. 하위 프로젝트 5다
- 사용자 로그 내보내기. 하위 프로젝트 3의 ②다
- iOS 빌드
