설계는 `design.md`다. 슬라이스마다 단계를 그 슬라이스를 시작할 때 쓴다. 단계가 끝나면 `[x]`로 바꾸고 결과를 한 줄 적는다.

명령
- DB 켜기: `docker compose up -d db`
- 서버 테스트: `CHERRY_TEST_DATABASE_URL=postgresql://cherry:cherry@127.0.0.1:5433/postgres uv run --project backend pytest -q backend/tests/api`
- 서버 켜기: `CHERRY_DEV_LOGIN=1 CHERRY_DATABASE_URL=postgresql://cherry:cherry@127.0.0.1:5433/cherry uv run --project backend uvicorn cherry_api.main:create_app --factory --port 8000`. 에뮬레이터는 `10.0.2.2:8000`으로 붙는다
- 앱 테스트: `cd app && flutter test`
- 에뮬레이터용 앱 빌드: `cd app && flutter build apk --debug --dart-define=DEV_LOGIN=true`
- 이 PC에서는 DB 주소에 `localhost` 대신 `127.0.0.1`을 쓴다. `localhost`는 IPv6로 먼저 붙으려다 멈춰 테스트가 30초씩 기다렸다. 2026-10-01

### 슬라이스 1 결과. 2026-10-01

- 서버 테스트 28개 통과. `backend/tests/api/`. 전체는 547개 통과, DB 주소가 없으면 서버 테스트 28개는 건너뛴다
- 앱 테스트 10개 통과. 금액 쓰기, 홈 카드 한 줄의 다섯 모양, 빈 홈에서 등록까지의 흐름
- 손계산 값. 신한카드 Mr.Life에 지난달 41만을 넣으면 30만 구간, 지킬 금액 30만, 다음 50만 구간까지 50만. 비우면 0원 구간과 `no_prev_month_data`. 이번 달에 받은 새 카드는 특례 30만 구간. 한국 시간 10월 1일 00:30에는 등록한 달이 지나 추정값을 쓰지 않고 0원 구간
- 테스트에서 알게 된 것. 엔진은 카드마다 `check_conditions`, `assumed_value` 안내 경고를 늘 붙인다. 앱은 이 둘을 슬라이스 4의 카드 상세에서 보여 준다
- 에뮬레이터. 개발용 로그인, 빈 홈, 카드 검색 "mr", 등록 시트에서 41만 입력, 홈의 "30만 구간"과 "30만 더 쓰면 유지"까지 눌러 확인했다. 등록 버튼이 아래 시스템 막대에 붙던 것과 "추정" 배지의 흰 글자 대비를 고쳤다
- Flutter의 `setState`에 Future를 돌려주는 화살표 함수를 넣으면 오류가 나 화면이 갱신되지 않는다. 위젯 테스트가 잡았다

### 슬라이스 1 위험 검토. 2026-10-01

높음 1건, 중간 3건을 고쳤다.
- 높음. 커밋이 응답 뒤에 일어나 로그인 직후 다음 요청이 세션을 못 찾을 수 있었다. 응답 전에 커밋한다
- 중간. 개발용 로그인을 꺼도 그때 받은 토큰이 살아 있었다. 끈 서버는 켜질 때 개발용 세션을 지우고, 개발용 로그인은 PC의 DB에서만 켜진다
- 중간. 등록 미리보기가 새 카드 특례의 혜택별 구간과 옵션을 무시해 삼성카드 taptap O의 패키지 혜택이 모두 보였다. 엔진처럼 혜택마다 구간을 보고 옵션 혜택은 뺀다
- 중간. 같은 개정 행을 덮어써 결제가 가리키는 규칙이 바뀔 수 있었다. 개정 행은 쌓기만 한다

낮음 중 고친 것: 422 응답의 보낸 값, 지난달 금액 상한 1억, 이미 돌린 마이그레이션이 바뀌면 서버가 켜지지 않음, 마이그레이션 번호 겹침, 앱의 401 처리와 저장소 읽기 실패, 새 카드 받은 달을 한국 시간으로 셈, 검색 구간을 이달 1일 개정으로 맞춤, API 문서 화면은 개발 때만, 경계 시험 더함.

미룬 것
- 개정을 못 찾은 카드는 홈에서 실적 무관처럼 보인다. 지금 카드 20장에는 없다. 첫 개정이 미래인 카드가 생기면 고친다
- 탈퇴한 사람은 30일 동안 같은 수단으로 다시 가입하지 못한다. 슬라이스 7에서 정한다
- 출시 빌드의 서명 키, 만료된 세션 지우기. 슬라이스 8
- 서버 테스트를 돌리는 CI가 없다. 지금은 PC에서만 돈다
- 개정 해시는 Rules 모델 전체의 덤프라 모델에 기본값 있는 칸을 더하면 모든 개정이 새 행이 된다

두 번째 검토에서 중간 1건과 낮음 4건을 더 고쳤다. 기본 옵션이 있는 카드는 그 옵션의 혜택을 보인다. 하나 원더2 DAILY가 40만 구간인데 혜택이 0개로 보였다. 개발용 로그인의 `hostaddr` 검사, 시행일 추정 칸 고치기, 앞 번호 마이그레이션 막기, 401일 때 열린 화면까지 닫기다. 서버 테스트 38개, 앱 테스트 12개.

슬라이스 2에서 지킬 것
- 결제의 `card_revision_id`는 지금 메모리 개정 내용의 해시로 `(card_id, effective_from, rules_sha256)` 행을 찾는다. 가장 큰 id를 고르면 틀린다. 내용을 A에서 B로 고쳤다가 A로 되돌리면 큰 id는 B다
- 홈과 미리보기의 혜택 제목은 `benefits_at`이 엔진의 새 카드 특례와 옵션 기본값을 흉내 낸다. 결제가 생기면 엔진 결과와 어긋나지 않는지 시험을 더한다
