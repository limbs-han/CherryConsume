# 006 폰 안 저장과 폰 안 계산

2026-10-02 사용자가 구조를 바꾸기로 했다. 설계 문서의 확정된 결정 "계정과 결제 내역은 서버 저장, 추천은 서버 계산"을 "카탈로그를 앱에 담고 기록과 계산을 폰 안에서 한다"로 바꾼다. 작업 005 슬라이스 8 배포는 멈췄다.

## 왜

- 계산대 앞에서 쓰는 앱이다. 지하 매장처럼 신호가 약한 곳에서도 추천이 바로 떠야 한다. 서버 계산은 인터넷이 없으면 추천을 못 한다
- 다루는 것이 남의 결제 기록이다. 기록이 폰 밖에 없으면 서버 해킹, DB 백업, 탈퇴 뒤 삭제, 개인정보 보관 부담이 사라진다
- 1인 개발이고 수익이 없다. 서버 비용과 관리가 0이 된다

## 성공 기준

1. 비행기 모드의 실제 Android 폰에서 카드 등록, 결제 기록, 추천, 추천에서 결제 기록, 기록 고치기와 지우기, 카드 상세, 모르는 값 답하기, 엑셀 가져오기가 모두 된다
2. Python 엔진 시험 387개가 확인하던 것을 Dart 시험이 모두 확인한다. 카드별 YAML 표 20개와 시험용 카탈로그는 그대로 읽어 쓰고, 나머지 Python 시험은 같은 입력과 기대값으로 옮긴다. 기대값은 지금 손계산 값 그대로다
3. 작업 005 서버 테스트가 인용한 시나리오 번호마다 그것을 확인하는 Dart 테스트가 하나 이상 있다. 저장한 혜택은 카탈로그가 바뀌어도 다시 계산하지 않는 E18, 다시 계산 범위 E52~E56, 같은 파일을 두 번 올려도 한 번만 들어가는 S11이 들어간다
4. 앱이 인터넷으로 하는 일은 카탈로그 파일 받기 하나뿐이다. 결제, 카드, 답은 폰 밖으로 나가지 않는다. 앱 코드에서 네트워크를 부르는 곳이 한 곳뿐인지 시험으로 확인한다
5. 새 카탈로그를 받아도 저장한 결제의 혜택은 그대로다. 받은 파일이 깨졌거나 검사를 통과하지 못하면 쓰지 않고 가진 것을 쓴다. 시험으로 확인한다
6. 설정에서 기록을 파일 하나로 내보내고, 앱을 지웠다 다시 깐 뒤 그 파일을 가져오면 홈과 기록이 내보내기 전과 같다. Android 자동 백업은 꺼져 있다
7. 서버, Python 엔진, 카카오와 Google 로그인이 저장소에서 빠진다. 카탈로그 검사와 파이프라인 시험은 그대로 통과한다
8. 금액은 정수로만 다룬다. 카드번호를 받는 칸이 없다

## 하지 않을 것

- 서버 동기화, 계정, 여러 기기에서 함께 쓰기
- 사용자 행동 로그 보내기. 1차 출시에는 모으지 않는다. 사용자가 생기면 동의한 사람만 가명처리한 요약을 작은 받는 서버를 거쳐 Databricks로 보내는 작업을 따로 한다. 2026-10-02 사용자가 정했다
- Android 자동 백업
- iOS 빌드
- 카메라 카드 인식, 결제 알림 읽기, 스토어 등록. 원래대로 다른 하위 프로젝트다
