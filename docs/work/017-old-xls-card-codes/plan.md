## 단계

1. [x] 옛 엑셀 읽기
   - `app/lib/store/xls.dart`의 `readXls`, `readSource`가 옛 엑셀 앞머리면 부르고 출처 `xls`. 기록 가져오기의 출처 검사도 받는다. 설계 1절
   - 검증: 시험 안에서 만든 옛 엑셀 파일로 글자, 숫자, 날짜, 수식 결과, 이어진 공유 글자, 큰 흐름과 작은 흐름을 읽는다. 사슬이 도는 파일, 섹터가 파일 밖인 파일, 비밀번호 레코드, Book 흐름은 알맞은 문구로 거절한다. 이 PC에서 실제 우리카드와 기업은행 거래용 파일이 다른 도구로 읽은 값과 칸마다 같다
   - 2026-10-06 `c931bb0`. `app/test/store/xls_test.dart` 7개. 이 PC에서 실제 우리카드 1,156칸, 기업은행 거래용 836칸이 xlrd로 읽은 값과 모두 같다. 시험은 `app/test/local/xls_real_probe_test.dart`이고 기대값은 시험 전에 xlrd로 만든다
   - 기대값을 바꾼 기존 시험 둘. `imports_test.dart`와 `imports_ibk_test.dart`가 64바이트짜리 가짜 옛 엑셀로 옛 형식 문구를 봤다. 이제 읽으려 들어 "깨져"가 맞다. 옛 형식 문구는 Book 흐름 파일로 본다. `import_test.dart`는 안내 한 줄이 늘어 칸을 누르기 전에 화면에 보이게 한다
   - 기업은행 거래용은 이제 읽히지만 머리 줄이 없어 열 짝짓기 화면이 뜬다. 그 화면에 "기업은행은 출력용으로 받으면 돼요" 안내를 더했다
   - 위험 검토: 중간 1, 낮음 4. 디렉터리 항목마다 흐름을 다시 따라가 깨진 2MB 파일 하나에 16초가 걸렸다. 뿌리 항목 하나와 처음 찾은 Workbook만 읽는다. 수식과 칸의 오류는 xlsx처럼 "#N/A" 같은 글자로, 흐름 이름은 대소문자를 가리지 않는다. 새 판의 기록 파일에 출처 xls가 들어가면 표 정의 번호가 같은 옛 판이 "기록 파일이 아니에요"로 거절하는 것은 단계 2의 표 정의 6번과 함께 나가 번호가 6이 되어 풀린다
2. [ ] 카드 칸 짝짓기
   - 형식 표의 `oneCard`를 `cardCodes`로, 표 정의 6번 `import_card_codes`, 미리보기와 저장, 화면의 고르기 줄. 설계 3절
   - 검증: 두 카드 파일은 값마다 고르고, 고르지 않은 값의 줄은 넣지 않는다. 한 카드 파일은 묻지 않는다. 고른 짝은 다음 가져오기에 쓰이고 기록 내보내기에 없다. 위젯 시험
