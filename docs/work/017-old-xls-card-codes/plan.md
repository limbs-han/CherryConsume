2. [x] 카드 칸 짝짓기
   - 형식 표의 `oneCard`를 `cardCodes`로, 표 정의 6번 `import_card_codes`, 미리보기와 저장, 화면의 고르기 줄. 설계 3절
   - 검증: 두 카드 파일은 값마다 고르고, 고르지 않은 값의 줄은 넣지 않는다. 한 카드 파일은 묻지 않는다. 고른 짝은 다음 가져오기에 쓰이고 기록 내보내기에 없다. 위젯 시험
   - 2026-10-06 `3210976`. `app/test/store/card_codes_test.dart` 12개와 `app/test/import_test.dart` 위젯 시험 하나. 앱 시험 874개, 이 PC의 실제 파일 시험까지 894개 통과
   - 기대값을 바꾼 기존 시험 셋. `import_formats_test.dart`의 섞인 신한카드 파일은 파일 전체 오류 대신 줄마다 "어느 카드인지 골라 주세요"다. `imports_test.dart`의 미리보기 요약에 `unpaired` 칸이 늘었다. `db_test.dart`의 표 목록에 6번 표가 늘었다
   - 위험 검토 첫 번: 높음 1, 중간 2, 낮음 6. 값이 하나인 파일에서 기억한 짝이 위에서 고른 카드를 말없이 이겼다. 의도 성공 기준 4대로 위에서 고른 카드가 먼저이고 설계 3절을 고쳤다. 빈 카드 칸을 값으로 세던 것, 짝을 바꿔 같은 파일을 다시 넣으면 같은 결제가 다른 카드에 들어가던 것, 카드를 지워도 짝이 남던 것, 저장의 짝 검사, 시나리오 E60 문구를 고쳤다
   - 재검토: 중간 1, 낮음 3. 고르기 줄의 짝이 나중에 위에서 고른 카드를 이겨 위에서 카드를 바꾸면 고른 짝을 비운다. 카드 칸이 모두 빈 파일은 위에서 카드를 골라야 한다. 지운 카드의 결제는 다른 카드 겹침으로 보지 않는다
   - 남긴 것: 짝을 바꾼 뒤 다른 카드에 있는 결제의 취소가 오면 원 결제를 못 찾아 짝 없는 취소로 빠진다. 사용자가 짝을 잘못 바꿨을 때만 생기고 화면이 짝 없는 취소 건수를 알린다. 고르기 줄에서 짝을 바로잡고 다시 넣으면 된다
   - 표 정의 6번이 더해져 기록 파일의 표 정의 번호가 6이다. 옛 판 앱은 새 판의 기록 파일을 "앱을 새 판으로 올린 뒤" 문구로 거절한다. 단계 1의 출처 xls 문제도 이것으로 풀린다
