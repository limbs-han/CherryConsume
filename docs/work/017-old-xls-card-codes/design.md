# 작업 017 설계

의도는 `intent.md`다. 지금은 `app/lib/store/imports.dart`의 `readSource`가 파일 앞머리로 xlsx, html 표, csv를 가르고, 옛 엑셀 앞머리 `D0 CF 11 E0`이면 거절한다. 카드사 형식 표는 `app/lib/store/formats.dart`이고, 카드 칸 값이 둘 이상이면 `oneCard`가 파일을 통째로 막는다.

2026-10-06 실제 파일 둘을 이 PC의 다른 도구로 열어 모양만 봤다. 값은 가렸다.

| 파일 | 모양 |
|---|---|
| 우리카드 메일 | BIFF8. 시트 하나. 제목 "국내 거래승인내역(정상)", 카드번호 일부, 성명, 조회 기간 줄 아래 머리 줄. 결제 102줄 아래 승인 건수와 금액, 국외, 취소 합계 줄 셋. 카드 칸 값이 둘. 요청방식은 일시불과 체크계좌. 취소일은 모두 "-" |
| 기업은행 거래용 | BIFF8. 시트 하나. 머리 줄 없이 첫 줄부터 결제 |

## 1. 옛 엑셀 읽기

새 파일 `app/lib/store/xls.dart`의 `readXls(Uint8List) → List<List<Object?>>`가 첫 워크시트를 행과 칸으로 돌려준다. 칸 값은 xlsx와 같은 꼴이다. 글자, 정수나 소수, 날짜 서식이 걸린 숫자는 `DateTime`, 시각만 든 것은 `Duration`이다. 지금 xlsx의 `_dateIds`, `isDateFormat`, `fromExcel`을 함께 쓴다. 새 의존성은 들이지 않는다. Dart에 쓸 만한 옛 엑셀 라이브러리가 없다.

읽는 차례
1. OLE 복합 파일 머리에서 섹터 크기와 섹터 사슬 표를 읽는다. 사슬 표가 길면 이어진 표 목록까지 따라간다
2. 디렉터리에서 이름이 "Workbook"인 흐름을 찾는다. 4KB보다 작으면 작은 흐름 표로 읽는다. "Book"만 있으면 BIFF5 이전 형식이라 거절한다
3. 흐름의 레코드를 차례로 읽는다
   - 통합 문서 부분: 비밀번호 `FILEPASS`가 있으면 거절한다. 공유 글자 표 `SST`와 이어지는 `CONTINUE`, 숫자 서식 `FORMAT`, 칸 서식 `XF`, 1904 날짜 기준 `DATEMODE`, 시트 위치 `BOUNDSHEET8`
   - 첫 워크시트 부분: `LABELSST`, `LABEL`, `NUMBER`, `RK`, `MULRK`, `FORMULA`와 뒤따르는 `STRING`, `BOOLERR`
4. 칸을 행과 열에 놓는다. 열은 지금처럼 60열까지, 행은 3,000줄 남짓까지다

막는 것. 파일은 이미 2MB까지다. 섹터 번호가 파일 밖을 가리키거나 사슬이 돌면 섹터 수만큼 따라간 뒤 멈추고 "파일이 깨져 읽지 못했어요"로 거절한다. 공유 글자 수, 레코드 길이, 행과 열 번호도 범위를 본다. 거절 문구는 셋이다.
- 비밀번호: "비밀번호가 걸린 파일이라 읽지 못했어요. 카드사에서 비밀번호 없이 받거나 xlsx로 저장해 올려 주세요"
- BIFF5 이전: 지금의 옛 엑셀 문구
- 깨짐: "파일이 깨져 읽지 못했어요"

읽은 파일 모양 `import_batches.source`에 `xls`를 더한다. 기록 가져오기의 출처 검사도 받는다.

## 2. 우리카드 형식

| 칸 | 값 |
|---|---|
| `id`, `name` | `woori-approvals`, 우리카드 거래승인내역 |
| `marks` | No, 회원, 카드, 요청방식, 승인번호, 승인일자, 승인금액, 할부, 접수일, 취소일, 가맹점, 사업자번호 |
| `columns` | 결제일과 시각은 승인일자, 가맹점명은 가맹점, 금액은 승인금액, 할부는 할부, 승인번호는 승인번호, 취소 여부는 취소일 |
| `cardCodes` | 카드 |
| `seen` | 회원은 본인. 요청방식은 일시불, 체크계좌. 할부는 빈 칸. 취소일은 "-" |

- 받은 파일 이름이 "정상"이라 취소 줄이 없다. 취소일에 날짜가 든 줄은 본 적이 없어 넣지 않고 보인다
- 맨 아래 합계 줄은 결제일과 가맹점이 비어 지금처럼 건너뛴다
- 가족 카드 줄은 "회원" 값이 달라 넣지 않고 보인다

## 3. 카드 칸 짝짓기

형식 표의 `oneCard`를 `cardCodes`로 바꾼다. 카드 칸 값은 카드번호 일부라 카드 이름으로 맞출 수 없다. 사용자가 값마다 보유 카드를 한 번 고른다.

- 표 정의 6번 `import_card_codes`: 형식, 카드 칸 값, 보유 카드, 고친 시각. 형식과 값이 주 키다. 보유 카드를 지우면 함께 지운다. 카드 지우기는 행을 남기고 지운 표시만 해서 그때 짝을 따로 지운다. 기록 가져오기는 보유 카드를 다시 넣어 짝이 모두 지워진다. 기록 내보내기에 넣지 않는다. 카드번호 끝 4자리와 카드의 짝은 폰 안에만 둔다는 규칙과 같다
- 미리보기는 파일의 카드 칸 값마다 건수와 짝지은 보유 카드를 돌려준다. 짝은 화면이 보낸 짝이 먼저다. 값이 하나뿐이면 다음은 위에서 고른 카드, 그다음 기억한 짝이다. 값이 둘 이상이면 기억한 짝이다. 지금 고른 카드가 예전에 기억한 짝보다 우선이다. 2026-10-06 단계 2 위험 검토 높음 1. 처음 쓴 차례는 기억한 짝이 위에서 고른 카드를 말없이 이겨 의도 성공 기준 4와 달랐다
- 카드 칸이 빈 줄은 값으로 세지 않는다. 값이 하나 이하인 파일이면 그 값의 카드나 위에서 고른 카드이고, 값이 둘 이상이면 넣지 않는다. 빈 값은 짝으로 기억하지 않는다. 단계 2 검토 중간 2
- 승인번호, 금액, 결제일이 같은 결제가 다른 보유 카드에 이미 있으면 "다른 카드에 이미 있는 결제예요"로 넣지 않는다. 짝을 바꿔 같은 파일을 다시 넣어도 두 카드에 들어가지 않는다. 단계 2 검토 중간 3
- 값이 둘 이상이면 미리보기 줄마다 카드 이름을 보이고 머리의 카드 이름은 "여러 카드"다
- 짝이 없는 값의 줄은 "어느 카드인지 골라 주세요"로 넣지 않는다
- 화면은 값이 둘 이상이거나 짝이 없는 값이 있으면 미리보기 위에 "카드 칸 M000 · 12건 → 보유 카드 고르기" 줄을 둔다. 고르면 다시 읽는다. 저장할 때 화면이 보낸 짝을 기억한다. 열 짝과 같은 방식이다
- 기업은행 출력용의 카드번호 칸, 신한카드 이용내역의 이용카드 칸도 `cardCodes`로 바꾼다. 카드 한 장 파일은 지금처럼 위에서 고른 카드로 들어가고 묻지 않는다

## 4. 시험

- 옛 엑셀: 시험 안에서 작은 옛 엑셀 파일을 바이트로 만드는 도우미를 둔다. 글자, 숫자, 날짜, 수식 결과, 이어진 공유 글자, 큰 흐름과 작은 흐름. 깨진 파일은 사슬이 도는 것, 섹터가 파일 밖인 것, 비밀번호 레코드, Book 흐름
- 이 PC의 대조: 실제 우리카드와 기업은행 거래용 파일을 `readXls`로 읽어 다른 도구로 읽은 값과 칸마다 견준다. 견주는 기대값은 시험이 도는 PC에서 만들어 저장소에 남기지 않는다
- 우리카드 형식과 카드 칸 짝짓기는 지어낸 값의 같은 모양 파일로 시험한다
