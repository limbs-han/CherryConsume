# 작업 017 옛 엑셀 읽기와 카드 칸 짝짓기, 우리카드 형식

## 왜

- 2026-10-06 사용자가 우리카드 메일로 받은 이용 내역 파일을 줬다. 진짜 옛 엑셀 형식이라 지금 앱은 "옛 엑셀 형식이라 읽지 못했어요"로 거절한다. 기업은행 "거래용"도 같은 형식이다.
  - 옛 엑셀 형식: 엑셀 97~2003의 .xls. 여러 파일을 한 파일에 담는 OLE 복합 파일 안에 BIFF8이라는 레코드 묶음으로 표가 들어 있다. 지금 앱이 읽는 xlsx는 zip 안의 XML이라 읽는 법이 전혀 다르다
- 파일 하나에 카드 칸 값이 둘이다. 작업 015 규칙은 카드 여러 장의 줄이 섞인 파일을 통째로 막는다. E60
- 같은 날 사용자가 옛 엑셀 읽기를 만들고, 카드 칸 값마다 보유 카드를 고르게 하기로 했다. 작업 015 의도는 옛 엑셀 읽기를 하지 않을 것으로 적어 두어 새 작업으로 한다. 작업 015의 단계 6 우리카드는 이 작업으로 옮긴다.

## 성공 기준

1. 옛 엑셀 파일의 첫 시트를 xlsx와 같은 행과 칸으로 읽는다. 글자, 숫자, 날짜 서식이 걸린 숫자, 수식의 저장된 결과, 여러 레코드로 이어진 공유 글자를 읽는다. 시험: 지어낸 값으로 만든 옛 엑셀 파일. 이 PC에서 실제 우리카드 파일과 기업은행 거래용 파일을 읽어 다른 도구로 읽은 값과 칸마다 같다
2. 비밀번호가 걸린 파일, 아주 옛 엑셀 형식, 깨진 파일은 앱이 멈추지 않고 알맞은 문구로 거절한다. 파일 안의 번호가 서로를 돌며 가리키거나 파일 밖을 가리켜도 끝난다. 시험: 지어낸 깨진 파일 여럿
3. 우리카드 "국내 거래승인내역" 파일을 형식 표로 읽는다. 결제 건수와 합계가 파일 맨 아래의 승인 건수, 승인 금액과 같다. 시험: 지어낸 값의 같은 모양 파일, 이 PC의 실제 파일 대조
4. 카드 칸 값이 둘 이상인 파일은 미리보기에서 값마다 보유 카드를 고른다. 고른 짝은 폰에만 두고 다음 가져오기에 쓰며 기록 내보내기에 넣지 않는다. 값이 하나뿐이고 위에서 카드를 골랐으면 묻지 않고 그 카드다. 시험: 두 카드 파일, 한 카드 파일, 내보내기
5. 카드를 고르지 않은 값의 줄은 넣지 않고 "어느 카드인지 골라 주세요"로 보인다. 시험
6. 기업은행 출력용과 신한카드 이용내역 형식도 같은 카드 칸 짝짓기를 쓴다. 카드 여러 장이 섞인 파일을 막던 E60의 그 부분은 고르기로 바뀐다. 기대값을 바꾸는 기존 시험은 plan.md에 까닭을 적는다
7. 저장소에 실제 결제 값과 카드 칸 값을 넣지 않는다. 검사: 새 시험의 값이 지어낸 값이다

## 하지 않을 것

- 기업은행 "거래용"처럼 머리 줄이 없는 파일의 형식. 열 이름 없이 열 위치로 알아봐야 한다. 기업은행은 출력용으로 받으라는 안내를 둔다.
- 옛 엑셀의 두 번째 시트부터, 차트와 그림
- 비밀번호 걸린 파일 풀기
- 사용자 우리카드 "우리 K-패스 COOKIE CHECK"를 카탈로그에 넣기. Databricks 세션의 전체 추출 몫이다

## 정한 것

- 2026-10-06 사용자가 옛 엑셀 읽기부터 만들고, 카드 칸 값마다 보유 카드를 고르기로 했다.
- 사용자 우리카드는 지금 카탈로그에 없어, 폰 확인은 다른 보유 카드를 골라 한다.
