광고, 분석, 오류 보고 라이브러리는 없다. 앱 의존성은 `archive`, `cp949_codec`, `crypto`, `file_picker`, `html`, `http`, `sqlite3`, `url_launcher`, `xml`이다.

사용자가 내보내기 파일을 Google Drive 같은 자기 저장소에 두는 것은 Play가 수집으로 보지 않는다. 사용자가 자기 저장소로 직접 올리고 앱은 그 데이터를 받지 않기 때문이다.

GitHub Pages의 한 쪽짜리 한국어 문서다. Play 사용자 데이터 정책은 방침에 개발자 정보와 문의처, 다루는 데이터와 넘기는 곳, 안전하게 다루는 절차, 보관과 삭제를 적으라고 한다. 2026-10-05 Play 고객센터에서 확인했다. 개인정보 보호법이 적으라는 항목 가운데 이 앱에 해당하는 것도 넣는다. 처음 아홉 절로 썼다가 2026-10-05 위험 검토를 받아 열두 절이 됐고, 같은 날 9절 카드 요청 설문을 더해 열세 절이 됐다.

1. 앱이 모으는 개인정보: 없다. 문의 메일과 시험 의견은 8절, 카드 요청 설문은 9절

4. 기록 내보내기와 파일 가져오기: 내보내기 파일에 든 것, 임시 사본을 지우는 때
5. 안전하게 다루는 법: 앱 전용 저장 공간, https, 암호화하지 않는다는 것
6. 지우기와 이용자의 권리: 앱 기록은 개발자에게 없다. 문의와 의견, 카드 요청은 메일로 열람, 정정, 삭제, 처리 정지를 요청한다. 앱을 지우면 지워진다

8. 문의와 시험 의견: 받는 것, 쓰는 곳, 답을 마치고 1년 뒤 지우고 요청하면 바로 지운다. Gmail과 Google 그룹. 그룹 회원 목록에 메일 주소와 이름이 보이고 그룹은 정식 출시 뒤 지운다

12. 개발자와 개인정보 보호책임자: Play 개발자 이름과 문의 메일

## 4. 기록 내보내기 알리기

2026-10-05 사용자가 이 절을 확정했다. 결제 기록은 폰 안에만 있다. 폰을 잃거나 앱을 지웠는데 내보낸 파일이 없으면 기록이 사라진다. 자동 백업은 결제 기록이 사용자 모르게 옮겨지지 않게 일부러 껐다. 그래서 사용자가 스스로 내보내도록 알린다. 설계 문서 7절의 열어 둔 위험이다.

지금은 설정의 "기록 옮기기" 묶음에 내보내기 줄만 있다. 설명은 "폰을 바꿀 때 기록을 파일 하나로 옮겨요"라서 폰을 바꿀 때만 쓰는 기능처럼 읽힌다.

### 4.1 알리는 법

설정의 기록 내보내기 줄 아래 설명을 마지막으로 내보낸 날로 바꾼다. 내보낸 적이 없으면 "아직 내보낸 적 없어요", 있으면 "마지막으로 내보낸 날 9월 19일"이다. 해가 다르면 "2025년 9월 19일"처럼 해를 붙인다. 홈에 띠를 띄우거나 첫 결제 뒤 안내하지는 않는다. 2026-10-05 사용자가 정했다.

내보낸 날은 Android 저장 창에서 파일을 저장했을 때만 적는다. 저장 창을 닫거나 실패하면 적지 않는다.

내보내기 확인 창의 문구는 바꾸지 않는다. 파일을 폰 밖에 두라는 안내를 더하자는 제안에 2026-10-05 사용자가 넣지 말라고 했다.

### 4.2 마지막으로 내보낸 날 저장

알리려면 마지막으로 내보낸 날을 기억해야 한다. 지금 DB에는 이런 앱 상태를 두는 표가 없다. 표 정의에 작은 표 하나를 더하는 DB 마이그레이션이라 커밋 전에 위험 검토를 거친다. 2026-10-05 표 정의 3번 `app_state(key, value)`로 더했다. 값은 `last_export`의 UTC 밀리초다. 이 날짜는 기록이 아니라서 기록 내보내기 파일에 넣지 않는다. 기록을 가져와도 그대로 둔다.

## 6. 카드 요청 설문

2026-10-05 Databricks 세션이 카드 요청 Google 설문 안내서를 쓰고 앱 링크와 방침을 주 개발 세션에 넘겼다. 같은 날 사용자가 이번 출시 준비에 넣기로 했다. 안내서는 `docs/databricks.md`의 "카드 요청 설문", 시나리오 E22다.

- 앱: 카드 추가 화면의 카드 목록 맨 아래와 검색 결과가 없을 때 "찾는 카드가 없나요? 카드 요청하기"를 둔다. 누르면 설정의 방침 줄처럼 폰 브라우저로 설문을 연다. 앱이 직접 받지 않는다. 설문 주소는 사용자가 설문을 만든 뒤 `cardRequestUrl`에 적는다. 비어 있으면 이 줄을 보이지 않는다
- 설문이 묻는 것: 카드사, 카드 이름, 신용과 체크, 선택 연락처인 메일 주소다. Google 계정 메일 수집은 끈다
- 방침: 받는 것, 쓰는 곳, 보관을 한 절로 더하고 국외 보관에 설문을 더한다. 연락처는 카드를 넣고 알린 뒤 바로 지운다. 넣지 못하는 카드의 연락처는 1년 뒤 지운다. 2026-10-05 사용자가 정했다
- 지우는 곳: 같은 날 위험 검토 중간 1, 2를 받아 정했다. 설문을 스프레드시트에 잇지 않는다. 시트는 지운 칸을 버전 기록에 남겨 되살릴 수 있어서다. 답은 설문의 응답 탭에만 두고, 카드를 넣고 알린 뒤 그 응답째 지운다. 보낸 알림 메일도 보낸편지함과 휴지통에서 지운다. 넣지 못한 요청은 받은 날부터 1년이 지나면 지운다. 순서는 `docs/databricks.md`의 "카드 요청 설문"에 있다
- 데이터 보안 양식: 설문은 앱이 아니라 브라우저의 Google 설문에서 사용자가 직접 보내므로 앱이 모으는 데이터가 아니다. 1.1의 문의 메일과 같은 자리다
