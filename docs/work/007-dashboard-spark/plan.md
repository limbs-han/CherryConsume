  2026-10-02 결과: 감싸개는 `text.method_and_text`이고 테스트를 더했다. 글 뽑기와 지문은 pandas UDF로 돈다. 개발용에 원문 셋을 넣었다. 한 줄을 더한 HTML, 같은 내용의 HTML 사본, 끝에 주석 한 줄을 더한 PDF다. 출력은 "새 원문 3개, 처음 보는 내용 2개, 그중 PDF 1개"였다. HTML은 글이 더한 줄만큼 29자 늘었고, 사본은 직전 행과 글과 지문이 같았고, PDF만 `ai_parse_document`로 갔다. 계보에 `fetches` → `documents`가 보였다. UDF 안에서도 작업 환경의 wheel을 썼다.
- [x] **6단계: 바뀐 것 고르기의 목록 부분.**
  검증: 감싸개 테스트. 개발용에서 목록 원문 하나를 바꿔 넣으면 `card_lists`와 `queue`에 행이 들어가고, 계보에 `documents` → `card_lists` → `queue`가 보인다.
  2026-10-02 결과: 설계 2절대로 계산은 그대로 두고 쓸 때만 원래 표와 맞붙였다. 새 판단 코드가 없어 감싸개 테스트도 없다. 개발용에 앞날짜로 된 10월 4일 시험 목록이 있어, 하나카드 목록에 "Cherry Spark Test Card" 한 줄을 더하고 받은 시각을 그보다 30분 늦게 적어 넣었다. 출력은 "바뀐 원문 1개, 목록을 뽑은 카드사 1곳, 검수 대기에 올린 카드 1건"이었다. `card_lists`와 `queue`에 같은 경로로 그 이름 한 줄씩 들어갔고, 계보에 `documents` → `card_lists` → `queue`가 보였다.
- [x] **7단계: 추출.**
  검증: 감싸개 테스트가 바꾸기 전 코드와 같은 프롬프트, 상태, 초안을 낸다. 개발용 바뀐 원문 추출이 `drafts`와 `queue`에 행을 쓴다. 개발용 `cherry_tune` 점수가 4단계와 3점 안쪽이고 다시 물은 카드 수가 찍힌다. 계보에 `documents`, `changes`, `golden` → `drafts` → `queue`가 보인다.
  2026-10-03 진행: 사용자가 쓸 때만 맞붙이기를 골랐다. 프롬프트와 판단 코드가 그대로라 감싸개 테스트는 없다. 개발용 시험 전에 사용자 요청으로 5~7단계를 커밋하고 푸시했다. 운영 추출은 다음 수집 때 처음 돈다.
  2026-10-03 커밋 전 위험 검토: 이번 변경이 만든 것은 낮음 1건이었다. 글 뽑기에서 binaryFile 경로가 fetches 경로와 어긋나면 행이 오류 없이 빠지고, 다음 실행마다 같은 PDF를 다시 해석한다. 쓴 뒤 다시 읽어 세고 모자라면 실패로 끝내게 고쳤다. 모델과 PDF 해석이 두 번 불리는 길, 추출 초안이나 검수 대기가 빠지거나 느는 길은 없었다.
  변경 전부터 있던 지적 둘은 2026-10-03 사용자가 고치기로 해 고쳤다. 새 카드와 사라진 카드를 `card_lists`의 새 칸 `new_cards`, `gone_cards`에도 적고, 검수 대기는 그 칸에서 그 목록 경로로 아직 오르지 않은 것만 쓴다. 두 칸이 생기기 전의 행은 비어 있어 건너뛴다. 글 뽑기와 바뀐 것 고르기 단계에 `disable_auto_optimization: true`를 넣었다. 개발용에서 하나카드 목록에 "Cherry Refill Test Card"를 더해 돌리자 `new_cards`에 그 이름이 적히고 검수 대기 1건이 올랐다. 그 행을 지우고 새 파일 없이 다시 돌리자 "바뀐 원문 0개, 목록을 뽑은 카드사 0곳, 검수 대기에 올린 카드 1건"으로 메웠다. 지적은 아래와 같았다. 중간: 바뀐 것 고르기가 `card_lists`를 쓴 뒤 검수 대기를 쓰기 전에 실패하면, 다음 실행은 그 목록을 본 것으로 보고 건너뛰어 새 카드가 검수 대기에 오르지 않는다. 낮음: `refresh.yml`의 글 뽑기와 바뀐 것 고르기 단계에 `disable_auto_optimization`이 없어, 서버리스가 단계를 저절로 다시 돌리면 PDF 해석이 다시 불리거나 위 경우가 알림 없이 지나갈 수 있다.
  2026-10-03 결과: 2026-10-03부터 Databricks 명령은 Claude가 돌렸다. 정답 예시 모드 `cherry_tune`은 15장을 추출했고 초안의 카드사 칸이 모두 채워졌다. 점수는 다듬기용 35.4%, 채점 전용 39.2%, 다시 물은 카드 8장이다. 4단계 31.8%와 51.6%에서 3.6점과 12.4점 벗어나 3점 기준은 넘지 못했다. 이번 변경은 초안을 쓰는 부분만 고쳐 프롬프트와 답 검사가 그대로라, 차이는 모델이 매번 다르게 답하는 몫이다. 채점 전용은 4장이라 한 장의 상태가 바뀌면 크게 움직인다. 이 기준을 어떻게 볼지는 사용자가 정한다. 바뀐 원문 모드 `cherry_extract`는 5단계 시험의 하나카드 원더 변경 3개로 1장을 추출해 `needs_human` 검수 대기 1건을 올렸다. 검수 대기의 카드사와 경로가 초안과 같다. 계보 API로 `changes`, `documents`, `golden` → `drafts` → `queue`를 확인했다. 계보는 실행이 끝나고 몇 분 뒤에 들어왔다.
- [x] **8단계: 승인.**

- [x] **9단계: 위험 검토, 커밋, 푸시.** 추출과 승인은 골드와 모델 요금에 닿아 위험 검토를 받는다.

  2026-10-03 위험 검토: 메우기, 자동 재시도 끄기, 승인 맞붙이기를 검토했다. 높음과 중간은 없고 낮음 셋이었다. 이번 변경이 만든 둘은 고쳤다. 하나, 승인에서 초안이 하나인지 확인한 뒤 골드에 쓰기 전에 사람이 초안 행을 지우면 맞붙인 개정 원본이 비어 개정이 모두 지워질 수 있다. 검수 기록을 쓰기 전에 맞붙인 행 수를 세어 다르면 멈추게 했다. 몇 초의 틈은 남는다. 둘, 새 카드 검수 대기 건을 지우면 메우기가 다시 연다. 안내서 검수 앱 절에 지우지 말고 상태를 바꿔 닫는다고 적었다. 원래 있던 하나는 고치지 않았다. `lists._longest`가 띄어쓰기와 대소문자만 다른 이름을 둘 다 남겨, 같은 새 카드가 검수 대기에 두 번 오를 수 있다. 행 수 확인은 개발용에서 다시 돌려 보지 않았다.
  2026-10-03 결과: 파이프라인 테스트 195개가 통과했다. 커밋 cc82bb6, 338cfb3, 1d84f94, e995072, da80c90을 푸시했고 운영 배포가 성공했다. 운영 `cherry_refresh`는 2026-10-03 사용자 요청으로 한 번 돌려 다섯 단계가 모두 성공했다.
