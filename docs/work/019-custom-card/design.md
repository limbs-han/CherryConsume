## 1. 저장과 계산 연결

2026-10-17 사용자가 확인했다.

엔진은 `catalog.cards`만 본다. 켤 때 직접 만든 카드를 이 목록에 더하면 홈, 추천, 카드 상세가 그대로 동작한다. 근거는 `app/lib/store/engine/context.dart`의 `_on`, `headOn`, `rulesOn`이 `catalog.cards[id]`만 읽는 것이다.

### 1.1 저장

- 새 표 `custom_cards`를 마이그레이션 7번으로 더한다. 칸은 id, 카드사, 이름, 신용과 체크, 연회비, 규칙 JSON, 복사해 온 카드 id, 만든 때, 고친 때, 지운 때다
- 규칙은 카탈로그 카드 규칙과 같은 JSON이다. 개정은 하나만 두고 시작일은 아주 이른 날로 둔다. 고치면 모든 달에 새 값이 적용되어 다시 계산 결정과 맞는다
- id는 `custom-`으로 시작해 카탈로그 카드와 겹치지 않는다

### 1.2 켤 때

- 카탈로그를 고르는 `readIndex`는 보유 카드가 모두 목록에 있어야 그 목록을 쓴다. 직접 만든 카드 id는 이 검사에서 뺀다. 빼지 않으면 내려받은 새 카탈로그를 거절한다
- 카탈로그를 고른 뒤 직접 만든 카드를 `catalog.cards`에 더하고 그다음 엔진을 만든다. 카드를 만들거나 고치면 저장소가 카탈로그에 다시 더하고 엔진을 새로 만든다
- 카드사 목록에 없는 카드사를 위해 앱 안에서만 "기타 카드사"를 하나 둔다
- 직접 만든 카드의 규칙은 `catalog_card_files`에 두지 않는다. 그 표는 목록이 가리키지 않는 줄을 켤 때 지운다

### 1.3 형식이 틀린 규칙 막기

- 앱에는 Python 카탈로그 검사기 같은 규칙 검사가 없다. `app/lib/catalog/models.dart` 머리 주석
- 그래서 사용자는 JSON을 쓰지 않고 입력 화면이 정해진 칸만 채워 규칙을 만든다
- 비슷한 카드에서 복사한 규칙은 이미 검사를 통과한 것이라 그대로 쓴다. 입력 화면이 다룰 수 없는 혜택은 "복사한 혜택"으로 보이고 지우기만 할 수 있다

### 1.4 혜택 방식

| 화면 선택 | 규칙 값 | 한 줄 설명 |
|---|---|---|
| 할인 | `billing_discount` | 결제 금액에서 빠지는 혜택 |
| 적립 | `points`, 1포인트 1원 | 직접 만든 카드는 포인트 가치를 1원으로 본다 |
| 캐시백 | `cashback` | 돈으로 돌려받는 혜택 |

### 1.5 실적 규칙

- 처음부터 만들면 모든 결제를 실적에 넣고 취소는 뺀다. 비슷한 카드에서 시작하면 그 카드의 `spend` 규칙을 가져온다
- `transactions`에 "실적 제외" 칸을 더하고 엔진이 실적을 셀 때 이 칸을 본다. 직접 만든 카드의 결제에서만 켤 수 있다
- 돈 계산이 바뀌므로 손계산 시험을 먼저 쓰고 `risk-reviewer` 검토를 받는다

### 1.6 고쳤을 때 다시 계산

- `app/lib/store/routes/answers.dart`의 `reprice`로 그 카드의 모든 결제를 다시 계산한다
- 설계 문서의 "저장한 혜택은 다시 계산하지 않는다" E18의 예외다. 직접 만든 카드는 사용자가 잘못 넣은 값을 바로잡는 경우가 대부분이라서다. 2026-10-17 사용자가 정했다

## 2. 화면

2026-10-17 사용자가 확인했다. 대화에서 다섯 화면 초안을 그림으로 보였다.

### 2.1 들어가는 곳

- 카드 추가 화면 오른쪽 위에 배경 없는 파란 글자 "직접 만들기"를 둔다
- 검색 결과가 없을 때의 "찾는 카드가 없어요" 아래에도 같은 버튼을 둔다

### 2.2 시작 방식

- "비슷한 카드에서 시작"과 "처음부터 만들기" 중 고른다
- 비슷한 카드는 카드 추가 화면과 같은 검색으로 찾는다

### 2.3 기본과 실적

- 카드사는 10곳과 기타라 넷이 넘어 바닥 시트에서 고른다. 설계 10절 원칙
- 카드 이름, 신용과 체크 알약, 연회비
- 실적 구간은 최대 3개다. 비우면 실적 무관 카드다

### 2.4 혜택 줄

- 최대 5줄이다. 한 줄은 대상, 방식, 크기, 월 한도, 필요한 구간이다
- 대상은 모든 가맹점이나 업종 1~3개, 크기는 %나 건당 원이다
- 복사한 혜택 가운데 입력 화면이 다룰 수 없는 것은 회색 "복사한 혜택"으로 두고 지우기만 할 수 있다
- "만들고 등록"을 누르면 기존 등록 시트로 이어진다

### 2.5 비슷한 혜택 가져오기

- 혜택 한 줄 시트에서 대상 업종을 고르면 그 업종의 카탈로그 혜택을 최대 5개 보인다. 입력 화면이 담을 수 있는 단순한 혜택만 보이고 같은 카드사 것이 먼저다
- 누르면 방식, 크기, 월 한도, 필요 구간이 채워진다
- 카드 규칙은 쓸 때 하나씩 읽는 구조라 처음 한 번 692장을 모두 읽어야 한다. 시트를 처음 열 때 화면을 막지 않고 뒤에서 읽고 그동안 "비슷한 혜택 찾는 중"을 보인다. 걸리는 시간은 구현 뒤 에뮬레이터로 잰다

## 3. 표시와 관리

2026-10-17 사용자가 확인했다.

- 홈 카드 줄, 카드 상세 제목 옆, 추천 순위 줄에 회색 알약 "직접 등록"을 붙인다. 혜택 금액은 카탈로그 카드처럼 추정으로 보인다
- 카드 상세 오른쪽 위 메뉴에 "카드 고치기"를 더한다. 만들 때와 같은 화면이 채워진 채 열리고, 저장하면 지난 결제를 다시 계산한 뒤 "결제 N건의 혜택을 다시 계산했어요"를 알린다
- 지우기는 기존 카드 해지와 같다. 홈과 추천에서 빠지고 결제 기록은 남는다. 직접 만든 카드의 규칙도 남겨 지난 기록의 혜택 이름이 보이게 한다
- 직접 만든 카드는 카드 추가 검색 목록에 나오지 않는다. 만들면 바로 등록되기 때문이다
