# 019 의도

## 왜

카탈로그에 카드 692장을 넣었지만 Databricks 체험이 끝나 더 넣기 어렵다. 사용자가 가진 카드가 목록에 없으면 앱을 쓸 수 없다. 사용자가 카드를 직접 만들어 실적과 혜택을 계산하게 한다. 직접 만든 카드도 카탈로그 카드와 같은 형식으로 폰 안에 저장해 계산 엔진, 추천, 홈, 카드 상세를 그대로 쓴다. 그래야 "혜택 계산" 앱이라는 개념이 유지된다.

## 사용자가 정한 것

- 범위 B. 실적 구간과 간단한 혜택 줄까지 입력한다. 2026-10-17
- 카드 추가 화면 오른쪽 위에 배경색 없는 "직접 만들기"를 둔다. 2026-10-17
- 비슷한 카드에서 시작하기를 1차에 넣는다. 같은 카드사의 카드를 복사해 고친다. 2026-10-17
- 혜택을 입력하면 카탈로그의 비슷한 혜택 양식이나 내용을 가져올 수 있게 한다. 2026-10-17
- 실적 규칙은 이 카드에만 예외를 둔다. 처음부터 만들면 모든 결제를 실적에 넣고 취소는 뺀다. 비슷한 카드에서 시작하면 그 카드의 실적 규칙을 가져온다. 어느 쪽이든 사용자가 결제마다 "실적 제외"를 표시할 수 있다. 카드사마다 다른 규칙을 하나의 기본값으로 두지 않는다는 프로젝트 규칙의 예외이고, 사용자가 직접 넣은 값이 우선이라는 규칙을 따른다. 2026-10-17
- 직접 만든 카드의 혜택이나 실적 구간을 고치면 이미 기록한 결제도 다시 계산한다. 처음에 잘못 넣은 값을 바로잡는 경우가 대부분이라서다. 2026-10-17

## 성공 기준

1. 카드 추가 화면 오른쪽 위 "직접 만들기"로 카드를 만들고 등록하면 홈에 남은 실적이 보인다. 화면 시험
2. 비슷한 카드를 골라 시작하면 그 카드의 실적 구간과 혜택 줄이 채워진다. 화면 시험
3. 혜택 줄을 입력할 때 비슷한 카탈로그 혜택을 골라 채울 수 있다. 화면 시험
4. 직접 만든 카드의 혜택을 엔진이 손계산 기대값대로 계산한다. 엔진 시험
5. 직접 만든 카드가 추천 순위에 들고 "직접 등록" 표시가 붙는다. 화면 시험
6. 직접 만든 카드의 혜택을 고치면 지난 결제의 혜택이 새 값으로 바뀐다. 저장소 시험
7. 처음부터 만든 카드는 모든 결제가 실적에 들고 취소는 빠지며, 결제마다 표시한 실적 제외는 빠진다. 엔진 시험
8. 직접 만든 카드가 기록 내보내기와 가져오기를 거쳐 그대로 돌아온다. 왕복 시험
9. 위험 검토를 받고 사용자가 확인한다

## 하지 않을 것

- 가맹점 단위 혜택, 1회와 하루 한도, 횟수 한도, 요일과 시간과 결제 수단 조건. 2차 후보
- 카탈로그에 같은 카드가 생겼을 때 공식 카드로 바꾸기. 2026-10-17 사용자가 2차로 미뤘다
- 직접 만든 카드를 서버나 다른 사람과 나누기. 폰 밖으로 보내지 않는다
