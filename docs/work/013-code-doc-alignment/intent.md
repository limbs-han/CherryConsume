# 013 코드와 문서 맞추기

2026-10-05 코드 해설서를 쓰며 찾은 어긋남 53건에서 시작했다. 목록은 같은 폴더 `findings.md`다. 2026-10-05 사용자가 이 의도를 확인했다.

## 왜

- 코드 해설서 13장에 코드와 문서가 어긋나는 곳 53건이 모였다. 동작이 문서나 정한 원칙과 다른 것 23건, 코드가 바뀌고 문서나 주석이 남은 것 27건, 곧 어긋날 것 3건이다
- 동작이 다른 것 가운데 몇은 사용자가 정한 원칙을 화면이 어긴다. 예를 들어 추천 화면의 "조건 확인" 배지가 작업 004에서 정한 알림 회색이 아니라 호박색이고, 흐린 글자가 회색 바탕 위에 있어 대비가 4.19:1이다
- 문서가 낡으면 다른 PC나 다른 AI가 이어 받을 때 옛 설명을 믿는다. 설계 문서가 기준이라는 규칙이 있어도 작업 001, 002, 005의 설계와 코드 주석은 서버 시절 말을 남기고 있다

## 성공 기준

1. `findings.md`의 앱과 문서 쪽 항목마다 고침, 그대로 둠, 확인 필요, 넘김 가운데 하나와 이유가 `design.md`에 있다
2. 고침으로 정한 동작 항목마다 그 동작을 지키는 시험을 먼저 써 실패를 보고, 고친 뒤 통과한다. 예를 들어 배지 색, 회색 바탕 위 글자 대비, 푸시 훅이 올리는 커밋마다 검사하는 것이다
3. 고침으로 정한 문서 항목마다 문서와 주석이 지금 코드와 같다. 옛 문구를 grep으로 다시 찾아 나오지 않는다
4. 파이프라인 쪽 항목 목록을 Databricks 세션에 넘겼다. `.claude/progress.md`에 위치를 적고 그 세션에 알린다
5. 계산 엔진과 저장소 시험을 고치지 않은 채 앱 시험과 백엔드 시험이 모두 통과한다
6. 화면을 바꿨으면 에뮬레이터에서 찍어 바뀐 것을 확인한다

## 하지 않을 것

- 해설서 자체를 고치기. 해설서는 2026-10-05 기준의 기록이다
- 계산 규칙 바꾸기. 엔진 동작이 문서와 다른 13-1~13-6은 문서를 맞추거나 확인 필요로 남기고, 계산을 바꿔야 하면 규칙 변경 절차를 따로 밟는다
