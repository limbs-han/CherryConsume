설계는 `design.md`, 의도는 `intent.md`다. 항목 번호 Z, G, H, A, D, P, R, Hi, I, S는 설계 2절이다.

- 단계마다 앱이 돌고 시험이 모두 통과한 채로 끝낸다
- `app/test/engine/`과 `app/test/store/`는 고치지 않는다. 성공 기준 5
- 바꾼 화면마다 화면 시험을 먼저 고치거나 더하고 통과시킨다. 성공 기준 4
- 에뮬레이터 `wj_local`을 작은 화면과 3버튼 방식으로 찍은 뒤에는 `adb shell wm size reset`, `adb shell wm density reset`, `adb shell cmd overlay enable com.android.internal.systemui.navbar.gestural`로 되돌린 뒤 쓴다. 찍을 때만 다시 바꾼다
- 커밋은 사용자가 요청할 때만 한다
- 걸리는 시간은 단계 1이 1.5일, 2가 반나절, 3이 2일, 4가 반나절, 5가 반나절이다

  - 결과: 2026-10-04 아홉 화면을 모두 고쳤고 앱 시험 726개가 통과한다. 위험 검토 뒤 729개. 화면 시험은 `home_test`, `add_card_test`, `card_detail_test`, `payment_screen_test`, `recommend_screen_test`, `records_screen_test`, `import_screen_test`, `settings_screen_test`, `title_bar_test`다. 엔진과 저장소 시험은 손대지 않았다. 옛 화면 모양을 찾던 시험은 새 모양에 맞췄다

    - 추천 결과의 금액 칸과 등록 시트의 금액 칸도 쉼표가 들어간다. 쉼표를 넣는 입력 규칙은 `lib/ui.dart`의 `ThousandsFormatter` 하나다
    - 엑셀 가져오기의 단계 버튼은 차례대로 파일 고르기, 다시 읽기, 저장이고 아래에 고정이다. "엑셀은 어디서 받나요" 안내는 설계 문서 "어디서 받은 파일인가"의 카드사 PC 웹 조회만 적었다. 카드사마다 메뉴 위치는 확인하지 않아 적지 않았다
    - 설정의 답은 줄을 누르면 바닥 시트에서 고른다. 원칙 5다. 앱 판은 `lib/screens/settings.dart`의 상수이고 `pubspec.yaml`의 version과 같은지 시험이 본다. 판 정보 패키지를 더하지 않으려고 이렇게 했다. 카탈로그 날짜는 카드마다 공식 문구와 대조한 날 `checked_at` 가운데 가장 늦은 날이다
    - 카드 상세의 답과 옵션, 결제 세부 시트의 업종에 남아 있던 Material 칩도 알약으로 바꿨다. G2
    - 제목줄은 시안 값대로 뒤로 가기 칸 48, 제목 시작 52다. 뒤로 가기가 없는 탭 화면 제목은 24다. 테마와 `rootTitleSpacing`
    - 금액 입력과 가져오기 화면이 바뀌어 위험 검토를 돌렸다. 높음은 없고 중간 둘, 낮음 넷을 모두 고쳐 앱 시험이 729개가 됐다. 쉼표 금액 칸은 가운데를 고쳐도 커서가 그 자리에 남고 자릿수가 차면 더 받지 않는다. 세부 시트의 할부는 엑셀로 가져온 24개월처럼 고르는 줄에 없는 개월도 그대로 보인다. 취소 금액도 쉼표 금액 칸으로 바꿨다. 2MB 넘는 파일을 고르면 앞 파일의 미리보기를 지운다
