# 011 UI와 UX 다듬기

2026-10-04 사용자가 실제 폰에서 앱을 써 본 뒤 시작했다. 작업 006 단계 8 다음이다.

## 왜

- 사용자가 써 보니 UI와 UX가 아직 미흡하다. 특히 카드 상세, 결제 기록, 추천, 기록과 설정이 아쉬웠다
- 하단 탭의 홈, 추천, 기록, 설정 아이콘이 밋밋하다. 지금은 Flutter 기본 선 아이콘이다
- 화면 시안은 작업 004에서 UI 결함과 UX 법칙으로 검토를 마쳤다. 앱은 작업 005와 006에서 기능을 먼저 만들며 시안을 다 따르지 않았다

## 성공 기준

1. 시안에 있는 앱 화면마다 시안과 지금 앱을 나란히 찍은 차이 목록이 `design.md`에 있다. 항목마다 고침 또는 그대로 둠과 사용자가 고른 답이 적혀 있다
2. 사용자가 고친다고 고른 항목이 모두 고쳐졌다. 고친 뒤 에뮬레이터 화면을 시안과 나란히 다시 찍어 항목마다 맞는지 적는다
3. 하단 탭 아이콘 넷이 사용자가 고른 새 아이콘이다. 고른 탭과 안 고른 탭이 모양이나 색으로 구별된다
4. 바뀐 화면마다 그 화면 시험이 바뀐 모습을 확인하고, 앱 시험 전체가 통과한다
5. 계산과 저장은 바뀌지 않는다. 엔진과 저장소 시험을 고치지 않은 채 그대로 통과한다
6. 실제 폰에서 사용자가 카드 상세, 결제 기록, 추천, 기록과 설정을 다시 써 보고 확인한다
7. 화면마다 버튼, 입력 칸, 글자가 상태 표시줄, 카메라 구멍, 제스처 막대, 3버튼 막대에 가리지 않는다. 작은 폰과 큰 폰 에뮬레이터에서 제스처 방식과 3버튼 방식으로 찍어 확인하고, 화면 시험이 Android와 iPhone의 시스템 막대 높이를 넣은 화면에서 주요 버튼과 글자가 막대와 겹치지 않는지 본다
8. 저장, 가져오기, 이 카드로 결제 기록 같은 화면의 주요 버튼이 키보드를 연 상태에서도 내리지 않고 보이고 눌린다. 가로로 미는 줄은 화면 좌우 가장자리에 붙지 않아 뒤로 가기 손짓과 겹치지 않는다
9. 설계 1절에서 사용자가 고른 토스식 원칙마다 적용한 화면 목록이 있고, 그 화면에서 원칙이 지켜진 것을 에뮬레이터 화면과 화면 시험으로 확인한다
10. 글꼴을 넣으면 앱 크기가 얼마나 늘었는지 재어 적는다

## 하지 않을 것

- 시안 전체를 새로 디자인하기. 차이 목록을 보다 시안을 바꿔야 할 곳이 나오면 따로 묻는다
- 토스의 글꼴, 아이콘, 그림, 화면을 그대로 가져다 쓰기. 토스 저작물이다. 원칙만 따르고 무료로 쓸 수 있는 글꼴과 직접 그린 아이콘을 쓴다
- iPhone 앱 빌드, 설치, App Store. Mac과 Apple 개발자 계정이 필요해 하려면 따로 작업을 만든다. Android 먼저라는 결정 그대로다
- 새 기능, 계산 규칙 바꾸기, 표 바꾸기
- 카메라 인식 화면. 2026-10-03 뺐다
- 출시 준비. 하위 프로젝트 5에서 한다
