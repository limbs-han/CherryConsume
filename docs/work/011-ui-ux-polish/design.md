## 1. 토스식 원칙

2026-10-04 여덟 후보를 지금과 제안으로 나란히 그려 보였고 사용자가 1~6을 골랐다. 7과 8은 권한 대로 뺐다. 토스의 글꼴, 아이콘, 그림은 쓰지 않고 원칙만 따른다. 이 원칙은 시안 캔버스를 고치지 않고 이 문서와 전체 설계 문서에 적는다.

|---|---|---|

뺀 것
- 7. 한 화면에 한 가지씩. 결제 기록은 계산대 앞에서 빨리 적는 화면이다. 카드는 추천 1순위로 미리 골라 두어 채울 칸이 금액과 가게 둘이라 단계를 나누면 누르는 횟수만 는다. 대신 6의 금액 칸 바로 열기를 쓴다
- 8. 불러오는 중 뼈대 화면. 기록이 폰 안에 있어 화면이 거의 바로 그려져 뼈대가 깜빡이기만 한다. 2절에서 0.3초 넘게 걸리는 화면이 나오면 그때 넣는다

## 2. 시안과 앱의 차이 목록

2026-10-04 `backend/tools/screens.py`와 `app/integration_test/screens_test.dart`로 찍었다. 시험이 시안의 카드 세 장과 9월 결제 다섯 건을 넣고 화면마다 "SHOT 이름"을 출력하면, 도구가 adb로 시스템 막대까지 찍는다. 시안은 같은 도구가 설치된 Chrome으로 화면마다 찍는다. 사진은 `app/build/screens/`에 있고 저장소에 올리지 않는다. 에뮬레이터 두 가지로 찍었다. 큰 폰 1080×2400 제스처 방식과 작은 폰 720×1280 3버튼 방식이다. 숫자가 다른 것은 넣은 기록이 달라서이고 차이로 보지 않는다.

### 2.4 짧은 이름 칸

- 카드와 카드사 파일에 `short_name`을 더한다. 적지 않아도 되는 글자 칸이다. 카드는 "신한 Mr.Life", "현대 ZERO", "IBK 나라사랑"처럼 카드사 짧은 이름과 상품의 핵심 이름이고, 카드사는 "신한", "IBK", "KB"다
- 화면은 칩, 줄, 버튼처럼 자리가 좁은 곳에서 `short_name`을 쓰고 없으면 `name`을 쓴다. 카드 상세 제목과 등록 시트 제목은 전체 이름을 쓴다
- 이 작업이 카탈로그 틀, 검사, 앱 JSON, Dart 모델에 칸을 더한다. 값은 Databricks 세션이 카드 20장과 카드사 10곳에 넣어 검수 승인으로 골드에 올리고, `export`가 저장소에 커밋한다. `catalog/`는 직접 고치지 않는다
- 값이 오기 전에도 화면은 `name`으로 돈다
